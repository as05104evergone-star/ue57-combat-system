> **本册的定位**：v2.0 起，本册**只写「目前选定的正确写法」**——每一步都给出最终接法、为什么这样接、以及做完怎么自检，不回顾历史版本、不再罗列错误写法。所有踩过的坑、被推翻的方案、事故复盘、报错排查过程，已全部搬到《[角色闪避与招架反击-踩坑与错误归档](角色闪避与招架反击-踩坑与错误归档.md)》（下称「踩坑册」）。正文中偶见的 `⚠️ 易错点 K012` 就是指向踩坑册对应条目的跳转锚点。

> **历史版本**：v1.54 及以前的历史版全文见 `Docs/归档/角色闪避与招架反击教学手册_v1.54_历史版.md`（含历次版本记录与每次修正的来龙去脉）。

## 怎么用这本册子

1. **第一次做**：按课次顺序推进，每课五段——**目标 → 前置 → 操作（节点级） → 为什么 → 自检**。操作段给的是最终接法，节点名、引脚名、资产路径都可以直接照抄。
2. **卡住了**：先去踩坑册按「现象」搜关键词（比如「按左键没反应」「敌人不掉血」「永久站桩」），踩坑册每条都写清了根因和判据。
3. **改完要验收**：每课自检 + 附录 C 阶段勾选表；玩法验收口径以 `Docs/规划/角色闪避与招架反击制作规划及验收标准.md` §7 的 A01–A14 为准。
4. **新增功能**：先过附录 E「守卫条件维护规约」的 5 步反查法，再动手。

## 全书约定

- **资产路径**一律用 UE 对象路径 `/Game/Combo_Demo/...`；资产在缓存里的实测结构以 `Plugins/ComboMCP` 的 T3D 读取结果为准。
- **节点名**：插件（GASCombatBridge）节点在编辑器里只显示**中文显示名**（如「对目标造成伤害」），括号里给 C++ 内部名（`ApplyDamageToTarget`）方便搜索；引擎原生节点给蓝图面板上的英文名。
- **变量/函数名**照资产里的实际拼写照抄（含大小写），例如 `TryCounter`、`bCounterReady`、`CounterTarget`。
- **数值**只写数据键名，具体值以 `DT_Combat` / `DT_Enemy` 为准（本册出现的数值都是当前表里的实测值，改表后请以表为准）。
- **引脚**：exec 线（白箭头）只能接 exec；数据线（圆点）必须同类型同方向；`Branch` 的 `Condition` 引脚**默认值是 `true`**，没接线等于恒真。

## 第 2 课 五个必须先懂的概念

**目标**：后面每一课的“为什么”都建立在这五个概念上。

### 2.1 传统 InputKey 与 Enhanced Input 现在是并存的

- `AC_Combat` 里的左键轻击、左 Alt 装备、右键蓄力都是**传统输入事件**（`InputKey` 事件节点，本质是 `PlayerInput` 的按键事件）；玩家 `SandboxCharacter_CMC` 的移动/奔跑/跳跃走 **Enhanced Input**（`IA_*` + `/Game/Input/IMC_Sandbox`）。
- 两套可以并存，本项目已经这么跑。**招架沿用 InputKey（和左键一致），闪避沿用 Enhanced Input（和左 Shift 一致）**，改动最小。

### 2.2 Montage / Slot / Notify 是什么关系

- **AnimSequence** 是原始动作；**AnimMontage** 是“能被代码按 Slot 播、能分段、能挂通知”的容器。播放时动画系统把蒙太奇塞进 AnimBP 的 **Slot 节点**，本项目玩家的 Slot 名是 `DefaultSlot`（现有轻击能播就是证据）。**新蒙太奇的 Slot 必须选 `DefaultSlot`**，否则不播。
- **Notify**：`AnimNotify` 是单点，`AnimNotifyState` 是有起止的窗口。`ANS_InputDisabled` 管“这段时间禁输入”，`ANS_WeaponTrace` 管“这段时间开武器检测”。
- **同样的时长不要存两份**：无敌 0.30s 这类逻辑窗口用 `SetTimer` + DataTable 键表达（规划 §5.5 要求游戏时间计时），Notify 只负责表现层。所以本手册**不**新建“无敌 Notify”。

### 2.3 GAS 桥接组件负责血量，伤害不要直接减 Health

- 玩家 Pawn 上已挂 `GASCombatBridge`：它负责建 ASC、挂属性集、广播三个事件——`战斗就绪`、`受到伤害时`、`死亡时`。
- 伤害统一走 `GE_Damage`（`Data.Damage` SetByCaller），由属性集统一处理护盾、夹取、广播受击、判断死亡。**直接减 `Health` 会一次绕过这四个功能**。
- 受击动画绑「受到伤害时」（战斗语义），不要绑属性监听器（数值变化也会触发）。

### 2.4 防御必须在“施加伤害之前”拦截

- 规划 §5.1 定死的顺序：命中候选 → 本次攻击是否已处理 → 闪避判定 → 招架判定 → 普通伤害。
- 不是“扣血后再加回来”，而是攻击方在调 `对目标造成伤害` 之前先问目标“这一下你防住了吗”。目标回答 `None / Dodged / Parried`，只有 `None` 才真正结算。这也是要给 `BPI_CombatComponent` 加函数的原因——现有接口只有 4 个转发函数，没有“问一句”的入口。

### 2.5 位移只能有一个驱动

- 闪避有三种做法：动画根运动推胶囊、`LaunchCharacter` 推胶囊、改 `MaxWalkSpeed` 硬走。**混用会位移翻倍或回弹**。
- 本轮选 `LaunchCharacter` 受控位移：距离读表、时长复用无敌时长、水平速度 = 距离 / 时长。前提是**闪避序列本身不要开根运动**（第 3 课核实）。
- 验位移时**同时看模型和胶囊**：模型跑得比胶囊远 = 根运动没关；胶囊走了模型没走 = Slot 没播 / 蒙太奇空。

**自检**：能解释“为什么招架不需要新建 Notify”“为什么伤害不能事后补血”“为什么闪避序列要关根运动”。**预计**：0.5h。

## 第 3 课 M0-1 编辑器内核实 5 项

**目标**：把缓存读不到、但决定后面怎么写的 5 件事确认掉，产出核实记录。**前置**：第 0–2 课。

**操作**（逐项做，结果填到本课末尾的表）

1. **玩家 GAS 组件配置**：打开 `/Game/Blueprints/SandboxCharacter_CMC` → 组件面板选 `GASCombatBridge` → 细节确认 `开始游戏时自动初始化` ✔、`缺少组件时自动创建` ✔、`自动创建时启用复制` ✔、`挂载的属性集` 里有 `通用战斗属性集`（`GASCombatCoreAttributeSet`）；再 PIE → `窗口 → 工具 → GAS 战斗调试` → 选玩家 → 看是否显示“属性 11 项”。

### 10.1 先看整条链路（别急着连节点）

```
GE_Damage 结算伤害
  └─ 属性集广播「受到伤害」→ GASCombatBridge 转发
       └─ 玩家 BP：GASCombatOnDamageTaken(DamageInstigator, DamageCauser, DamageAmount, RemainingHealth)
            └─ 取 DamageInstigator 位置 → AC_Combat.HandlePlayerHit(DamageAmount, AttackerLocation)
                 ├─ 守卫 bIsDead
                 ├─ 禁移动 / 禁输入
                 ├─ SelectPlayerHitMontage(AttackerLocation) → 播受击蒙太奇
                 └─ SetTimer(combat.player.hitstun) → OnPlayerHitRecover → 恢复移动/输入
```

三条不能破的底线：① **不直接改 Health**——扣血只走 `GE_Damage`（`Data.Damage` SetByCaller），属性集统一处理夹取、广播受击、判断死亡，直接 `SetAttributeBaseValueByName("Health")` 会绕过受击与死亡；② **不在受击里判无敌**——无敌由攻击方在结算前调 `TryDefendAttack` 拦截（第 13 课），受击函数只兜底；③ **不用 `Delay` 做硬直**——`Delay` 是 latent 节点，死亡/打断后清不掉，硬直必须 `Set Timer by Event` + `Clear and Invalidate Timer by Handle`。

### 10.2 在 `AC_Combat` 建变量与函数

1. 左侧变量面板 `+` 新建三个变量：`bIsDead`（Boolean，默认 false）、`bIsHitStunned`（Boolean，默认 false）、`HitStunTimer`（搜 **Timer Handle**，类型名 `TimerHandle`）。
2. 左侧函数面板 `+` 新建两个函数：`HandlePlayerHit`、`SelectPlayerHitMontage`（后者勾上返回值，类型 `Anim Montage`）。
3. 在 `AC_Combat` 的**事件图表（Event Graph）** 里右键搜 **Add Custom Event**，命名 `OnPlayerHitRecover`。

> **一个必须先讲清的边界**：`OnPlayerHitRecover` 是事件图表里的 Custom Event，而 `Set Timer by Event` 要写在 `HandlePlayerHit` 这个**函数**里——**函数图里不能放 Custom Event，也不能把事件图表里的 Custom Event 直接拖到 `Event` 引脚上**（事件节点只能活在事件图/Ubergraph 里）。函数里要引用它，用 **`Create Event`** 节点：右键搜 **Create Event** → `Function` 下拉选 `OnPlayerHitRecover` → 输出（Event 委托引脚）接 `Set Timer by Event` 的 `Event` 引脚。`Create Event` 是纯节点，函数图里可以放。两条硬约束：回调**必须无参**（带参数的回调编译器会报错或定时器不触发）；`Create Event` 节点上的对象（`Self`）默认就是 `AC_Combat` 自己，不需要再赋值。

### 10.3 `HandlePlayerHit` 逐节点

**签名**：`HandlePlayerHit(DamageAmount : double, AttackerLocation : Vector)`，无返回值。**节点顺序**（括号里是右键搜索词）：

1. `Branch`（**Branch**），条件接 `bIsDead` → True 一路接 `Return Node`（**Return Node**）。**先判死再做事**。
2. `Clear and Invalidate Timer by Handle`，Handle 接 `HitStunTimer`：连击时清掉上一个硬直计时器，否则第一刀的计时器会把第二刀提前“恢复”。
3. `Set bIsHitStunned` = `true`。
4. **先 `Cast To BPI_CombatComponent`**（`Object = OwningCharacter`；`OwningCharacter` 由 `Get Owner → Cast To Character` 得到）→ 从 `As BPI Combat Component` 拖出 `CallSetMovementEnabled` = `false`。
5. 从**同一个 Cast** 拖出 `CallSetInputEnabled` = `false`。禁止硬直中按攻击/闪避/招架，恢复时在 `OnPlayerHitRecover` 里打开。**为什么必须 Cast**：`AC_Combat` 自己也有同名函数（接口实现），但 `CallSetMovementEnabled` 在组件里是**空实现**、`CallSetInputEnabled` 只翻转组件自己的 `InputEnabled` 布尔；不写 Target 直接调，玩家的 `MovementEnabled` 根本没变。正确写法在 `AC_Combat.StartCharge` 里有现成样例，照抄它。
6. `Play Anim Montage`：`Target = OwningCharacter`、`Anim Montage = SelectPlayerHitMontage(AttackerLocation)`、`InPlayRate = 1.0`、`StartSectionName` 留空。`PlayAnimMontage` 内部默认 `bStopAllMontages=true`，会先停掉正在播的动作，不需要手动 Stop。
7. `Set Timer by Event`，四件事：拖一个 **`Create Event`**、`Function` 选 `OnPlayerHitRecover`；`Event` 引脚 ← 它的输出；`Time = GetCombatParam(DT_Combat, "combat.player.hitstun").Value`、`Looping = false`；`Return Value` 接 `HitStunTimer`。
8. （可选，验收前删）`Print String` 打 `DamageAmount` 和 `RemainingHealth`。

**伪代码**

```
HandlePlayerHit(DamageAmount, AttackerLocation):        // 函数图
    if bIsDead: return
    Clear and Invalidate Timer(HitStunTimer)
    bIsHitStunned = true
    (OwningCharacter as BPI_CombatComponent).CallSetMovementEnabled(false)   // ← 必须打到玩家，不是组件自己
    (OwningCharacter as BPI_CombatComponent).CallSetInputEnabled(false)
    PlayAnimMontage(OwningCharacter, SelectPlayerHitMontage(AttackerLocation), 1.0)
    HitStunTimer = SetTimerByEvent( CreateEvent(OnPlayerHitRecover),   // ← 函数图里必须用 Create Event
                                    GetCombatParam(DT_Combat,"combat.player.hitstun").Value,
                                    false )
```

**“硬直中再挨一刀”的规则**：首版 = **每次命中都刷新硬直**（先清计时器再重设、重播受击）。连招打你两刀 = 两段硬直连续生效；“一次攻击只产生一次结果”由攻击方的 `HitActorsThisWindow` 去重保证（第 12 课），不靠玩家侧。

### 10.4 `SelectPlayerHitMontage` 逐节点

**签名**：`SelectPlayerHitMontage(AttackerLocation : Vector) → AnimMontage`。

1. `Get Actor Transform` 拿 `OwningCharacter` 的 Transform。
2. `Inverse Transform Location`：`T = 上一步 Transform`、`Location = AttackerLocation` → 攻击者在玩家**局部空间**的位置。
3. `Break Vector` 拆出 `X`（前/后）、`Y`（右/左）；`Abs` 分别取 `|X|`、`|Y|`。
4. `Greater Equal`（float/double 版本）：`|X| >= |Y|`？**True（前后方向）**：`Branch` 判 `X > 0` → True 返回 `AM_PlayerHit_F`，False 返回 `AM_PlayerHit_B`；**False（左右方向）**：`Branch` 判 `Y > 0` → True 返回 `AM_PlayerHit_R`，False 返回 `AM_PlayerHit_L`。
5. 四条路径各接 `Return Node`（把蒙太奇资产拖进去）。**越界/空值兜底**：`X=Y=0`（攻击者与玩家同点）会走 `|X|>=|Y|` 的 True 且 `X>0` 为 False → 落到 `AM_PlayerHit_B`，不会空播；担心蒙太奇没指定，可在每条 Return 前加一次 `IsValid` 兜底到 `AM_PlayerHit_F`。

**为什么用局部空间而不是角度扇区**：比较 `|X|` 与 `|Y|` 天然处理 0/360 跨界，且和八向闪避的扇区映射（第 14 课）用的是同一套“前方 = +X、右方 = +Y”约定，两个功能的方向语义不会打架。**坐标约定**（别记反）：UE 里角色 `X+` 是前、`Y+` 是右，所以 `Y > 0` = 攻击者在玩家右侧 = 玩家**右侧中招** → 播 `_R`。

### 10.5 `OnPlayerHitRecover`

1. `Branch` 判 `bIsDead` → True 直接 `Return`（死亡后不允许任何旧计时器把控制还回来）。
2. `Set bIsHitStunned = false`；`Cast To BPI_CombatComponent`（`OwningCharacter`）→ `CallSetMovementEnabled(true)`；从同一个 Cast → `CallSetInputEnabled(true)`。
3. **不要在这里再塞一个 `Delay`**：计时器已经等了 `combat.player.hitstun`，回调里再 `Delay 0.38` 等于恢复要 0.76s；更严重的是 `Delay` 中途死亡也**清不掉**，到点仍会把输入打开。

**M2/M3 之后要补的**：恢复前检查 `bIsDodging` / `bParryWindowActive` / `bCounterReady`，如果玩家受击前正在别的状态，别无条件开输入（第 18 课的 `CleanupAll` 统一处理）。首版先只做受击，留一行注释 `// M2/M3: 见 CleanupAll`。

### 10.6 玩家 BP 绑「受到伤害时」

1. 打开 `/Game/Blueprints/SandboxCharacter_CMC` → 组件列表选中 `GASCombatBridge` → 细节面板「事件」区点 `+` → 选 **受到伤害时**（`GASCombatOnDamageTaken`）。EventGraph 出现 `GASCombatOnDamageTakenEvent`，引脚：`DamageInstigator`、`DamageCauser`、`DamageAmount`、`RemainingHealth`。

### 10.8 抄 NPC 侧的正解：抄骨架、换五处

NPC 侧（`BP_MasterNPC` + `AC_NPC`）与玩家用**同一个 GASCombatBridge 插件**，事件签名与这些节点的调用完全一致，所以“结构”可以照抄；但 **`ApplyHitReaction` 不能整段复制**——它带着敌人专用数据键、敌人骨架蒙太奇和敌人专用宿主。

| NPC 侧 | 玩家侧 | 处理 |
| --- | --- | --- |
| 「受到伤害时」事件（`DamageInstigator`, `DamageCauser`, `DamageAmount`, `RemainingHealth`） | `SandboxCharacter_CMC` 同名事件（组件名 `GASCombatBridge`） | ✅ 照抄节点 |
| `SetAttributeBaseValueByName("MaxHealth"/"Health")` | 同名事件，取数键换 `player.hp.max`（NPC 是 `enemy.shadow.hp`） | 🔧 换键 |
| 「施加效果」（`ApplyEffectWithValues`，参数 `Target`、`GE_HitStun`、SetByCaller `Data.Duration`） | 完全一致 | ✅ 可抄 |
| `AC_NPC.SelectHitMontage`：`InverseTransformLocation` → 比较 `\|X\|`/`\|Y\|` → 四向索引 | `AC_Combat.SelectPlayerHitMontage`，返回 `AM_PlayerHit_F/B/L/R` | ✅ 算法照抄，🔧 换蒙太奇 |
| `AC_NPC.HandleDeath`：`bDead` 守卫 → `CancelAllAbilities` → `AddLooseTags(State.Dead)` → `DisableMovement` → 胶囊 `NoCollision` → 播 `AM_Hit_Death` | `AC_Combat.HandlePlayerDeath`，播 `AM_PlayerHit_Death`；死亡表现可选布娃娃 `Ragdoll_Start/_End` | ✅ 骨架照抄，🔧 换蒙太奇与收尾 |
| 硬直时长读 `combat.enemy.*`（大硬直分支读 `combat.enemy.parry_stun`） | 玩家读 `combat.player.hitstun`，首版不分大小硬直 | 🔧 必须换键 |
| `AC_NPC` 的 `bFromParry` 参数 | 玩家 M1 不需要（招架走第 13 课 `TryDefendAttack`） | ❌ 不要抄 |
| 宿主 `AC_NPC`（变量/蒙太奇数组都硬编码敌人资产） | 宿主换成 `AC_Combat`，玩家状态集中一处好清理 | 🔧 换宿主 |

**结论一句话**：抄“三个事件 + 「施加效果」+ 方向比较算法 + 死亡守卫顺序”，不抄“函数体、数据键、蒙太奇、宿主”。跨资产复制整个函数会把敌人的资产硬引用一起带过来，按上表逐段重建更稳。

### 10.9 死亡/硬直门禁三处：入口、状态、清理

一句话：**“恢复回调里判 `bIsDead`”只挡得住计时器，挡不住玩家的手**。门禁必须同时出现在三处：

| 位置 | 要做什么 | 为什么 |
| --- | --- | --- |
| ① 入口（输入事件） | 左键/重击/侧键/闪避/招架/`左 Alt` 装备/`F1–F4` 调试键/`IA_Look`+`IA_Look_Gamepad` 这些事件的**最前面**加 `Branch(NOT bIsDead)`，False 直接断开；受击硬直期把 `bIsHitStunned` 一起算进去 | 输入事件与状态机是两条线：`bIsDead` 只是组件变量，入口不读它 → 死后照样出招、照样转视角 |
| ② 状态（调用目标） | 所有 `CallSetMovementEnabled` / `CallSetInputEnabled` 都打到 `OwningCharacter` 的 `BPI_CombatComponent` 接口上（`Cast To BPI_CombatComponent` → 调） | 组件自己的实现是空壳/半壳；玩家的 `MovementEnabled` 才是 `IA_Move` 真正读的开关 |
| ③ 清理（计时器/委托） | 死亡时用 `Clear and Invalidate Timer by Handle` 清掉硬直/闪避/招架/反击所有计时器；不留 `Delay`、不留写死时长的恢复路径 | 旧计时器回调会把控制还回来；`Delay` 即使清了计时器也仍会执行完 |

**守卫一律写成 `NOT`**：把 `bIsDead` 直接接进 `AND`/`Branch` 等于“只有死了才能打”。正确形态是 `bWeaponInHand AND NOT bIsDead`——在 `bIsDead` 后面插一个 **`NOT Boolean`**。

**视角、模型朝向的三处来源**（都要照顾到）：① 鼠标/右摇杆 → `AddControllerYawInput` / `AddControllerPitchInput`，直接改 **Controller 的 Yaw/Pitch**（`IA_Look`、`IA_Look_Gamepad`），门禁加在这两个事件最前面；② Controller 的 Yaw 被改后角色身体跟着转——`UpdateRotation_PreCMC` 会切 `CharacterMovement` 的 `bUseControllerDesiredRotation` / `bOrientRotationToMovement`，前者打开时角色平滑转向 Controller 朝向；③ `AC_Combat.ReceiveTick` 里还有一句 `SetActorRotation(Yaw = RInterpTo(当前, CachedInputRotation.Yaw, 13))`，把角色朝“上次攻击时的输入方向”转。所以**只关角色朝向是没用的**（镜头还在转），正确做法是拦 ①的入口，②③自然静止。

**按这三处自查的实际问法**：① 死后按左键，左键事件第一行有没有 `Branch(NOT bIsDead)`？② 死后按 WASD，`Cast To BPI_CombatComponent` 那根线在不在？③ 死后 0.4 秒内又“活”了一下，`OnPlayerHitRecover` 里有没有 `Delay`、死亡时 `HitStunTimer` 清了吗？

**最小修复顺序**（每步单独 PIE 验证）：① 在 `LightAttack` 函数入口加 `Branch(NOT bIsDead) → Return`（最外层攻击门禁：调试键、缓冲输入都绕不过函数本身）；② 在左键/重击输入事件最前面各加一次同样的 `Branch`（防输入缓冲把死亡后的点击排队）；③ 把 `HandlePlayerHit` / `HandlePlayerDeath` / `OnPlayerHitRecover` 里的 `Call*` 全部改成先 Cast 到玩家再调；④ 删掉 `OnPlayerHitRecover` 里残留的 `Delay`，恢复只走一次；⑤ 死亡 PIE 全验：左键、右键蓄力、侧键 1/2、V、WASD、跳跃 → 全部无反应；出招到一半死亡 → 动作停止且不再恢复。

**执行顺序的另一条硬要求**：`HandlePlayerHit` 里必须“先 `Clear` 旧计时器 → 再 `Set` 新计时器”，`Clear` 不能挂在 `Set` 后面，否则会把刚设的计时器清掉，表现为受击一次后永远不能动。

**PIE 验收清单（每项独立试，不要连按）**：常态左键/右键能打 → 死亡后左键/右键/装备键/侧键/V/WASD/跳跃/鼠标视角全部无反应 → 受击后 0.38s 恢复移动与攻击 → 出招中死亡动作停止且 1 秒内不自己恢复。

### 11.1 死亡后镜头与朝向怎么真正收口

**修法 A（推荐）：在玩家 BP 的两个 look 事件前面加 `bIsDead` 门禁**

> **易错点**：`Get Component By Class` 的 `Component Class` 选了 `AC_Combat` 之后，**`Return Value` 引脚本身就是 `AC_Combat` 类型**，直接拉 `Get bIsDead` 就行，**不需要再 `Cast To AC_Combat`**；如果把 `Cast To` 当纯数据节点用（exec 不接），cast 不会执行、`As AC Combat` 可能读到空值。要么不用 Cast，要么把 exec 也串进链里（`Triggered → Cast → Branch`）。

1. 打开 `/Game/Blueprints/SandboxCharacter_CMC` → `EventGraph`，找到 `IA_Look`（鼠标）和 `IA_Look_Gamepad`（手柄）两个 `EnhancedInputAction` 节点。
2. 右键搜 **`Get Component By Class`** → `Class` 引脚选 **`AC_Combat`**（不是 `ActorComponent`）；从 `Return Value` 直接拉出 **`Get bIsDead`**（拖变量进来或在引脚上拖出后搜 `bIsDead` 选**获取**，**不要**选“设置 bIsDead”）。
3. 接 **`NOT Boolean`** 得到“还活着”的布尔。
4. **断开** `IA_Look.Triggered` → `AddControllerYawInput` 的连线，改成 `Triggered → Branch`、`Branch.Condition = NOT 结果`、`Branch.False → AddControllerYawInput`、`Branch.True → 留空`。原来 `AddControllerYawInput` 的 exec 输出还接着 `AddControllerPitchInput`（上下看），所以**只拦 yaw 这一头就同时拦住了俯仰**。
5. 手柄那条 `IA_Look_Gamepad` 同样处理（它后面先经过几个 `Promotable Operator` 再进 yaw/pitch，门禁要加在**这些运算之前**）。
6. `bIsDead` 不能是私有变量：选中 AC_Combat 的 `bIsDead`，细节面板 **Private** 没勾（默认不勾，能跨蓝图读）。

**修法 A′（更省、更不容易接错，和 A 二选一）**：死亡事件本来就在玩家 BP 里接（`GASCombatOnDeath → AC_Combat.HandlePlayerDeath`），顺手加一句 **`Set bIsDeadLocal = true`**（玩家 BP 新建布尔变量 `bIsDeadLocal`），look 事件里直接读这个本地布尔 → `NOT` → `Branch`。不用每帧 `Get Component By Class`、不用跨蓝图 Cast，门禁和死亡事件共用同一个来源；以后做复活在同一处置回 false。

**修法 B（可选，省每帧查找）**：玩家 BP 加变量 `CombatComponent`（类型 `AC_Combat`），在 `ReceivePossessed`（或 `GASCombatOnCombatReady`）里 `Get Component By Class (AC_Combat) → Cast → Set CombatComponent`，之后 look 事件直接用 `CombatComponent → Get bIsDead`。`ReceivePossessed` 时组件已创建完毕，是安全的；不要放在 `ConstructionScript`（PIE 下副本还没生成）。look 事件一帧最多一次，每帧查找开销可忽略，**先把 A 做对再考虑 B**。

**补充：想连第 3 处也彻底静止**：在 `AC_Combat.HandlePlayerDeath` 末尾加 **`Set Component Tick Enabled`（Target = 组件自己 `self`，`bEnabled = false`）**。死亡路径已经 `CallWeaponTrace(false)`，Tick 里的武器检测本来也不会结算；Tick 关掉后 `ReceiveTick` 的试转和武器检测都不再跑。**不要**用玩家 BP 的 `Set Actor Tick Enabled(false)`——那会连动画、移动组件一起停，死亡蒙太奇也播不出来。

**验收**：死亡后鼠标上下左右 + 手柄右摇杆 → 镜头不动、模型不转；活着时视角正常；死亡后左键/右键/装备键/侧键/V/WASD/跳跃仍全部无反应。**预计**：0.3h。

### 12.3 「前向 × 50」与球体检测（向量入门）

`前向 × 50` = **“从敌人身体中心，沿他面朝的方向，往前 50 厘米的那个点”**，单位是**厘米**（UE 默认 1 单位 = 1 cm）。

1. `Get Actor Forward Vector` 返回**长度为 1** 的向量，指向该 Actor 的正面：敌人朝世界 +X 时是 `(1, 0, 0)`，转 90° 后变成 `(0, 1, 0)`——**它永远跟着敌人的朝向走**，所以用它而不是写死 `+X`。
2. `Multiply` 一个 `50`（类型选 **Float**）：`(1,0,0) × 50 = (50,0,0)`，长度变成 50 cm。
3. 起点前挪 50 的原因：敌人胶囊半径约 42 cm，起点放身体中心会让检测球**先包住自己**（半径 60 > 50，挪 50 cm 后仍与自身胶囊重叠）。所以**必须**在 `Actors to Ignore` 里填 `Owner`。
4. 终点 `前向×160` 的原因：球体检测是**扫掠**（一个球从 Start 扫到 End，扫过的整个“胶囊形”体积都算命中），不是单点；50→160 覆盖 `50 - 60` 到 `160 + 60`，即从贴近身体到前方约 2.2 m。
5. 半径 60：给挥砍留的“宽度/厚度”。太小（20）只有刀尖正中才算命中；太大（120）会隔空打人。

**节点连法**（`Sphere Trace For Objects` / 搜 `Sphere Trace`）：

```
Start = Get Actor Location(Owner)  +  (Get Actor Forward Vector(Owner) × 50)
End   = Get Actor Location(Owner)  +  (Get Actor Forward Vector(Owner) × 160)
Sphere Trace For Objects（按对象类型进行球体追踪）
    Start = 上面 Start
    End   = 上面 End
    Radius = 60
    Object Types = [ Pawn ]       ← 玩家是 Pawn 对象类型；点数组里的 + 加一个元素，下拉选 Pawn
    Trace Complex = false
    Actors to Ignore = [ Owner ]          ← 千万别漏
    Draw Debug Type = For Duration / Duration = 2  ← 调试期打开，PIE 里能直接看到球扫过的范围
    Out Hit → Break Hit Result → Hit Actor
```

**为什么不用 `By Channel`**：`Sphere Trace By Channel` 默认的 `Visibility` 通道在本项目扫不到玩家（玩家胶囊/网格用的 `Pawn`、`CharacterMesh` 预设都忽略 `Visibility`，见 `Config\DefaultEngine.ini` 的 `+Profiles=(Name="Pawn"...)` 与 `(Name="CharacterMesh"...)`），表现是“敌人出招、球是红的、什么都不发生”。

**如果 `Object Types` 的 `+` 找不到**：元素的 `+` 在**图表里的节点本体**上（`Object Types` 那一行最右端；节点拉宽一点、或选中节点后在图上找），**详情面板里通常不显示**。也可以换等价节点 **`Sphere Trace By Profile`**，`Profile Name` 填 **`Pawn`**——Name 字符串输入，完全不涉及枚举数组；它的下拉里列的是**碰撞预设名**（`Pawn` / `CharacterMesh` / `BlockAll` / `NoCollision`…），没有 `Visibility` 是正常的。

**三个数字怎么调**：50 = 起点离身体多远（差不多“手的位置”）；160 = 挥击能碰到的前后距离；60 = 挥击宽度。调参先动 160 和 60，50 一般不用改（手感偏短加 160，偏“隔空打”减 60）。这三个是手感参数，**不写进 DT**，做成 `AC_EnemyAttack` 的三个 Float 变量（`TraceForwardOffset` / `TraceLength` / `TraceRadius`）方便边 PIE 边调。调试技巧：`Draw Debug Type = For Duration` + `2` 秒，PIE 里能看到一串绿球沿敌人面前扫过去。

**自检**：PIE 站在敌人 2.5m 内 → 每约 2 秒挨一刀，掉 `enemy.shadow.atk`（10）血并播受击；走远（3m 外）→ 球不绿、不掉血；按 T 打自己仍正常。

> ⚠️ 本步易错，见 K036、K037。

### 12.4 组件初始化与 `DoAttackHit` 的入口约束

**正确的 `ReceiveBeginPlay` 顺序：Cast → Is Valid → Set → 再起计时器**

```
ReceiveBeginPlay
  → Cast To Character (Object = Get Owner)
      Cast Failed → Print String("AC_EnemyAttack 挂错 Actor 了")   ← 调试期必有
      As Character → Set Owning NPC
  → Is Valid (Owning NPC)
      True  → Set Timer by Event (Delegate = AttackLoop, Time = AttackInterval, Looping = true)
      False → Print String("OwningNPC 仍为空，检查 Cast 是否接到 Set")
```

`Cast` 的 `As Character` 输出**必须真的接到 `Set Owning NPC`**，否则 `DoAttackHit` 一读 `OwningNPC` 就报「尝试读取 AC_EnemyAttack_C 中的属性 OwningNPC 时，结果为无」。**`DoAttackHit` 只由 `AN_EnemyAttackHit` 通知触发**：`BeginPlay`、`Tick`、`ReceiveActorBeginOverlap` 一律不接——挂在常驻事件上会让所有敌人在 BeginPlay 同时调一次，那时 `OwningNPC` 还没赋值。

**Notify 侧必须真正串 exec**：只有数据线（`Get Owner` → `Find Component by Tag`）而 exec 还是 `Entry → Result` 直连的话，`DoAttackHit` 根本不会被调用，表现是“敌人出招了但打不到人、也没有报错”。正确链条：

```
Received_Notify
  → Get Owner
  → Find Component by Tag (Tag = "EnemyAttack")
  → Is Valid
      True  → Cast To AC_EnemyAttack → 调 DoAttackHit
      False → Print String("Notify 没找到 EnemyAttack 组件：检查组件 Tags")
```

顺带检查：`BP_MasterNPC` 里 `AC_EnemyAttack` 组件的 **Component Tags** 必须填 `EnemyAttack`（没有它 `Find Component by Tag` 必然返回空）。

> ⚠️ 本步易错，见 K025、K035。

### 12.5 敌人不鞭尸：跨蓝图读“玩家死了没”

`AttackLoop` 只判距离是不够的：玩家死后尸体还在原地，距离一直满足，敌人会每 `AttackInterval` 继续挥刀。**`bIsDead` 是 `AC_Combat` 上的普通变量，蓝图之间可直接读，不需要接口、不需要事件**。

```
Player (AC_EnemyAttack 里已赋值的 Character)
  → Get Component By Class（Target = Player，Component Class = AC_Combat）  ← 类选择器里选 AC_Combat（不是 Cast）
  → Return Value（此引脚已经是 AC_Combat 类型，不需要再 Cast）
  → Is Valid
      False → 玩家没挂组件（理论上不会发生），按“活着”处理或直接 return
      True  → Get bIsDead（右键搜 bIsDead）
```

要点：`Get Component By Class` 的 `Return Value` 是**“按 `Component Class` 决定的输出类型”**（引擎用 `DeterminesOutputType` 实现，`Runtime/Engine/Classes/GameFramework/Actor.h:3805` 同款元数据），选 `AC_Combat` 时返回的就已经是 `AC_Combat` 引用；**一定要先 `Is Valid`**，玩家身上没有该组件时 `Return Value` 是空，直接拉 `bIsDead` 就会报“尝试读取…属性 bIsDead 时，结果为无”；读不到 `bIsDead` 时把节点右键菜单的 **Context Sensitive（上下文关联）关掉**再搜。

**插到两个地方（双保险）**

1. **`AttackLoop`（主修，让它停手）**：放在 `Set Player = Get Player Character(0)` 之后、距离判断之前——`if (玩家无效) → return`、`if (Player 的 bIsDead) → return`、`if (距离 > AttackRange) → return`。
2. **`DoAttackHit`（兜底，防其他调用路径）**：命中后、`Array Add`/对目标造成伤害之前——`Break Hit Result → Hit Actor → if (Hit Actor 的 bIsDead) → return`，不 Add、不结算、不播受击。这里的 `bIsDead` 是**命中到的那个 Actor** 的组件，不是 `Player` 变量（用 Hit Actor 更准，也顺便挡住“别的玩家/召唤物”）。

**守卫怎么写**：`DoAttackHit` 开头的守卫是“**该不该继续**”，条件写成 `if (NOT bAttacking OR bIsParryStunned OR TargetIsDead) → return`（都是 OR，任一成立就退出）。**不要**用 `AND` 拼死亡判断；入门阶段用连续的 Branch 逐个判，好读也好查。不读 `Health` 属性来判断（读属性要走 GAS 节点，且“血=0 但还没播死亡”的瞬间语义不一致；`bIsDead` 是 `HandlePlayerDeath` 里第一时间置的），也不靠“攻击里不结算伤害”假装停手（那样敌人会永远贴着尸体挥刀）。

**自检**：PIE 里让敌人把玩家打死 → 玩家倒地后敌人**不再挥刀**；重开 PIE → 敌人恢复出招；玩家死亡瞬间若正好有一刀在挥，那一刀不应再让玩家播受击或掉血。

### 12.6 纯节点空值求值：按“先确认非空，再往下走”拆分支

把 `Hit Actor → Get Component By Class → bIsDead` 这条链直接接进分支条件，即使这一帧球没命中也会报错：

```
尝试读取非UClass中的(real)属性 CallFunc_BreakHitResult_HitActor，结果为无。 节点：分支  图表：DoAttackHit
尝试读取非UClass中的(real)属性 CallFunc_GetComponentByClass_ReturnValue_2，结果为无。 节点：分支  图表：DoAttackHit
```

这两条不是逻辑错误，而是“在对象为空时读了它的属性”；报错里的名字不是变量，是**上游纯节点（pure）的输出引脚名**。蓝图的**纯节点（没有白色 exec 引脚）会在任何读取它输出的地方被求值**：条件链一旦被执行流走到就会**从头到尾算一遍** → 空对象被读 → 报错。

**正确写法：拆成带 exec 的分支**（不要塞进同一个 `AND`/`OR` 条件——纯节点在条件里会**两边都算**，`Is Valid` 为假也拦不住另一半）：

```
Sphere Trace By Profile（exec）
  → Branch（Condition = 追踪节点的 Return Value（bool））      ← 读 bool 是安全的
       False → 结束（没命中，什么都不做）
       True  → Break Hit Result → Hit Actor
               → Branch（Condition = Is Valid(Hit Actor)）    ← 先确认命中的是人
                    False → 结束
                    True  → Get Component By Class（Target = Hit Actor，Class = AC_Combat）
                            → Branch（Condition = Is Valid(Return Value)）  ← 再确认组件在
                                 False → 结束
                                 True  → Branch（Condition = Get bIsDead）
                                           True  → 结束（死了不结算）
                                           False → Array Contains（去重）→ Array Add → 对目标造成伤害
```

**`Is Valid` 本身可以吃空对象**（它就是“判空”函数），所以 `Is Valid(Hit Actor)` 不会报错，会报错的是“读空对象的成员”；判断 `bIsDead` 的链必须放在**两次 `Is Valid` 都为真之后**；也可以用 `Out Hit → bBlocking Hit` 代替 `Return Value`（结构体引脚永远存在，读它安全）。

**自检**：PIE 里在敌人面前左右横跳（一半挥刀落空、一半命中）持续 30 秒，Output Log 过滤 `Attempted to read` / “尝试读取” 应为 0 条；命中时照常掉血与受击，没命中时什么都不发生。

> ⚠️ 本步易错，见 K034。

### 12.7 敌人自己的死亡守卫：`StopCombat`

**要解决的问题**：敌人被打死、死亡动作播完后仍会站起来继续攻击玩家。因为 `AC_EnemyAttack` 只查了 `bAttacking`、`bIsParryStunned`、`Player` 的 `bIsDead`，**没有一处查“自己（`OwningNPC`）已死”**；`AC_NPC.HandleDeath` 又只做了 `DisableMovement` 与 `SetCollisionEnabled`，既不清 `AttackLoop` 的循环计时器，也不 `StopAnimMontage`、不复位 `bAttacking`。

**Step 1｜加两个自己的变量**：`AC_EnemyAttack` 是组件，只能靠自己身上的状态——不要试图去读 `AC_NPC` 的变量。加 `bDead`(bool，默认 false)、`AttackLoopTimer`(TimerHandle)；把 EventGraph 里 `Set Timer by Event` 的 **Return Value** 存进 `AttackLoopTimer`。

**Step 2｜新建 `StopCombat` 函数：让它自己收拾自己**（每步连成一条 exec 链，用 `OwningNPC` 或 `self` 取自己）：`Set bDead = true` → `Clear and Invalidate Timer by Handle`（Handle = `AttackLoopTimer`）→ `Set bAttacking = false` → `Set bIsParryStunned = false` → `Array Clear`（Target = `HitTargetsThisSwing`）→ `OwningNPC → Get Mesh → Stop Anim Montage`（Montage = `AttackMontage`，**只停攻击蒙太奇**；不要用 `Montage Stop` 全停，会连死亡蒙太奇一起停掉）。

**Step 3｜给两个门加自身死亡门**：`AttackLoop` 在**第一道 `OwningNPC` 有效性判断之后**插 `Branch`，`Condition = Get bDead`，true 直接结束；`DoAttackHit` 把开头那道 `if (NOT bAttacking OR bIsParryStunned)` 并入 `OR bDead`。两处都只读**自己的** `bDead`，不跨组件。

**Step 4｜`AC_NPC.HandleDeath` 通知攻击组件停工**：在末尾（`bDead` 已置 true 之后、`DisableMovement` / `SetCollisionEnabled` 那一带）：`Get Owner → Get Component By Class(AC_EnemyAttack) → Is Valid → 调 StopCombat()`。清理动作全在 `StopCombat` 里，这里只负责“通知”，不需要从组件外部去动它的计时器和变量。

**Step 5｜PIE 验收**：把敌人打死，观察 10 秒——不再出现「执行攻击函数」日志、不再播攻击蒙太奇、玩家血量不变；重新开局/重刷敌人后行为正常。

**自检**：敌人死亡动作播完后保持倒地/消失；死亡瞬间正在挥的那一刀不结算伤害；玩家在敌人尸体旁站 10 秒不被攻击。

> ⚠️ 本步易错，见 K022、K040。

### 12.8 敌人受击硬直：`NotifyHitStunned`

**要解决的问题**：玩家打中敌人，敌人确实进入受击硬直（`GE_HitStun` + 受击蒙太奇），但攻击照旧——受击动作刚起就被下一刀顶掉，硬直期间照样转向、照样结算伤害。原因是 `AC_NPC.ApplyHitReaction` **没有一处通知 `AC_EnemyAttack`**：硬直只活在 GAS 效果和动画层，攻击侧读不到；受击蒙太奇抢占攻击蒙太奇会触发异步 `Play Montage` 的 `On Interrupted`，而它只做 `Set bAttacking = false`，下一个 `AttackInterval` 立刻重新起手。

**Step 1｜`AC_EnemyAttack` 新增两个变量**：`bIsHitStunned`(bool，默认 false)、`HitStunTimer`(TimerHandle)。

**Step 2｜新建函数 `NotifyHitStunned(StunDuration: float)` + 自定义事件 `EndHitStun`**（一条 exec 链，全部用 `OwningNPC` / `self`）：

1. `Set bIsHitStunned = true`；
2. `Clear and Invalidate Timer by Handle`（Handle = `HitStunTimer`）—— 连续命中时重置，不要叠加；
3. `Set bAttacking = false`；
4. `OwningNPC → Get Mesh → Stop Anim Montage`（Montage = `AttackMontage`）—— **只停攻击蒙太奇**；
5. `Array Clear`（Target = `HitTargetsThisSwing`）—— 防同一挥击在硬直里补结算；
6. `Set Timer by Event`（Delegate = `Create Event` → `EndHitStun`，Time = `StunDuration`，Looping = false），**Return Value → `HitStunTimer`**。

`EndHitStun`：只做 `Set bIsHitStunned = false`（不要在这里清 `AttackLoopTimer`，也不要重启循环，理由见 Step 3）。

**Step 3｜给两个门加受击硬直守卫**：`AttackLoop` 的第一道 `if (NOT (bAttacking OR bIsParryStunned))` 的 `OR` 再加一项 `bIsHitStunned`；`DoAttackHit` 开头 `if (bDead OR (NOT bAttacking OR bIsParryStunned OR Player.bIsDead))` 里并入 `bIsHitStunned`。**为什么不清 `AttackLoopTimer`**：循环计时器只负责“每 `AttackInterval` 唤一次 `AttackLoop`”，守卫会让它空转返回；硬直结束时 `bIsHitStunned=false`，下一次 tick 自动恢复出招。清掉就得在 `EndHitStun` 里重建，等于多一个“可能忘配”的计时器。

**Step 4｜死亡清理补两句**：`StopCombat` 末尾加 `Set bIsHitStunned = false` + `Clear and Invalidate Timer by Handle`(Handle = `HitStunTimer`)，这样“受击中被打死”不会残留硬直状态和计时器。`StopCombat` 里已有 `Set bDead = true`，做死亡的；**绝不能用它兼硬直**，否则硬直一次等于永久死亡。

**Step 5｜`AC_NPC.ApplyHitReaction` 通知攻击组件（推模型）**：在算出 `StunDuration`、并 `ApplyEffectWithValues` / `PlayAnimMontage` 之后（函数链尾）：`OwningCharacter → Get Component By Class(AC_EnemyAttack) → Is Valid → 调 NotifyHitStunned(StunDuration)`。理由与 §12.7 Step 4 相同：`AC_NPC` 是组件类，别去 `Cast To AC_NPC`，也别跨组件读变量。

**Step 6｜PIE 验收**

1. 轻击命中：0.35s 内敌人不出招、不再结算伤害；硬直结束后恢复出招；
2. 重击（伤害 ≥ `combat.enemy.hitstun_large_threshold` = 24 点）：1.8s 硬直，期间完全不出招；
3. 连续快速命中三次：每次命中重置硬直，**不会叠加成无限硬直**（看 `HitStunTimer` 是否被清）；
4. 硬直中把敌人打死：不再出现「执行攻击函数」日志，受击蒙太奇不被攻击蒙太奇顶掉；
5. Output Log 无红字、过滤「尝试读取」为 0 条。

**自检**：上面 5 条逐条过；`bIsHitStunned` 一定挂在 `AC_EnemyAttack` 上（挂在 `AC_NPC` 上攻击组件读不到）。

> ⚠️ 本步易错，见 K023、K040。

### 14.1 TryToDodge 细讲：向量怎么变成可比大小的 float

`Get Last Movement Input Vector` 返回的是 `Vector`（世界空间，长度 0–1），`0.1` 是 `Float`——蓝图里不存在「向量 < 浮点数」这种节点，必须先把向量**取长度**变成标量：

| 顺序  | 节点（中文显示名 / 内部名）                                                        | 输入                         | 输出            | 作用                             |
| --- | ---------------------------------------------------------------------- | -------------------------- | ------------- | ------------------------------ |
| 1   | `Get Last Movement Input Vector`（GetLastMovementInputVector）           | Target = `OwningCharacter` | `Vector`      | 玩家这一帧想往哪走（世界空间，已含八方向合成）        |
| 2   | **`Vector Length XY`（VSize2D）**                                        | `Vector`                   | `Float`       | **关键一步**：把「方向+大小」压成一个数字（只取水平面） |
| 3   | `>=`（GreaterEqual_FloatFloat）                                          | A = 长度，B = `0.1`           | `bool`        | 死区判断：小于 0.1 视为「没推方向」           |
| 4   | `Branch`（分支）                                                           | Condition = 上一步 bool       | 两条 exec       | True = 有方向，False = 无方向         |
| 5A  | True：`Normalize`（归一化 / Normalize）                                      | `Vector`                   | 单位 `Vector`   | 长度变 1，后面算角度才稳定                 |
| 5B  | False：`Get Actor Forward Vector` → `Multiply (Vector × Float, B = -1)` | —                          | 反向单位 `Vector` | 后撤方向                           |
| 6   | `Play Anim Montage` / `SelectDodgeMontage`                             | 方向                         | —             | 后续步骤                           |

> 为什么用 **`Vector Length XY`** 而不是 `Vector Length`：`Vector Length` 含 Z，角色站在斜坡、跳起、被击退时会带 Z 分量，容易把「没按方向」误判成「有方向」。`Vector Length XY` 只看前后左右。

**函数签名（以资产实测为准，别自己加参数）**

`AC_Combat.TryToDodge` 是**无参函数**（`void TryToDodge()`），方向在函数内部取、在内部合并，调用方不需要传任何数据：

```
TryToDodge()                                   // 无参数
  ├─ Branch(CanStartDodge())
  │    True → SelectDodgeMontage(MoveDirWorld = Select(…)) → Play Anim Montage → Set bIsDodging
  └─ False → Print String("当前无法进行闪避")
```

- 方向来源：`Get Last Movement Input Vector`（Target = `OwningCharacter`）。
- 死区判断：`Vector Length XY(输入) >= 0.1` → 接到 `Select` 的 **`Pick A`** 引脚。
- `Select` 的输出（世界空间单位向量）只喂一处：`SelectDodgeMontage.MoveDirWorld`；蒙太奇由 `SelectDodgeMontage` 返回后再接 `Play Anim Montage` 的 `Montage` 引脚。
- 调用点：玩家 BP 的 `IA_Sprint` 里 `Started → 拖出自身变量 AC_Combat → 调 TryToDodge`（无参，数据引脚一个都不用接）。
- 想单独测某个方向：在函数里临时把 `Get Last Movement Input Vector` 换成 `Make Vector` 常量，测完改回，**不要改签名**。

> **优化（可选）**：如果第 15 课要拿「本次闪避方向」做位移，建议在 `TryToDodge` 里加一个 `DodgeDirection`(Vector) 变量，`Select` 输出先 `Set DodgeDirection`，再把它接 `SelectDodgeMontage` 与 `Launch Character`——这样「方向」只有一个来源，以后改公式不用改两处。

**必须知道的三件事**

1. `Get Last Movement Input Vector` 是「移动意图」的合成结果，**不是速度**，也不是原始轴值（`S_PlayerInputState` 里的 X/Y）。它是世界空间向量，所以**不需要**再乘 Right/Forward——那一步已经由输入系统做完了。
2. 同帧陷阱：按下方向键和按 Shift 在同一帧时，`Get Last Movement Input Vector` 可能还是 0（输入处理顺序）→ 才会出现「偶尔跳成后撤」。这就是 0.1 死区的来源，不是 bug。
3. 顺序不能反：**先判长度、再归一化**。0 向量归一化还是 0，长度判断就失效了。

| `(0,0,0)`       | 后撤分支 | `AM_Dodge_B_180`  |
| `(1,0,0)`（角色前向） | 0    | `AM_Dodge_F_0`    |

| `(-1,0,0)`      | 4    | `AM_Dodge_B_180`  |

（向量方向按「世界 X 前、Y 右」记；若角色旋转过，用 `Get Actor Forward Vector` 做基准换算，别直接拿世界 X。）

### 14.2 两条分支怎么合流：exec 只走一条主线

**硬规则**：蓝图的 **exec（白线）输入引脚只能接一根线**。所以 `Branch.True` 和 `Branch.False` **不可能同时接到同一个后续节点**。

**正确做法：exec 只留一条主线，用纯节点 `Select` 合并两条数据**（`Select`，中文「选择」：输入 `A`、`B` 两个候选值 + **`Pick A`** 一个 bool，输出 `Return Value`；`Pick A` 为真取 `A`，否则取 `B`）。

> **引脚名以资产实测为准**：本项目图里 `Select` 的 bool 输入引脚叫 **`Pick A`**（内部名 `bPickA`），不是 `Condition`。拖出 `Select` 节点后，它下半部分的勾选框就是 `Pick A`。

把所有多余的分支删掉，只保留一条主线，改成：

```
CanStartDodge ──Branch(False → Print "当前无法进行闪避")
                  True ↓
        ┌──────────────────────────────────────────────┐
        │ Select (Vector)                              │
        │  Pick A = (Vector Length XY(方向) >= 0.1)     │
        │  A      = Normalize(方向)                     │
        │  B      = GetActorForwardVector × (-1)        │
        └──────────────────────────────────────────────┘
                  │ Return Value（方向）
                  ↓
        SelectDodgeMontage(方向) → Play Anim Montage
```

要点：

- `Select` 是**纯节点**（没有白线），只负责「二选一给个值」，不参与执行流；执行流从 `Branch.True` 直接接 `SelectDodgeMontage` / `Play Anim Montage`。
- `Pick A` 就是那个 `>= 0.1` 的 bool；`A` 接「有输入时的单位向量」，`B` 接「后撤方向」。
- 想更好调试：把 `Select` 的输出先 `Set DodgeDirection`（局部变量），后面几步都读它，PIE 里能直接看到这个值。
- 后撤方向别用「世界 -X」：角色转身后世界 -X 不是背后的方向。用 `Get Actor Forward Vector × (-1)`（`Multiply (Vector × Float)`，B 填 `-1.0`）。

### 14.3 `Normalize` / `Normalize In Place` 怎么选

| 你的输入                                           | 用哪个节点                                          | 说明                                             |
| ---------------------------------------------- | ---------------------------------------------- | ---------------------------------------------- |
| `Vector`（`Get Last Movement Input Vector` 就是它） | **`Normalize`**                                | A = 向量，Tolerance = `0.0`，`Return Value` = 单位向量 |
| `Vector2D`                                     | **`Normalize 2D`**                             | 同理，别用 In Place                                 |
| 确实要给变量原地归一                                     | `Normalize In Place` / `Normalize 2D In Place` | A 接**变量的引用**（拖变量进来），节点返回 bool（是否变了），结果写回那个变量   |

**本项目建议**：全程走 `Vector`（3D）——`Get Last Movement Input Vector` 本来就是 Vector，`Vector Length XY` 只取水平长度用于死区判断，`Normalize` 用 3D 版即可；不要中途换成 Vector2D，否则每换一次都要转换节点，容易接错。

**顺序再确认一遍**：`长度判断（Vector Length XY + >= 0.1）` → `Normalize`。先归一化再判长度，0 向量归一化仍是 0，死区就失效了。

> ⚠️ 本步易错，见踩坑册 K061

### 14.4 引脚分两种颜色：白箭头 vs 圆点

蓝图里只有两类引脚，先分清这个，后面所有「接不上」都能自己判断：

| 长什么样        | 叫什么        | 能接什么                                                       | 例子                                              |
| ----------- | ---------- | ---------------------------------------------------------- | ----------------------------------------------- |
| **白色三角箭头**  | 执行引脚（exec） | **只能接白色三角箭头**                                              | `Branch` 的 True/False、`Play Anim Montage` 的入口   |
| **彩色圆点/菱形** | 数据引脚       | **只能接同类型的数据圆点**（Vector 接 Vector、Float 接 Float、bool 接 bool） | `Normalize` 的 `Return Value`、`Select` 的 `A`/`B` |

**`Normalize In Place` 与 `Select` 接不上**，因为它：

- 没有「结果输出」圆点（结果写回变量里了，不在引脚上）；
- 它的 `A` 是**输入**（还带着 by-ref 菱形标记），只能接一个**变量**，不能接别的节点算出来的东西；
- 它还带白色 exec 箭头（因为它要改数据，属于「有执行顺序」的节点）。

而 `Select` 的 `A` 要的是**一个向量数据**。所以：`Normalize In Place` 的白色箭头 → 接不进 `Select` 的圆点；它的 `A` 是入口不是出口。

**你要的是纯节点 `Normalize`（不带 In Place、没有白色箭头）**：`A` 是输入、`Return Value` 是输出，输出圆点接 `Select.A` 即可。

**怎么一眼认出来**：拖节点时看它有没有白色箭头。**有白色箭头 = 它参与执行流**；`Normalize`（纯节点）只有圆点、没有白色箭头。更多引脚语义坑见 K061、K062。

### 14.5 `SelectDodgeMontage` 细讲（节点级，一个不落）

**本课产出**：`AC_Combat` 上多一个数组变量 `DodgeMontageBySector`（8 个闪避蒙太奇），函数 `SelectDodgeMontage(MoveDirWorld : Vector) -> AnimMontage` 能按「输入方向相对角色朝向」的夹角返回对应方向的那一个。

**第 0 步：先把数据放好（不用连线）**

| 变量名                    | 类型                        | 用途            | 默认值怎么填                             |
| ---------------------- | ------------------------- | ------------- | ---------------------------------- |
| `DodgeMontageBySector` | `TArray<AnimMontage>`（数组） | 0→7 号扇区对应的蒙太奇 | 编译后到组件实例的 Details 面板里按下面的顺序加满 8 个元素 |

**数组下标与蒙太奇的对应关系（这个顺序就是「真相」，以后调方向只动这里）**：

| 数组下标 | 角度范围（相对角色正前方）     | 蒙太奇               | 按键直觉 |
| ---- | ----------------- | ----------------- | ---- |
| 0    | -22.5° ～ +22.5°   | `AM_Dodge_F_0`    | W    |
| 1    | +22.5° ～ +67.5°   | `AM_Dodge_F_R_45` | W+D  |
| 2    | +67.5° ～ +112.5°  | `AM_Dodge_R_90`   | D    |
| 3    | +112.5° ～ +157.5° | `AM_Dodge_B_R_45` | D+S  |
| 4    | +157.5° ～ ±180°   | `AM_Dodge_B_180`  | S    |
| 5    | -157.5° ～ -112.5° | `AM_Dodge_B_L_45` | S+A  |
| 6    | -112.5° ～ -67.5°  | `AM_Dodge_L_90`   | A    |
| 7    | -67.5° ～ -22.5°   | `AM_Dodge_F_L_45` | W+A  |

（正角度 = 角色右侧，因为 UE 里 Yaw 正向从 +X 转向 +Y，而 +Y 是角色右方。）

**第 1 步：算「方向相对角色的夹角」**

| 顺序  | 节点                         | 引脚怎么接                                                                                                                                 | 类型                |
| --- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| 1   | 函数输入 `MoveDirWorld`        | 由 `TryToDodge` 传入；来源是那个 `Select` 的输出：有输入时= `Normalize(Get Last Movement Input Vector)`，无输入时= `-Get Actor Forward Vector`，**两种都是单位向量** | `Vector`          |
| 2   | `Get Actor Rotation`       | Target = `OwningCharacter`                                                                                                            | `Rotator`         |
| 3   | `Find Look At Rotation`    | **Start 保持默认 `(0,0,0)`**，Target = `MoveDirWorld`                                                                                      | `Rotator`         |
| 4   | `Normalized Delta Rotator` | **A = 第 3 步的 Rotator，B = 第 2 步的 Rotator**                                                                                             | `Rotator`         |
| 5   | `Break Rotator`            | 输入 = 第 4 步输出；只取 `Yaw`                                                                                                                 | `Float`（-180…180） |

四个要点：

- **`Start` 必须是 `(0,0,0)`**，不是角色位置。`Find Look At Rotation` 是「从 Start 看向 Target」的朝向；Start 用原点时，它退化成「这个方向本身的 Yaw」。把 Start 换成角色位置，算出来的就是「角色看向那个点」的朝向，方向感会整个偏掉。
- **A/B 顺序是 A − B**。A=方向、B=角色，得到「方向在角色右边多少度」；接反了会左右镜像（W 正常、D 却播 `L_90`）。
- 用 **`Normalized Delta Rotator`**，不要用 `Delta (Rotator)`。后者不平滑到 ±180°，跨 0° 时会从 179 跳到 -179。
- 角色在斜坡上的 Pitch/Roll 不用管：我们只 `Break` 出 `Yaw`。

**第 2 步：夹角 → 扇区编号（0…7）**

| 顺序  | 节点                        | 接法                    | 中间值示例（W 时）    | 中间值示例（S 时）      |
| --- | ------------------------- | --------------------- | ------------- | --------------- |
| 6   | `Add (Float)`             | `Yaw` + `360.0`       | 0 + 360 = 360 | 180 + 360 = 540 |
| 7   | `Fmod`                    | A = 第 6 步，B = `360.0` | 360 % 360 = 0 | 540 % 360 = 180 |
| 8   | `Add (Float)`             | 第 7 步 + `22.5`        | 22.5          | 202.5           |
| 9   | `Divide (Float)`          | 第 8 步 ÷ `45.0`        | 0.5           | 4.5             |
| 10  | `Floor`（向下取整）             | 第 9 步 → 整数            | 0             | 4               |
| 11  | `Percent (Integer)` / `%` | 第 10 步 `% 8`          | 0             | 4               |

为什么是 `+22.5` 再 `÷45`：每个扇区 45° 宽，方向角落在「扇区中心 ±22.5°」内就算这个扇区。先加半宽（22.5）再除，就等价于「四舍五入到最近的扇区」。`% 8` 是防止 8（360° 附近）冒出来。

**第 3 步：扇区 → 蒙太奇，返回**

| 顺序  | 节点                                                                        | 接法                                                     |
| --- | ------------------------------------------------------------------------- | ------------------------------------------------------ |
| 12  | `Get Array Item`（拖出 `DodgeMontageBySector` 后搜 `Get`，选 **`Get (a copy)`**） | Array = `DodgeMontageBySector`，Index = 第 11 步 `Sector` |
| 13  | `Return Node`                                                             | 返回值接第 12 步输出                                           |

`Get Array Item` 是**纯节点**（没有白箭头），所以函数里执行流是「函数入口 → 直接连 Return Node」，中间这些算角度的节点全挂在 Return Node 的数据输入链上。**不要**给它们接白线。

**为什么用数组而不是 `Select` / `Switch`**

| 方案                        | 可行性         | 说明                                       |
| ------------------------- | ----------- | ---------------------------------------- |
| `Select` 节点               | ❌ 做不了 8 选 1 | 只有 `Pick A` + A/B 两路；要 8 路得嵌 3 层，节点爆炸    |
| `Switch on Int` + 8 个分支   | ⚠️ 能但难写     | 是**执行流**节点，每个分支都得到 Return Node；8 条线容易漏   |
| **数组 + `Get Array Item`** | ✅ 推荐        | 一条数据链、顺序一目了然、以后加「空中闪避/连闪」只要换数组          |

**校验顺序（定位方向错乱）**

1. 在 `TryToDodge` 里加 4 个 `Print String`：`MoveDirWorld`、`DeltaYaw`、`Angle01`、`Sector`，再接一个 `Get Array Item` 结果的 `Get Display Name`。
2. 站定不动只按 W：期望 `MoveDirWorld≈(1,0,0)`、`DeltaYaw≈0`、`Angle01≈0`、`Sector=0`。
3. 四个基准 W / A / S / D 依次试：`DeltaYaw` 应为 0 / -90 / 180 / +90，`Sector` 为 0 / 6 / 4 / 2。
4. **整体平移**（比如 W 播了 `F_R_45`）：公式没问题、数组顺序错了，按偏移量挪数组元素，别改公式。
5. **左右镜像**（W 对、D 播 `L_90`）：A/B 接反了，把 `Normalized Delta Rotator` 的两个输入互换。
6. 让角色原地转 90° 再按 W：若仍播 `F_0`，说明用的是**相对角**（正确）；若变成别的方向，说明有节点偷偷用了世界角。

**注意**：数组只填了 3、4 个元素 → 下标 5/6/7 取到空 → `Play Anim Montage` 静默不播；蒙太奇骨架不是 `SK_UEFN_Mannequin` 或没挂 `DefaultSlot` → 回第 7 课。

**预计**：1h。

### 14.6 `CanStartDodge` 的 7 项条件与失败原因打印

`CanStartDodge` 的完整公式：

```text
Can = NOT bIsDead
      AND NOT bIsHitStunned
      AND NOT bIsParrying
      AND NOT bIsDodging
      AND NOT bWeaponBusy
      AND IsMovingOnGround(CharacterMovement)
      AND (DodgeChainLeft > 0)
```

任一项为假都会走 False、只打印「当前无法进行闪避」。逐项自查：

| 条件                 | 快速验证                                                                                    |
| ------------------ | --------------------------------------------------------------------------------------- |
| `bIsDead`          | `Print String(Conv_BoolToString(bIsDead))`；活着应为 false                                   |
| `bIsHitStunned`    | 同上；受击硬直结束（第 10 课 `OnPlayerHitRecover`）后应回 false                                        |
| `bIsParrying`      | 招架还没做，应一直 false                                                                         |
| `bIsDodging`       | 成功闪一次后由 `EndDodgeAction`（§17.3）复位；未复位时第二次按 Shift 必 False                                  |
| `bWeaponBusy`      | 装备/卸下蒙太奇结束时必须干净回 false；卡在 true 会同时挡闪避和攻击                                                |
| `IsMovingOnGround` | 站着应 true；出生下落瞬间、被地形卡住时可能 false，用 `Get Character Movement → Is Moving On Ground` 打印      |
| `DodgeChainLeft`   | 开局应由 §17.1 的 BeginPlay 写成 `2`；打印一次确认                                                    |

**顺手确认两件事**：

1. **`CanStartDodge` 在图里只有一个调用节点**：实际接线是 `FunctionEntry → CanStartDodge(函数带执行引脚) → Branch.execute`，同时 `CanStartDodge.ReturnValue → Branch.Condition`。读图工具的输出里会看到两遍 `(call CanStartDodge)`（一遍当语句、一遍当 if 条件），那是**渲染假象，不是两个节点**。调用节点自己带 `execute/then`，是因为 `CanStartDodge` 有 `Return Node`、不是纯函数，这是正常写法。
2. `Greater (int)` 节点的 `B` 引脚默认 `0`，保持 0 即可；别改成 2，那会变成「剩余次数 > 2」。

**注意**：「走 False」不等于输入没接上——`TryToDodge` 被调到（有 Print 输出就说明输入链是通的）之后，False 只表示门禁返回 false。

**预计**：0.5h。

## 第 15 课 M2-2 闪避位移与碰撞

**目标**：闪避推动胶囊与模型一起移动，距离读数，碰墙不穿墙。

**前置**：第 14 课。

**操作**

1. 先在 `TryToDodge()` 里把「这次闪避的方向」存下来（新增变量 `DodgeDirection : Vector`；`Select` 的输出先 `Set DodgeDirection`，再把它接 `SelectDodgeMontage.MoveDirWorld`）。然后播完蒙太奇后追加：

   ```
   Distance = GetCombatParam(DT_Combat, "combat.dodge.distance")
   Duration = GetCombatParam(DT_Combat, "combat.dodge.iframe")
   Speed    = Distance / Duration
   Launch Character(Target = OwningCharacter, Velocity = DodgeDirection * Speed,
                    bXYOverride = true, bZOverride = false)
   Set Timer by Event(CreateEvent(DodgeMoveStop), Duration, Looping=false) → 返回值存 DodgeMoveStopTimer
   ```

   > 两个容易漏的点：① 新增计时器句柄变量 **`DodgeMoveStopTimer`**（`TimerHandle`），否则后面第 18 课清不掉；② `Speed` 单位是 cm/s，`combat.dodge.distance` 是厘米（400），`combat.dodge.iframe` 是秒（0.3）→ 1333 cm/s，别把距离当米。

2. 事件 `DodgeMoveStop`：`Launch Character(Target = OwningCharacter, Velocity = (0,0,0), bXYOverride = true, bZOverride = false)`（保留 Z，避免闪避中悬空速度被清）。

3. 编译保存，PIE 实测：无输入闪避看位移方向（应为后撤）；按 W 闪避向前；对着墙闪 → 停下不穿墙。

**为什么**

- 位移时长复用 `combat.dodge.iframe` 是本轮定下的决定（规划 §0.6），少一个键，且「位移与无敌同起同止」最直观。
- 用 `LaunchCharacter` 而不是 `AddMovementInput`：后者需要持续 Tick 喂输入，还会被 CMC 摩擦/加速曲线改写距离；`LaunchCharacter` 一次性给速度，距离可预期。
- 必须用 `bXYOverride = true`：否则和玩家当前的移动速度叠加，距离会随是否在跑而变化。

**自检**：平地无方向闪避 → 后撤约 4 米（400cm，允许摩擦误差）；按 W → 前扑；对墙 → 停在墙前；模型与胶囊没有明显分离。

**注意**：位移没在结束/打断时清零 → 角色持续滑行；序列本身带根运动 → 位移翻倍（回第 3 课关根运动）。

**预计**：1h。

## 第 16 课 M2-3 无敌窗口

**目标**：无敌窗口内的近战攻击完全无效（不掉血、不硬直、不打断），窗口外正常受伤；同一次挥击跨窗口结束不补伤害。

**前置**：第 15 课；第 13 课拦截插槽。

**操作**

1. `TryToDodge()` 里加（计时器句柄 `DodgeInvincibleTimer` 第 14 课已建）：

   ```
   bInvincible = true
   Set Timer by Event(CreateEvent(EndInvincible), Duration, Looping=false) → 返回值存 DodgeInvincibleTimer
   ```

   （`Duration` 就是上面算好的 `GetCombatParam(DT_Combat, "combat.dodge.iframe")`，别另外再读一次写死 0.3。）

2. 事件 `EndInvincible`：`bInvincible = false`。

3. 把 `AC_Combat.TryDefendAttack` 改成：

   ```
   if bInvincible → Print String("Defend: Dodged") → return Dodged
   return None
   ```

   > `bIsDodging` 不参与判断：无敌窗口由 `bInvincible` 表达，动作期由 `bIsDodging` 表达，两者分开才不会在「动作提前结束但无敌还在」时判错。

4. `AC_EnemyAttack.DoAttackHit` 的 Result 分支补上：`Dodged → Print String("Dodged")`（不结算伤害）。

5. 同一次挥击去重：`DoAttackHit` 里**先**把目标加进 `HitTargetsThisSwing`（`Array Contains` 判过之后、`ResolveDefense` 之前），再做拦截与结算——这样同一挥击在无敌结束后不会再打一次。

### 16.1 判定落点：先确认哪张图真的被执行

调用链是固定的：`AC_EnemyAttack.DoAttackHit` → `BPFL_Defense.ResolveDefense(Target = Player)` → `Does Implement Interface(Player, BPI_CombatComponent)` 成立 → 调用**被命中对象本身**（玩家角色）的 `TryDefendAttack` 接口函数 → 玩家 BP 的转发壳 → `AC_Combat.TryDefendAttack`。**判定体全部写在 `AC_Combat.TryDefendAttack`（53 节点）里**；玩家 BP 只做转发，不在它里面写判定。

**A. 玩家 BP 侧：4 节点转发壳**

打开玩家 BP（`/Game/Blueprints/SandboxCharacter_CMC`）→ 接口 → `BPI_CombatComponent` → 函数 `TryDefendAttack`，图里只留 4 个节点：

1. `函数入口（TryDefendAttack）` 的 `then` → 调 `AC_Combat → TryDefendAttack`（把组件从「组件」面板拖进图，`Target` 接组件）。
2. 把入口的 `Attacker`、`bAttackParryable` 两个参数分别接到该调用的同名输入引脚。
3. 该调用的返回值（`Chance`）→ `返回节点` 的 `DefenseResult`。
4. 图里其它节点（`Print String`、自定义 `Branch`、`Literal enum`）全部删掉——判定不在这张图里。

**B. `AC_Combat` 侧：`bInvincible` 分支接在成功链之前**

`AC_Combat.TryDefendAttack` 的判定顺序固定为「死亡 → 无敌 → 招架窗口 → 角度 → 成功链」，无敌这一段对应：

1. 第一个 `Branch`（`Condition` = `Get bIsDead`）的 `False` → 第二个 `Branch`（`Condition` = 自己组件的 `Get bInvincible`）。
2. 第二个 `Branch` 的 `True` → `Print String`（`Defend: Dodged`）→ 一个 `返回节点`，`DefenseResult` ← `Literal enum E_DefenseResult` 选 **`Dodged`**。
3. 第二个 `Branch` 的 `False` → 继续后面的招架判定链（`bAttackParryable AND bParryWindowActive` → 角度 → 成功链）。
4. 放多个 `返回节点` 是允许的（本项目就是 5 个：`Parried` / `Dodged` / 三个 `None` 出口）；若坚持只用一个，就用 `Select` 在数据侧汇合两条枚举，**不要两条线都怼到同一个数据引脚**。

**怎么算接对了**：玩家 BP 的 `TryDefendAttack` 图**只有 4 个节点**（入口 / 调用 `AC_Combat.TryDefendAttack` / 两个参数连线 / 返回）；`AC_Combat.TryDefendAttack` 编译无红叉，5 个返回节点的 `DefenseResult` 都有连线（不是默认 `NewEnumerator0`）。

### 16.2 `ResolveDefense` 的返回值必须接回

`ResolveDefense` 里 `DoesImplementInterface` 为 true 之后那个 `TryDefendAttack` 接口调用节点，**`then` 执行引脚与 `DefenseResult` 数据引脚都必须接**；图里每个 `FunctionResult` 的 `DefenseResult` 也不能留默认 `NewEnumerator0`。

1. 打开 `/Game/Combo_Demo/BP/Library/BPFL_Defense` 的 `ResolveDefense` 图，找到 `TryDefendAttack`（接口调用）节点。
2. 在它右边加一个 **Return Node**：`then`（调用后）→ Return 的 `execute`；节点的 `DefenseResult`（输出）→ Return 的 `DefenseResult`。
3. 保存、`Compile`。若编辑器不允许再加第三个 Return：用 `Select`（枚举，条件用 `Does Implement Interface` 的结果）把接口返回值与字面量 `None` 二选一，再汇入现有 Return。
4. PIE 验收：闪避中挨刀 → 敌人打印 `BeDodged`、玩家不掉血不硬直；不闪避挨刀 → 正常掉血（证明没有把伤害整体关掉）。

> 规则：**函数返回值也是一种状态，调用方必须有人接**。

> ⚠️ 本步易错，见踩坑册 K069

### 16.3 受击恢复必须复位 `bIsHitStunned`

`CanStartDodge` 含 `NOT bIsHitStunned`。`HandlePlayerHit` 里 `Set bIsHitStunned = true`，复位点必须在 `AC_Combat` → EventGraph → `OnPlayerHitRecover`：在 `if bIsDead` 的 **else** 分支里（`CallSetMovementEnabled(true)` 前后都行）加 `Set bIsHitStunned = false`。

- 不要在 `bIsDead` 为 true 时复位（死亡态交给清理流程）。
- 可选：`HandlePlayerDeath` 里也清一次。
- 漏了这一步的表现：挨一次打后所有闪避都被门禁挡掉，看起来像「一直处于受击状态」。

> ⚠️ 本步易错，见踩坑册 K043

**为什么**

- 无敌是「本次攻击不生效」，不是「回血」。事后回血会照样触发受击/死亡/奖励事件。
- 去重放在拦截之前：A03 要求「同一挥击跨越窗口结束不补伤害」，靠的是攻击侧记录「这一刀已经问过这个目标了」。

**自检**（A03）：

- 让敌人出招，在刀即将命中的窗口内闪避 → 日志依次出现 `Defend: Dodged`（玩家侧）与 `BeDodged`（敌人侧），**玩家血量不动、不播受击蒙太奇**。
- 不闪避直接挨刀 → 没有 `Defend: Dodged`，正常掉血 + 受击。
- 等闪避动作完全结束（`EndInvincible` 到点）再挨刀 → 正常受伤（证明 `bInvincible` 被复位）。
- 故意让无敌在刀命中前结束（把 `combat.dodge.iframe` 调很小）→ 仍会被这一刀打中一次，但**不会**因为同一刀跨帧再打一次。
- 挨一次打、等受击恢复后再闪避 → 能闪（§16.3）；连续闪第二次 → 能闪（§17.3）。

**注意**：无敌计时器在受击/死亡时没清 → 死后还无敌（第 18 课）；把去重放在结算之后 → 一刀多帧多次结算；若「怎么砍都不掉血」：查 `CombatGraph` 里 `EndInvincible` 事件是否还在、`Set Timer by Event` 的 `Event` 是否接的 `Create Event(EndInvincible)`、时长是否用的 `Duration`（不是 0）。

**预计**：0.8h。

## 第 17 课 M2-4 连闪与恢复

**状态**：✅ 已完成并验收通过（用户 2026-10-26 PIE，自述 A04 连闪上限 / 0.85s 恢复 / 0.5s 衔接全部通过）。

**目标**：连闪上限读表（`combat.dodge.chain`），超限被拒；恢复（`combat.dodge.cooldown`）后可再闪；衔接（`combat.dodge.chain_window`）生效。

**前置**：第 14–16 课。

**操作**

### 17.1 初始化连闪额度（组件 BeginPlay）

在 **`AC_Combat` 组件自己的 EventGraph**（不是玩家 BP `SandboxCharacter_CMC`）里，找到已有的 `Receive Begin Play`，接在原有逻辑后面补一行：

```
DodgeChainLeft = Int(GetCombatParam(DT_Combat, "combat.dodge.chain"))   // 开局 2 次，不用等恢复
```

> **为什么在组件侧**：`DodgeChainLeft` 是 `AC_Combat` 的变量，`CanStartDodge` / `TryToDodge` / 两个计时器回调也都在组件里；写到玩家 BP 里要先 `Get Component By Class(AC_Combat)` 才能 Set，既绕又可能早于组件 BeginPlay 踩空。玩家 BP 侧不参与这条初始化。不要新建一个叫 `BeginPlay` 的自定义事件来冒充它。

> ⚠️ 本步易错，见踩坑册 K041

### 17.2 恢复计时的开火条件

`TryToDodge()` 里，播蒙太奇之后：

```
// 衔接窗口：动作期 = chain_window，过后可接下一次动作
bIsDodging = true
Clear and Invalidate Timer by Handle(DodgeActionEndTimer)      // 先清旧的，再设新的
Set Timer by Event(CreateEvent(EndDodgeAction), GetCombatParam(DT_Combat, "combat.dodge.chain_window"), false)
     → 返回值存 DodgeActionEndTimer

// 消费一次连闪额度（先判能不能再减，避免减成负数）
DodgeChainLeft = Max(DodgeChainLeft - 1, 0)

// 只有额度用完才开恢复计时：最后一次闪避结束 0.85s 后补满
Branch(DodgeChainLeft > 0)
  True  → 本次结束（还能连闪，不开恢复计时）
  False → bDodgeRecovering = true
          Clear and Invalidate Timer by Handle(DodgeRecoverTimer)
          Set Timer by Event(CreateEvent(OnDodgeRecovered), GetCombatParam(DT_Combat, "combat.dodge.cooldown"), false)
               → 返回值存 DodgeRecoverTimer
```

> **`Set Timer by Event` 的返回值一定要接进 `DodgeRecoverTimer`**（拖 `Return Value` 存句柄）；否则 `Clear and Invalidate Timer` 永远清的是空句柄。顺序必须是「先 `Clear` 旧句柄 → 再 `Set` 新计时器」，反了会把刚设的计时器清掉。

> ⚠️ 本步易错，见踩坑册 K070

### 17.3 事件 `EndDodgeAction`

`bIsDodging = false`。这是闪避动作期的唯一复位点——漏了它，闪第一次之后 `CanStartDodge` 永久 false。

### 17.4 事件 `OnDodgeRecovered`

在**同一张 `AC_Combat` EventGraph** 里新建（或补全）该事件，事件体三件事：

```
Set DodgeChainLeft = Int(GetCombatParam(DT_Combat, "combat.dodge.chain"))   // 补满次数
Set bDodgeRecovering = false
Print String("闪避次数已恢复")
```

> `EndDodgeRecovered` 若存在，并入 `OnDodgeRecovered` 或直接删掉（避免两处改同一状态）。

### 17.5 `CanStartDodge` 的失败原因打印

`CanStartDodge()` 打印失败原因时区分两种：`DodgeChainLeft == 0` → 打印 `Dodge: no chain`；`bIsDodging` → 打印 `Dodge: busy`。

**为什么这么设计**：只用一个 `DodgeChainLeft` 表达「还能闪几次」，恢复计时到期才补满；「在恢复中」就是「次数为 0」，不需要额外的布尔开关。恢复计时只在额度真正用完时开一次，等价于规划里的「最后一次闪避结束后开始恢复计时」。

### 17.6 `TryToDodge` 与恢复计时的完整接法（7 处核对）

| #   | 位置                     | 正确接法                                                                                                                                                                                                                                       |
| --- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | `TryToDodge` 链尾        | 不直接调用 `OnDodgeRecovered` / `EndDodgeRecovered` / `EndInvincible`；恢复与无敌只由计时器触发                                                                                                                                                                |
| 2   | `TryToDodge` 无敌计时器     | `SetTimerByEvent(Event = EndInvincible, Time = combat.dodge.iframe)`（0.3s）→ 返回值存 `DodgeInvincibleTimer`；设完**不要**紧跟 `Clear and Invalidate Timer`                                                                                                 |
| 3   | `TryToDodge` 动作结束      | `GetCombatParam(combat.dodge.chain_window)`（0.5s）→ `SetTimerByEvent(Event = EndDodgeAction)` → 存 `DodgeActionEndTimer`（新建变量，类型 `TimerHandle`）                                                                                                  |
| 4   | `TryToDodge` 递减之后      | `Set DodgeChainLeft = Max(DodgeChainLeft - 1, 0)` → `Branch(DodgeChainLeft > 0)`：**True → 本次结束**（还能连闪）；**False →** `Set bDodgeRecovering = true` → `GetCombatParam(combat.dodge.cooldown)`（0.85s）→ `SetTimerByEvent(Event = OnDodgeRecovered)` → 存 `DodgeRecoverTimer` |
| 5   | 事件 `EndDodgeAction`    | 事件体：`Set bIsDodging = false`（第 18 课在此后接 `CleanupDodge()`）                                                                                                                                                                                  |
| 6   | `OnDodgeRecovered` 事件体 | `Set DodgeChainLeft = Int(GetCombatParam(DT_Combat, "combat.dodge.chain"))` → `Set bDodgeRecovering = false` → `Print String("闪避次数已恢复")`                                                                                                          |
| 7   | `EndDodgeRecovered`    | 并入 `OnDodgeRecovered` 或删掉（避免两处改同一状态）                                                                                                                                                                                                        |

> 已经接对、不要动的部分：`DodgeMoveStopTimer` ← `Create Event(DodgeMoveStop)`（`Time = combat.dodge.iframe`）、`DodgeRecoverTimer` ← `Create Event(OnDodgeRecovered)` 这两个委托目标；`DodgeChainLeft` 的 `Max(X-1, 0)`。

**自检**（A04）：

- 连按闪避 3 次 → 第 3 次出现 `Dodge: no chain` 日志。
- 停手约 0.85s 后再按 → 又能闪 2 次，且日志出现「闪避次数已恢复」。
- 每次闪避间隔小于衔接窗口（0.5s）时按不出来。
- 闪避全程挨刀：敌人打印 `BeDodged`、玩家不掉血不硬直（验证 `bInvincible` 没被秒关）。

**注意**：次数在「闪避成功」和「闪避尝试」两处各减一次 → 少一半次数；恢复计时器不重启 → 连闪中途被提前重置；用 Tick 计时 → 帧率不同结果不同。

## 第 18 课 M2-5 退出清理与中断

**目标**：任何异常退出路径都不留无敌、计时器、锁输入、滑行速度。

**前置**：第 14–17 课。

**操作**

1. `AC_Combat` 新建函数 `CleanupDodge()`：用 `Clear and Invalidate Timer by Handle` 清 `DodgeInvincibleTimer`、`DodgeActionEndTimer`、`DodgeMoveStopTimer`；`bInvincible=false`；`bIsDodging=false`；`Launch Character(Target=OwningCharacter, Velocity=(0,0,0), bXYOverride=true, bZOverride=false)`。

   > **不要在这里清 `DodgeRecoverTimer`、也不要在这里复位 `bDodgeRecovering`**。`DodgeRecoverTimer` 是连闪额度（`DodgeChainLeft`）的**唯一**补满入口，清掉后额度停在 0、`CanStartDodge` 的 `DodgeChainLeft>0` 恒假，表现为「取消一次之后闪避永久不可用」。它只在死亡清理里清（人死了不需要恢复）。
   > 清理顺序建议：先清计时器 → 再清布尔 → 最后停速度（先后无所谓，但三个都要有；只清计时器会让 `bIsDodging` 卡住）。

2. 在以下位置调用它：
   - 闪避蒙太奇结束 / 被打断（**函数节点看 §18.1**；异步 `Play Montage` 节点才是 `On Completed` / `On Interrupted` 两个都接，不接会卡在 `bIsDodging`）；
   - `HandlePlayerHit()`（受击打断闪避，且受击本身已被拦截则不会走这里）；
   - `HandlePlayerDeath()`；
   - `Play Anim Montage` 返回 0（播放失败，打印日志并清理）。

3. 蓄力互斥：在 `Branch(CanStartDodge)` 之前加 `if bIsCharging → 调 CancelCharge()`（它已经清了计时器、停了 Montage、清了蓄力状态），再进闪避。

4. 同样给招架/反击准备清理函数（下一课用），死亡清理里统一调用 `CleanupAll`（闪避 + 招架 + 反击 + `HitStunTimer`）。

### 18.1 函数节点（`Play Anim Montage`）怎么收口

`Play Anim Montage` 是普通函数，播完不会回调；异步 `Play Montage` 节点才有 `On Completed` / `On Interrupted`。函数派用下面两种方式之一（推荐 ①，第 17 课已有计时器可直接复用）：

**① 复用第 17 课的计时器（最省事，本项目默认）**

- `EndDodgeAction` 事件里已经置 `bIsDodging=false`，在它后面接 `CleanupDodge()` ——「闪避动作结束」就以这个 `combat.dodge.chain_window`（0.5s）收口点为准。
- 被打断的路径由显式调用点兜住：`HandlePlayerHit()`（受击）、`HandlePlayerDeath()`；攻击/蓄力入口的互斥见 Step 3。
- 优点：零新节点；缺点：清理时点由计时器决定，不是蒙太奇真实长度。

**② 绑 AnimInstance 的蒙太奇结束委托（最接近异步节点语义）**

- `Get Anim Instance`（玩家 Character → `Get Mesh` → `Get Anim Instance`）→ `Bind Event to On Montage Ended`。引擎侧依据：`UAnimInstance::OnMontageEnded` 是 `UPROPERTY(BlueprintAssignable)`，见 `Runtime/Engine/Classes/Animation/AnimInstance.h:756`。
- 回调节点参数：`Montage`（UAnimMontage）与 `bInterrupted`（bool）。正常播完 = false；被顶掉 / `Montage Stop` / 受击打断 = true。
- 回调里：`Branch(Get bIsDodging)`（或比较 `Montage == CurrentDodgeMontage`）→ `CleanupDodge()`。**要过滤**，否则攻击/受击蒙太奇结束也会清掉闪避状态。
- 绑定放在 `AC_Combat` 的 `ReceiveBeginPlay`（`Get Owner → Get Mesh → Get Anim Instance → Bind Event to On Montage Ended`）；Character 销毁时 AnimInstance 一起销毁，无需解绑。
- 优点：时点精确；缺点：多一个委托概念、要记得过滤。

**两种播放节点在本项目里的分布**（别以为自己接错了）：

- 玩家 `SandboxCharacter_CMC`：闪避/攻击/受击蒙太奇全部是 `Play Anim Montage` 函数，图里没有任何异步 `Play Montage` 节点。
- `AC_Combat`：只有「武器装备/卸下」两处用了异步 `Play Montage`（`EventGraph.K2Node_PlayMontage_0/_1`），所以那里确实有 `On Completed` 等引脚。
- `AC_EnemyAttack`：攻击蒙太奇用的是异步 `Play Montage`（`EventGraph.K2Node_PlayMontage_0`），所以第 12 课的 `On Completed / On Interrupted → bAttacking=false` 对敌人成立。

> ⚠️ 本步易错，见踩坑册 K068

**自检**（A11 的一部分）：蓄力中按闪避 → 蓄力取消且后续松开右键**不**会补一记重击；闪避中被打中（窗口外）→ 之后能正常移动、能再闪；闪避中死亡 → 输入与移动彻底关闭，10 秒后再没有「恢复」发生。

**注意**：只清计时器不清标志位（`bInvincible` 残留）；函数节点上没有 `On Interrupted` 可接，于是没人调 `CleanupDodge`（被打断就卡在 `bIsDodging`，见 §18.1）；死亡后旧计时器回调把输入恢复（清 `DodgeRecoverTimer` 只在死亡清理里做）。

## 第 20 课 M3-2 招架判定

**目标**：只有「窗口内 + 正面 ±60° + 可招架攻击」才成功，四种非法条件全部失败。

**前置**：第 19 课；第 13 课拦截插槽。

**操作**：① `AC_Combat.TryDefendAttack` 补成四道门（死 → 无敌 → 资格 → 角度，§20.2）；② 招架动作分左右手的来源提前登记（§20.3）；③ `TryParry` 的执行链与 `Select`（§20.4）；④ 两层转发器逐参数接通（§20.5）；⑤ PIE 验收四种非法条件（§20.6）。

### 20.1 判定数学：WorldDir、Dot 与 Cos 阈值

- **`WorldDir` = `Normalize(Attacker位置 − OwningCharacter位置)`**：世界空间里「从自己指向攻击者」的单位向量。先 `Subtract` 得位移，再 `Normalize` 把长度抹成 1 —— 不归一化的话敌人越远这个向量越大，点积数值被距离污染，判定就不再只跟角度有关。
- **前向投影**：`Dot Product`（`A` = `WorldDir`，`B` = `OwningCharacter → Get Actor Forward Vector`）。这就是「换到本地空间后取 X 分量」的结果，但少一层 `Inverse Transform Direction`（它要 `T` 接 `Get Actor Transform`，接成 `Rotator` 直接编不过）。
- **`Dot` 数值 = `cos(夹角)`**，范围 [-1, 1]：`1` 正前、`0` 正侧、`-1` 正后。`cos` 在 0–180° 上单调递减，所以「`Dot >= Cos(半角)`」与「夹角 ≤ 半角」完全等价，不用真的 `Acos`，也不碰 0/360 跨界与精度问题。
- **左右手同理**：`Dot(WorldDir, OwningCharacter → Get Actor Right Vector)` > 0 = 威胁在右手边（§20.3 用它决定播哪只手）。
- **数值例**：`combat.parry.front_angle` = 60（**半角**）→ 阈值 `cos60°` = 0.5。正前 → `Dot` = 1 ✅；偏 45° → 0.707 ✅；正侧 90° → 0 ❌；背后 → -1 ❌。

**为什么**：点积比「算角度扇区」稳（不处理 0/360 跨界）；只挡正面意味着游戏想让你面向威胁（规划 §2 范围规则）；`Attack Parryable` 由攻击方传入，把「明确标记可招架」这条规则落在攻击定义上，而不是靠伤害类型猜。

### 20.2 `AC_Combat.TryDefendAttack` 逐节点接法

**改哪张图**：`/Game/Combo_Demo/BP/Components/AC_Combat` 的 `TryDefendAttack` 函数图。玩家 BP `SandboxCharacter_CMC` 那张只是转发器，改法见 §20.5。

**目标形状**（四条 exec 主干串起来，不是四颗 `Branch` 并排）：

```
函数入口
 → ① Branch(bIsDead)
      T → Return(None)
      F → ② Branch(bInvincible)
            T → Print String("Defend: Dodged") → Return(Dodged)
            F → ③ Branch( AND(bAttackParryable, bParryWindowActive) )
                  T → ④ Branch( >= (A = Dot, B = DegCos) )
                        T → Print String("Defend: Parried")
                            → Set bParrySucceededThisAttempt = true
                            → 〔第 21 课 8 段成功链，插在这里〕
                            → Return(Parried)
                        F → Return(None)
                  F → Return(None)
```

| Step | 怎么接 |
| --- | --- |
| 1 死亡门 | `bIsDead`(Get) → `Branch`；函数入口 exec 接它。**T** → 新建 `Return Node`，`Defense Result` 接 `Literal enum E_DefenseResult` = `None`（这颗要新开，别和后面的共用） |
| 2 无敌门 | 死亡门 **F** → `Branch(bInvincible)`；**T** → `Print String`（`Defend: Dodged`）→ `Return Node(Dodged)` |
| 3 资格门 | `Branch(bInvincible)` 的 **F** → 新 `Branch`，`Condition` ← `AND Boolean`：`A` = `bParryWindowActive`(Get)、`B` = 函数入口的 **`Attack Parryable`** 引脚；**F** → `Return Node`（`None`） |
| 5 成功分支 | 角度门 **T** → `Print String`（`In String` = `Defend: Parried`、`Text Color` = `(R=1.0, G=0.35, B=0.0, A=1)`、`Duration` = `2.0`）→ `Set bParrySucceededThisAttempt = true` → 新建 `Return Node`（`Defense Result` = **`Parried`**） |
| 6 默认 `None` | 死亡门 T、资格门 F、角度门 F 各一颗 `Return Node`，`Defense Result` 接 `Literal enum E_DefenseResult` = `None` |

**Step 4｜角度门（先方向、再点积、最后阈值）**

1. **WorldDir**：`Attacker → Get Actor Location`、`OwningCharacter → Get Actor Location` → `Subtract`（**A = Attacker 的位置，B = 自己的位置**，反了就是「从敌人指向你」）→ `Normalize`（普通版，`Tolerance` = `0.0001`；不要 `Normalize In Place`）。
2. **Dot**：`Dot Product`（`A` = `Normalize.Return Value`，`B` = `OwningCharacter → Get Actor Forward Vector`）。
3. **Cos 阈值**：`Get Combat Param`（`Table` = `DT_Combat`，`Key` = `combat.parry.front_angle`）→ `Degrees To Radians` → `Cos`。
4. 资格门的 **T** → 新建 `Branch`，`Condition` ← `>=`（float，**A = Dot，B = Cos 结果**；顺序反了会永远不通过）。

> `Set bParrySucceededThisAttempt = true` 是**全资产唯一的写点**。漏了它：`EndParryWindow` 永远走冷路径、第 21 课永远拿不到 `bCounterReady`。
>
> ⚠️ 易错，见踩坑册 K074 / K075（`>=` 两脚接反、成功链没接 `Return`）。

### 20.3 招架动画怎么分左右：威胁提前登记

**难点在时序**：`TryDefendAttack` 是**敌人的刀已经打到你身上那一刻**才被调用的，而蒙太奇在**按下侧键那一刻**就必须开始播，两者隔着最长 0.22s。所以「用接口参数 `Attacker` 决定初始播哪只手」在时序上做不到。方向来源必须**提前登记**：让敌人在**起手时**把自己的身份告诉玩家组件。

**Step 0｜资产先备齐**：`/Game/Combo_Demo/Animation/Montage/Parry/` 下现有 `AM_Parry_L`（单 Section `Default`、序列 `AS_Parry_L`、含 `ANS_InputDisabled` 0–0.417s）；右手只有序列 `AS_Parry_R_Seq`。二选一：

- **方案 A（荐）**：复制 `AM_Parry_L` 为 `AM_Parry_R`，把 `DefaultSlot` 段里的序列换成 `AS_Parry_R_Seq`，`ANS_InputDisabled` 保留并按新序列长度重拖。
- **方案 B（不加资产）**：把 `AM_Parry_L` 做成双 Section —— `Default`（左）与 `Right`（右），两段分别用 `AS_Parry_L_Seq` / `AS_Parry_R_Seq`；`Play Anim Montage` 的 `Start Section Name` 接 `Select`（`"Default"` / `"Right"`）。

**Step 1｜`AC_Combat` 加两个只负责「方向」的状态**：`ThreatActor`（`Actor`，默认 `None`；只决定播哪只手，**不参与任何判定**）、`bParryThreatRight`（`bool`，威胁是否在右手边）。

**Step 2｜`AC_Combat` 新建函数 `NotifyIncomingAttack(Attacker: Actor)`**

| 节点 | 引脚怎么接 |
| --- | --- |
| `Set ThreatActor` | 值 ← 函数入口 `Attacker` |
| `Get Actor Location`（①/②） | ①`Target` ← 函数入口 `Attacker`；②`Target` ← `OwningCharacter` |
| `Subtract`（Vector） | `A` ← ①的 `Return Value`；`B` ← ②的 `Return Value`（**A 必须是威胁、B 是自己**） |
| `Normalize`（Vector） | `A` ← `Subtract.Return Value`；`Tolerance` = `0.0001` |
| `Dot`（Vector） | `A` ← `Normalize.Return Value`；`B` ← `OwningCharacter → Get Actor Right Vector` |
| `>`（float）→ `Set bParryThreatRight` | `A` ← `Dot.Return Value`；`B` = `0`（默认值）；`Set` 的值 ← `>` 的布尔输出 |

> 用 `>` 而不是 `>=`：正侧方（`Dot` 恰好 0）按左手播，避免每次站位不同左右乱跳。

**Step 3｜敌人在起手时登记**：`AC_EnemyAttack` 的 `AttackLoop` 里，`Set bAttacking = true` 之后、`Play Montage` 之前插一句 `Player → Get Component By Class(AC_Combat) → Is Valid → NotifyIncomingAttack(OwningNPC)`。放在起手处（而不是 `DoAttackHit`）才能覆盖整整 0.22s 窗口。

**Step 4｜`TryParry` 里用类型化 `Select` 选蒙太奇**：`Index` ← `bParryThreatRight`(Get)；`Option 0` = `AM_Parry_L`；`Option 1` = `AM_Parry_R`；`Return Value` → `Play Anim Montage` 的 `Montage To Play`。两端都是蒙太奇资产，通配符自动收敛成 `AnimMontage`，不需要 `Cast`。

**Step 5｜复位**：`EndParryWindow` 末尾 `Set ThreatActor = None`；`HandlePlayerDeath` 里也清一次。**不要**放进 `CleanupDodge`（那是闪避的清理）。

**Step 6｜左右反了怎么改（别改数学）**：`Dot(WorldDir, RightVector) > 0` 表示「威胁在你**右手边**」；「右手边来刀用哪只手格挡」是动作设计取舍，不是公式问题。PIE 里看一次，明显反了就把 `Select` 的 `Option 0` / `Option 1` 对调。

### 20.4 `TryParry` 逐节点接法（一条链，不用 `Sequence`）

```
函数入口
 → Branch(bWeaponInHand)                      False → 结束
 → Branch( OR 五项禁止 )                       True  → 结束
 → Branch(bParryWindowActive)                  True  → 结束（不刷新）
 → CleanupDodge()
 → Set bParrySucceededThisAttempt = false
 → Set bIsParrying = true
 → Set bParryWindowActive = true
 → Play Anim Montage(Target = OwningCharacter, Montage To Play ← Select.Return Value,
                     Play Rate = 1.0, Start Section Name 留空)
 → Get Combat Param(DT_Combat, Key = combat.parry.window)
     → Set Timer by Event(Delegate = CreateEvent(EndParryWindow), bLooping 不勾) → Set ParryWindowTimer
 → Set Timer by Event(Delegate = CreateEvent(EndParryAction), Time = 1.1, bLooping 不勾) → Set ParryActionWindow
```

- 五项禁止 = `bIsDead`、`bIsHitStunned`、`bIsParrying`、`bWeaponBusy`、`bParryCooldown`，OR 后接 `Branch.Condition`，**True = 禁止 = 结束**。
- 两颗计时器都存进 `Timer Handle` 变量，供清理用（窗口 0.22s、动作收尾 1.1s）；不加 `Sequence`、不加 `Cast To Actor`、不在这里接 `CleanupParry`（它会当场清掉刚建的窗口计时器）。

**接完顺序自检**：① 敌人起手 → `NotifyIncomingAttack` 写入 `ThreatActor` 与 `bParryThreatRight`；② 按招架 → 守卫 → `CleanupDodge` → 置 `bIsParrying` / `bParryWindowActive` → 按 `bParryThreatRight` 选左/右手 → 播蒙太奇 → 0.22s 窗口、1.1s 动作收尾；③ 敌刀命中 → `ResolveDefense` → `TryDefendAttack` 四道门 → `Parried` + `bParrySucceededThisAttempt = true`；④ 0.22s 到 → `EndParryWindow`：成功只关窗、失败关窗 + 0.45s 冷却；⑤ 1.1s 到 → `EndParryAction`：可再招架。

### 20.5 两层转发器必须逐参数接通

招架判定要穿过**两个**转发器才落到 `AC_Combat.TryDefendAttack`，任何一跳漏一个引脚，表现都只是「某个条件恒假」，编译不会报错。

**① `BPFL_Defense.ResolveDefense`**

| 节点 / 引脚 | 接到哪里 |
| --- | --- |
| `Does Implement Interface`（`Target`，接口 `BPI_CombatComponent`） | **False** → `Return Node`（`Defense Result` = `None`，不动） |
| 接口消息节点（图上标 `Message`）的 `Attacker` | ← 函数入口的 `Attacker` 输出 |
| 接口消息节点的 `Attack Parryable` | ← 函数入口的 `bAttackParryable` |
| 接口消息节点的 `then` | → `Return Node` 的 `execute` |
| 接口消息节点的 `DefenseResult` | → `Return Node` 的 `Defense Result` |

> `Attacker` 与 `Target` 是两个不同对象：`Target` 是被打的人，`Attacker` 是打人的人。把 `Target` 的重路由节点（小圆点）接到接口消息的 `Attacker` 上，传进去的就是**玩家自己**，方向向量变成 0（见踩坑册 K081）。

**② 玩家 BP `SandboxCharacter_CMC.TryDefendAttack`（接口实现）**：从**函数入口节点**拉线，接到对 `AC_Combat.TryDefendAttack` 的调用上——`Attacker` → `Attacker`、`Attack Parryable` → `Attack Parryable`，调用的 `Defense Result` → 本函数 `Return Node.Defense Result`。

> ⚠️ 易错，见踩坑册 K080（漏接 `Attack Parryable`，改敌人默认值也没用）。转发器必须逐参数自检一遍：漏接一个输入参数编译不报错，运行期只表现为「某个条件恒假」。

### 21.3 Part A：`TryDefendAttack` 成功链补 8 段

**A0 先断一根线再连**：`Set bParrySucceededThisAttempt` 的 `then` 目前直连 `Return Node`（`Defense Result` = `Parried`）的 `execute`，先断开；新链从这颗 `then` 出，链尾接回 `Return Node.execute`。（不断开会变成两条执行线同时往下走。）

| 段 | 节点 | 引脚怎么接 |
| --- | --- | --- |
| A1 | `Get OwningCharacter` → `Get Mesh` → `Get Anim Instance` → `Montage Stop`（**Target = Anim Instance** 那个） | `Target` 依次串接；`In Blend Out Time` = `0.1`；`Montage` = **留空** |
| A2 | `CleanupParry`（已有函数，直接拖进图）→ `Set ThreatActor = None`（建议加） | `execute` ← A1 的 `then`；后一句 ← 上一步 `then` |
| A3 | `Set CounterTarget` | 值 ← **函数入口的 `Attacker`**（类型就是 `Actor`，可直连） |
| A4 | `Set bCounterReady` = `true` | `execute` ← A3 的 `then` |
| A5 | `Clear and Invalidate Timer by Handle` | `Handle` ← `Get CounterWindowTimer`（先清旧，句柄只留最新） |
| A6 | `Get Combat Param` → `Set Timer by Event` → `Set CounterWindowTimer` | `Table` 默认 `DT_Combat`（别动）、`Key` = `combat.parry_counter.window`；`Delegate` ← `Create Event`（下拉选 `EndCounterWindow`）；`bLooping` 不勾；句柄存 `CounterWindowTimer` |
| A7 | `Get Display Name` → `Append` → `Print String` | `Append.A` = `"ParrySuccess: "`、`B` ← `Get Display Name`；`Duration` = `2.0`；`then` → `Return Node`（`Defense Result` = `Parried`）的 `execute` |

**A8 顺序总表（一条链，顺序别乱）**

```
Set bParrySucceededThisAttempt = true        ← 图上已有
  → Get OwningCharacter → Get Mesh → Get Anim Instance → Montage Stop(0.1, Montage 空)
  → CleanupParry()
  → Set ThreatActor = None                   ← 建议加
  → Set CounterTarget = Attacker
  → Set bCounterReady = true
  → Clear CounterWindowTimer                 ← 先清旧
  → GetCombatParam("combat.parry_counter.window") → SetTimerByEvent(EndCounterWindow, bLooping=false)
  → Set CounterWindowTimer = Return Value
  → Get Display Name(Attacker) → Append("ParrySuccess: ") → Print String
  → Return Node (Defense Result = Parried)
```

- `Montage` 留空的理由：`TryParry` 会按来袭方向播 `AM_Parry_L` 或 `AM_Parry_R`，留空 = 停当前那条；填死 `AM_Parry_L` 则在播右手动作时停不掉。
- `bParrySucceededThisAttempt` 的**权威复位点在 `TryParry` 的动作分支起点**（§19 操作 1），这里不补 `Set false`（理由见 §21.4 B4）。
- **`CleanupParry()` 必须排在 `Set bCounterReady = true` 之前**：`CleanupParry` 现在含 Counter 清理（11 节点，见 §21.8 与踩坑册 K090），它会把 `bCounterReady` 与 `CounterWindowTimer` 一起清掉；放在「发资格」之后会同帧清掉自己刚发的资格。函数图里**拖不进** EventGraph 的 Custom Event 节点，A6 的 `Delegate` 一律用 `Create Event`（踩坑册 K110）。

### 21.4 Part B：`EndCounterWindow` 事件 + 死亡清理 + `CleanupParry` 的三个副作用

**B1 建事件**：`AC_Combat` → EventGraph 空白处右键 → **Add Custom Event** → 改名 `EndCounterWindow`，无参。

**B2 事件体（2 节点）**：`EndCounterWindow` 的 exec → `Set bCounterReady = false` → `Set CounterTarget` = 空。事件体里**不要**再 `Clear and Invalidate(CounterWindowTimer)`：这个事件就是那个计时器的回调，自己清自己没意义；真正要清的是「再次成功时」（A5）和「死亡时」（B3）。

**B3 死亡清理**（加进第 18 课 `HandlePlayerDeath` / `CleanupAll` 的清单）：`Clear and Invalidate Timer by Handle`（`Handle` ← `CounterWindowTimer`）、`Set bCounterReady = false`。两句必须挂进 `CleanupAll` 现有执行链，不要做成孤立节点。`CounterTarget` 死亡时**不清**（第 22 课定：残留无实际影响，已登记进附录 E 的 E.3 表）。

**B4 `CleanupParry()` 的三个副作用（改它之前必须知道）**：`CleanupParry` 实测顺序是清 `ParryWindowTimer` → 清 `ParryCooldownTimer` → `Set bIsParrying = false` → `Set bParryWindowActive = false`，另含 Counter 清理（11 节点）。在 A2 里调它之后：

1. `EndParryWindow` 不再触发 → 这一次**不会**进入 0.45s 冷却。这正是「招架成功不惩罚」想要的效果，但它来自副作用而不是显式设计——将来改 `CleanupParry` 的人要知道会动到什么。
2. `EndParryWindow` 原本也负责复位 `bParrySucceededThisAttempt`。**不要**在 `CleanupParry()` 之后补 `Set false`：那样冷路径会恒读到 false，招架成功也进 0.45s 冷却，「连续抵御多段攻击」失效。权威复位点统一放 `TryParry` 的动作分支起点（§19），`EndParryWindow` 冷路径保留一次复位。
3. `EndParryWindow` 还负责 `Set ThreatActor = None`（§20.3 Step 5）→ 现在不清 → 下一次按招架的左右手可能沿用上一轮的威胁。`TryParry` 起手有 `NotifyIncomingAttack` 覆盖，只在一小段空隙里可能选错一次；要更稳就把 A2 那颗 `Set ThreatActor = None` 加上。

**B5 不受影响的**：`ParryActionWindow`（1.1s，`TryParry` 里硬编码）照旧到点触发 `EndParryAction`，只做 `Set bIsParrying = false`；本课重复置 false 无害。

### 21.5 Part C：`AC_EnemyAttack.DoAttackHit` 的 `Parried` 分支补 6 段

**C0 插入点**：`Switch on E_DefenseResult` 的 `Parried` 脚 → `Print String("BeParried")`（保持它最前，日志顺序是 `Defend: Parried` → `BeParried` → `ParrySuccess`）→ 从它的 `then` 接新链。

| 段 | 节点 | 引脚怎么接 |
| --- | --- | --- |
| C1 | `Get OwningNPC` → `Get Mesh` → `Get Anim Instance` → `Montage Stop` | `Target` 依次串接；`In Blend Out Time` = `0.1`；`Montage` = **留空** |
| C2 | `Set bAttacking` = `false` | `AttackLoop` 的守卫把 `bAttacking` 当「正在出招」 |

| C4 | `Get Component By Class`（`AC_NPC`）→ `Is Valid` → `ApplyHitReaction` | `Target` ← `OwningNPC`；`Damage Amount` = `0.0`；`Attacker Location` ← `Player → Get Actor Location`；`From Parry` = ✔；`Is Not Valid` 悬空即可 |

| C6 | 事件 `EndParryStun` | `Set bIsParryStunned = false`（可选：前面再串一颗 `Clear and Invalidate(ParryStunTimer)`） |

**C7 顺序总表**

```

  → Print String("BeParried")
  → Get OwningNPC → Get Mesh → Get Anim Instance → Montage Stop(0.1, Montage 空)
  → Set bAttacking = false
  → Set bIsParryStunned = true
  → Get Component By Class(AC_NPC) → Is Valid

  → Clear ParryStunTimer
  → SetTimerByEvent(EndParryStun, Time = Out Stun Duration, bLooping=false)
  → Set ParryStunTimer = Return Value
```

- 为什么 C1 一定要停：下一段 `ApplyHitReaction` 会立刻 `Play Anim Montage` 播受击动作，攻击蒙太奇还占着槽位时会出现「受击动作被攻击动作盖掉」或两个动作来回抢。备选 `Stop Anim Montage`（`Target` = Character，`Anim Montage` = `AttackMontage`，就是 `HandleHitStunned` 里那颗同款），缺点是 blend 时间不可调（引擎默认 0.25s）。
- `DamageAmount = 0`：招架成功不该对敌人造成伤害；配合 §21.6 步骤 1 之后，招架走哪条分支完全由 `bFromParry` 决定。`AttackerLocation` 传玩家位置，`SelectHitMontage` 用它算受击方向。
- **C8 与 `HandleHitStunned` 的关系**：`ApplyHitReaction` 末尾已经会 `Get Component By Class(AC_EnemyAttack) → Is Valid → HandleHitStunned(...)`（置 `bIsHitStunned`、`StopAnimMontage(AttackMontage)`、清 `HitTargetsThisSwing`、起 `HitStunTimer`）。所以一次招架之后 `bIsParryStunned` 与 `bIsHitStunned` **会同时为真**，两条计时器时长同源、同时到期——两个守卫都是 OR 起来的，行为正确，不是 bug。**不要**为了省一个计时器把 `bIsParryStunned` 的复位塞进 `EndHitStun`：时长同源只是巧合，后续很可能让「招架硬直」独立于「普通受击硬直」，耦合起来要拆两遍。
- **C9**：`bNextAttackParryable` 目前只有读、没有写，靠的是 `AC_EnemyAttack` 的 Class Default 手工勾了 `true`（第 20 课留下的临时手段）。别在检查本课时顺手把它改回 false。

### 21.6 Part D：`AC_NPC.ApplyHitReaction` 硬直取数（6 步）

**最终形状**：

```
Entry(DamageAmount, AttackerLocation, bFromParry)
 → Cast(GetOwner) → Character → Set OwningCharacter
 → Branch(bDead)                                         True → Return
 → GetCombatParam(DT_Combat, "combat.enemy.hitstun_large_threshold")
 → GreaterEqual(DamageAmount, 阈值) → Set bLarge
 → Branch(bLarge)
      True  → GetCombatParam("combat.enemy.hitstun_large") → Set StunDuration
      False → Branch(bFromParry)
                 True  → Branch( Not Equal(ParryStunOverrideKey, None) )
                            True  → Get Enemy Param(DT_Enemy, Key = ParryStunOverrideKey) → Set StunDuration（复制颗）
                            False → GetCombatParam("combat.enemy.parry_stun")        → Set StunDuration
                 False → GetCombatParam("combat.enemy.hitstun")                    → Set StunDuration
 → 〔四条支路 exec 在重路由节点汇合〕
 → Max(A = Get Stun Duration, B = 0.1) → Set StunDuration     ← §21.9 下限
 → Apply Effect with Values(GE_HitStun_C, Value = StunDuration)
 → SelectHitMontage(AttackerLocation, bLarge) → Play Anim Montage
 → Get Component By Class(AC_EnemyAttack) → Is Valid
      → HandleHitStunned(Stun Duration ← Get StunDuration)
 → Return Node(Out Stun Duration ← Get StunDuration)
```

**步骤 1｜`bLarge` 只留阈值**：`Set bLarge` 的值输入直接接 `Greater Equal (Double Double)`（`A` = `DamageAmount`，`B` = `combat.enemy.hitstun_large_threshold`）的输出，不要串 `Boolean OR`；`bFromParry` 不参与大硬直判定。

**步骤 2｜让招架分支可达**：第二颗 `Branch` 的 `Condition` 接**函数入口的 `bFromParry`**（不是 `Get bLarge`）。

**步骤 3｜招架分支加「敌人专属覆盖」（变量 1 + 节点 5）**：第二颗 `Branch`（`Condition` = 入口 `bFromParry`）的 **True 就是招架分支**，**False 是 0.35s 普通受击**（步骤 4，不动）。新 `Branch` 只加在 True 侧：

| 新节点 | 引脚怎么接 |
| --- | --- |
| `Get ParryStunOverrideKey` | §21.2 #5 新建的变量（纯 getter，无 exec 引脚） |
| `Not Equal (Name)` | `A` ← `Get ParryStunOverrideKey`；`B` = 空（`None`） |
| `Branch`（新） | `execute` ← 第二颗 `Branch` 的 `True`；`Condition` ← `Not Equal (Name)` |
| `Get Enemy Param`（新） | `execute` ← 新 `Branch` 的 `True`；`Table` 默认是 `DT_Combat`，**必须改成 `DT_Enemy`**；`Key` ← `Get ParryStunOverrideKey`；`Value` → 新 `Set StunDuration` |
| `Set StunDuration`（**复制一颗**） | `execute` ← `Get Enemy Param` 的 `then`；`StunDuration` ← 它的 `Value`；`then` → 汇合点那颗重路由节点 |

接线顺序：① 断开 `第二颗 Branch.True → Get Combat Param(combat.enemy.parry_stun).execute`；② `第二颗 Branch.True` → 新 `Branch.execute`；③ 新 `Branch.False` → 原来那颗 `Get Combat Param(combat.enemy.parry_stun).execute`（复用现成节点）；④ 新 `Branch.True` → 新 `Get Enemy Param.execute`（`Table` 改成 `DT_Enemy`）；⑤ 新 `Get Enemy Param.then` → 新复制的那颗 `Set StunDuration.execute`，`Value` → 它的 `StunDuration`；⑥ 新 `Set StunDuration.then` → 汇合点那颗重路由节点（exec 输入允许多接）。

> **汇合点那颗小圆点**：`Apply Effect with Values` 前面、把三条支路 exec 收成一条的那个小圆圈，编辑器里叫**重路由节点**（节点库搜 `Reroute`，或在一根线上右键选「添加重路由节点」），没有标题，只有一进一出两个引脚。
>
> **为什么必须复制一颗 `Set StunDuration`**：`StunDuration` 是**数据输入**，一条数据线只有一个来源，「两支的 `Value` 都接到同一颗 `Set`」在编辑器里连不出来（后接的会把先接的顶掉）。正确形状是两颗 `Set` 各写各的值，只让 exec 在重路由节点汇合。
>
> `Not Equal (Name)` 在节点库搜 `Not Equal`；若默认是 `Double` 版，右键 `Refresh Node` 或直接搜「Not Equal (Name)」。引擎实现是 `UKismetMathLibrary::NotEqual_NameName`（`Runtime/Engine/Classes/Kismet/KismetMathLibrary.h:3923`）。

**步骤 4｜普通受击分支不动**：`combat.enemy.hitstun`（0.35s）。

**步骤 5｜修 `HandleHitStunned` 的实参**：`Stun Duration` 入参从字面量 `0.8` 改成 `Get StunDuration` 拖过去。

**步骤 6｜把实际时长吐给调用方（本课唯一改函数签名的地方）**：① `ApplyHitReaction` → 点 **Function Entry** → Details → `Outputs` → `+`，名字 `OutStunDuration`，类型 `Float`（double）；② 加输出后函数需要一颗 **Return Node**——带 exec 的函数，输出参数只能靠 `Return Node` 回传。把现有最后一条 `HandleHitStunned` 的 `then` 接 `Return Node.execute`，`Get StunDuration` 拖进 `Return Node.Out Stun Duration`；③ 调用点两处：`BP_MasterNPC` 的 `OnDamageTaken` 里那颗 `ApplyHitReaction`（返回引脚悬空即可）、§21.5 C5 的 `Set Timer by Event.Time`。

> **为什么用输出参数，而不是在敌人侧再读一次键**：时长有三个来源（大硬直 / 通用招架 / 敌人覆盖），敌人侧复读等于把 `ParryStunOverrideKey` 的优先级再实现一遍，两份逻辑迟早分叉。不想改签名的代价是：`BP_MasterNPC` 填了 `ParryStunOverrideKey` 之后敌人硬直仍是 1.8s 而不是影子的 1.5s，A14 会当场抓出来。

### 21.9 硬直时长下限：`Max(StunDuration, 0.1)`（必做）

四条时长分支汇合之后、`Apply Effect with Values` 之前，插一颗 **`Max`**：`A` ← `Get Stun Duration`、`B` 填 `0.1`，`Max.Return Value` 用一颗 `Set StunDuration` 写回（`Apply Effect with Values` 读的就是 `StunDuration`）。再加一颗 `Print String` 打印 `Max` 之后的 `Stun Duration`（验完可删）。

**为什么必须做**：一旦某支取到的秒数是 **0**（表里没这行、键名写错、`bLarge` 分支选错都会导致），`Set Timer by Event` 用 0 秒**不会创建计时器**，负责复位的 `EndParryStun` / `EndHitStun` 永不执行 → `bIsParryStunned` / `bIsHitStunned` 永久 `true` → 敌人再也不出招，而且**不报红字、不崩溃**。

引擎依据：`Runtime/Engine/Private/KismetSystemLibrary.cpp:720-725`（`Time <= 0` 时只打警告、计时器不创建、回调永不执行）；`Runtime/Engine/Public/TimerManager.h:202`（`InRate` 注释写明 "If <= 0.f, clears existing timers."）。两者都不中断脚本，所以流程看起来「正常走完」，只有标志停在 true。

> ⚠️ 易错，见踩坑册 K097（完整根因链与证据）。
>
> 可选加固：覆盖键那次查询改用 `Get Enemy Param` 的 `Found` 输出分叉，`Found=false` 就回退 `combat.enemy.parry_stun`。现网取值正常（1.5s），不做也不影响本课；换敌人、改表名时能再挡一次同类静默失败。

## 第 22 课 M4 招架反击

**目标**：招架成功后按左键发动一次专用反击；资格只发一次、过期失效；挥空不返还；伤害走真实命中。

**前置**：第 21 课。

**操作**：① `AC_Combat` 新建 `TryCounter() -> bool`（§22.1）；② 改造左键输入（§22.2）；③ 核对反击伤害链路与蒙太奇时序（§22.3）；④ 守卫/清理登记（§22.4）；⑤ 编译保存。

**自检**

- A09：成功后按一次左键 → 播反击、扣 `combat.dmg.heavy` 的血；再按左键 → 普通轻击；资格过期后按左键 → 普通轻击。**（✅ 2026-10-29 PIE 已通过：蓝字由 `0/1/2` 变 `28`、反击蒙太奇 3.25s、再按为轻击）**

### 22.1 `TryCounter()`：资格校验与消费

```
if !bCounterReady → return false
// 下面五项是「阻塞项」，成立 = 不能反击
if bIsDead || bIsHitStunned || bIsDodging || bIsParrying || bWeaponBusy → return false
if CounterTarget 无效 → return false
if !bWeaponInHand → return false          // 首版要求武器在手
// 消费资格
bCounterReady = false
Clear Timer(CounterWindowTimer)
面向目标（可选）：Set Actor Rotation(Find Look At Rotation(Owner位置, CounterTarget位置), Yaw)
CurrentAttackDamage = GetCombatParam(DT_Combat, "combat.dmg.heavy")   // 首版临时复用
清空 HitActorsThisWindow
Play Anim Montage(OwningCharacter, AM_Parry_Counter_Attack_L)
CounterTarget = None
return true
```

**第 2 道守卫必须用 `Not Boolean` 包住五项 `OR`** —— 这五项是**阻塞条件**，`OR` 为真表示「不许反击」：

```
OR( bIsDead, bIsHitStunned, bIsDodging, bIsParrying, bWeaponBusy )
  → Not Boolean
  → Branch.Condition
       True  → 下一道门（CounterTarget 是否有效）
       False → FunctionResult(false)
```

- 等价写法：不取反 + `then`/`else` 对调（`OR.ReturnValue` 直连 `Branch.Condition`，`then → FunctionResult(false)`、`else → 下一道门`）。本册统一用 `Not Boolean` 版，与 `TryParry` 的写法一致。
- ⚠️ `Branch.Condition` 引脚默认值是 `true`，**没接线等于永远被挡**。接完必须点开 `Condition` 确认它连的是 `Not Boolean` 的输出。
- ⚠️ 易错，见踩坑册 K085（极性接反：五项全正常时反而 `return false`，反击永远不出，且没有任何报错）。

### 22.2 左键改造：先试反击，再落轻击

输入事件已迁到 `AC_Combat` 的 **`CombatGraph`**（不是 `EventGraph`）。在 `InpActEvt_LeftMouseButton` 事件的最前面插一个 `Branch`：

```
InpActEvt_LeftMouseButton
 → Call TryCounter()
 → Branch( 返回值 )
       True  → CleanupCounter() → 结束（不再走轻击）
       False → CheckBufferedInput → LightAttack（原流程，不动）
```

- `CleanupCounter()` 的**唯一调用点就是这里**：它做「清 `CounterWindowTimer` + `bCounterReady = false` + `CounterTarget = None`」，即资格消费点的收口。
- **不需要蒙太奇结束回调**：本项目的 `TryCounter` 用的是简单版 `Play Anim Montage`（函数派，拿不到 `On Completed` / `On Interrupted`），要硬做还得另加异步节点；资格在消费点已经清干净了。

### 22.3 反击伤害链路与蒙太奇时序

**伤害链路**：`AM_Parry_Counter_Attack_L` 上的 `ANS_WeaponTrace` 会调 `AC_Combat.CallWeaponTrace(true)`，`PlayWeaponTrace` 用 `CurrentAttackDamage` 对命中目标调「对目标造成伤害」（`ApplyDamageToTarget`）。链路已经存在，要保证的只有两件事：① `CurrentAttackDamage` 在**播蒙太奇之前**设好（`combat.dmg.heavy` = 28）；② `HitActorsThisWindow` 在**播蒙太奇之前**清空，否则上一刀记录过的目标会让反击打不中。

**蒙太奇时序**：`AM_Parry_Counter_Attack_L` 的 `ANS_InputDisabled` 通知时长必须是 **0 → 1.3299 秒**，与 `ANS_WeaponTrace` 的 `0.4024 → 1.3299` 一致。0 或过短的话，0.5s 后按左键会插一段轻击把反击打断（见踩坑册 K089）。

**易错点**：资格只清在计时器里、不清在消费时 → 左键连按多次反击（K086）；反击伤害写成新的裸数字 → 数值两处分叉（K088）；`ANS_WeaponTrace` 忘挂 → 动作播了但没伤害（K088）；没清 `HitActorsThisWindow` → 反击打不中（K087）。

### E.2 新增功能时必须做的 5 步（反查法）

1. **登记**：把新状态写进 E.3 状态登记表（在哪置 true、在哪置 false、哪些门必须检查、漏了的表现）。
2. **反查**：拿新状态逐个过 E.1 每一行，问「这个门要不要加它？」要加就当场改，不要留到以后再补。
3. **对称**：玩家侧加的守卫，敌人侧有没有同类入口？敌人加的，玩家侧有没有？两边只在有理由时才不对称，并写明理由。
4. **死亡**：新状态在死亡时怎么清？加进 `CleanupAll` / 敌人死亡清理；并且检查所有「每 N 秒循环」的计时器有没有死亡清理。
5. **回归**：按 E.4 跑一遍，重点三个场景——死后、受击后、闪避中。

### E.4 合并前回归清单（5 条，约 10 分钟）

1. **死后 10 秒**：逐键无反应、敌方不再出招、无残留无敌、无「输入被还回来」。
2. **受击一次后**：能恢复、能再闪、能再攻击（复位类症状）。
3. **闪避中挨刀**：只出现 `Defend: Dodged` + `BeDodged`，不掉血不硬直，且能继续闪。
4. **同一挥击跨窗口**：不补伤害（去重仍在拦截之前）。
5. **Output Log 过滤「尝试读取」= 0 条**（空对象读属性）。

### E.5 维护规则

- E.1 / E.3 是活文档：每次实测更正（如 §16.2、§16.3）都要回来同步一行，并在规划文档的版本记录里写明。
- 单元格只允许 ✔/✘/—；✘ 超过 3 个版本未修，在第 23 课验收里升为阻塞项。
- 新课若引入状态，必须同时提交 E.3 的新行；**没有「置 false 位置」的状态不许合并**。
- 风格沿用全书：Step 分步 + 为什么 + 自检 + 常见错误；每条 ✘ 都要能答出「出错长什么样」。
- **守卫分支必须写清「`then` 走哪边」**：一个 `Branch` 的 `Condition` 到底表达「通行条件」还是「阻塞条件」，**必须在图注释里写出来**，并全区统一——本项目约定：**阻塞条件**（一串 `OR` 拼「死亡 / 硬直 / 闪避 / 招架 / 武器忙」）用「成立 → `Return false`、不成立 → 继续」；`Condition` 引脚默认值是 `true`，接不上的引脚等于恒真 / 恒被挡，改完必须逐根线核对（2026-10-29 新增，见 K124）。
- **计时器时长必须有下限**：任何「从数据表取来的秒数」送进 `Set Timer by Event` / `Set Timer by Function Name` 之前，先 `Max(…, 0.1)`。原因：`Get Data Table Row` 查不到行时 `Value` 返回 **0**，而 0 秒**不会创建计时器**（`Runtime/Engine/Public/TimerManager.h:202`：`InRate` "If <= 0.f, clears existing timers."；`KismetSystemLibrary.cpp:720-725` 会打 `SetTimer passed a negative or zero time` 警告），回调永不执行 → 该计时器负责复位的状态永久卡 `true`。这类故障不崩溃、不报红字，只表现为「某个动作再也做不出来」（见 K123）。
