用法：规划 §4.1 把整轮拆成 29 步，本手册按步给课。**一课只做一件事，做完先过【自检】再开下一课**。每课结构固定：

- 【目标】这一课结束时你手里有什么。
- 【前置】必须先完成什么。
- 【操作】按编号做，节点名用中文（括号内是英文原名）。
- 【为什么】这样接的原因，避免只抄步骤不会改。
- 【自检】怎么证明做对了。
- 【常见翻车】这个项目真会撞的坑。
- 【预计】按每天 4h、边学边做的节奏估。

> **定时器写法约定（全书统一，第 10 课详讲）**：事件的回调（`EndInvincible` / `EndDodgeAction` / `OnDodgeRecovered` / `EndParryWindow` / `EndParryCooldown` / `EndCounterWindow` / `OnPlayerHitRecover`）一律做成**事件图表里的 Custom Event**，且**必须无参**。凡在**函数图**里设 `Set Timer by Event`，`Event` 引脚一律接 **`Create Event`** 节点（下拉选对应回调）——事件图表里的 Custom Event 既不能放进函数图，也不能直接拖到函数图的引脚上。伪代码里统一写作 `SetTimerByEvent(CreateEvent(回调), 时长, false)`。

> **节点命名约定（全书统一）**：`GASCombatBridge` 是引擎 Marketplace 的**二进制插件、带本地化**，蓝图调色板里只显示**中文显示名**，**用 C++ 内部名是搜不到的**。本手册写法统一为「中文显示名（`内部名`）」：
>
> | 调色板里搜这个 | 内部名 | 说明 |
> |---|---|---|
> | 对目标造成伤害 | `ApplyDamageToTarget` | 用一次 GameplayEffect 结算伤害；引脚 `Source` / `Target` / `DamageEffectClass`（默认 `GE_Damage`）/ `DamageAmount` / `Level` / `EffectCauser`（高级） |
> | 施加效果 | `ApplyEffectWithValues` | 施加 GE 并可带 SetByCaller 数值；引脚 `Target` / `Level` / `Instigator` / `EffectCauser` |
> | 按名字设置属性基础值 | `SetAttributeBaseValueByName` | 直接改基础值，**绕过** GE 管线，不触发受击/死亡广播 |
> | 添加属性集 | `AddAttributeSet` | 给 ASC 挂属性集 |
> | 取消所有技能 | `CancelAllAbilities` | 一刀切；死亡收尾用 |

## 第 2 课 五个必须先懂的概念

**目标**：后面每一课的“为什么”都建立在这五个概念上。

### 2.1 传统 InputKey 与 Enhanced Input 现在是并存的

- `AC_Combat` 里的左键轻击、左 Alt 装备、右键蓄力，都是**传统输入事件**（BP 里的 `InputKey` 事件节点，本质是 `PlayerInput` 的按键事件）。
- 玩家 `SandboxCharacter_CMC` 里的移动/奔跑/跳跃走的是**Enhanced Input**（`IA_*` + `/Game/Input/IMC_Sandbox`）。
- 两套可以并存，本项目已经这么跑了。**招架沿用 InputKey（和左键一致），闪避沿用 Enhanced Input（和左 Shift 一致）**，这样改动最小。

### 2.2 Montage / Slot / Notify 是什么关系

- **AnimSequence** 是原始动作；**AnimMontage** 是“能被代码按 Slot 播、能分段、能挂通知”的容器。
- 播放时动画系统把蒙太奇塞进 AnimBP 的 **Slot 节点**；本项目玩家的 Slot 名是 `DefaultSlot`（现有轻击能播就是证据）。**新蒙太奇的 Slot 必须选 `DefaultSlot`**，否则不播。
- **Notify** 是动作时间轴上的标记：`AnimNotify` 是单点，`AnimNotifyState` 是有起止的窗口。项目里 `ANS_InputDisabled` 管“这段时间禁输入”，`ANS_WeaponTrace` 管“这段时间开武器检测”。
- 关键认知：**同样的时长不要存两份**。无敌 0.30s 这种逻辑窗口本轮用 `SetTimer` + DataTable 键表达（规划 §5.5 要求游戏时间计时），Notify 只负责表现层（禁输入、武器检测）。所以本手册**不**新建“无敌 Notify”。

### 2.3 GAS 桥接组件负责血量，伤害不要直接减 Health

- 玩家 Pawn 上已经挂了 `GASCombatBridge` 组件；它负责建 ASC、挂属性集、广播三个事件：`战斗就绪`、`受到伤害时`、`死亡时`。
- 伤害统一走 `GE_Damage`（`Data.Damage` SetByCaller），由属性集在结算时统一处理护盾、夹取、广播受击、判断死亡。**直接减 `Health` 会一次绕过四个功能**。
- 受击动画要绑「受到伤害时」（战斗语义），不要绑属性监听器（数值变化也会触发）。

### 2.4 防御必须在“施加伤害之前”拦截

- 规划 §5.1 定死的顺序：命中候选 → 本次攻击是否已处理 → 闪避判定 → 招架判定 → 普通伤害。
- 所以不是“扣血后再加回来”，而是攻击方在调用 `对目标造成伤害` 之前先问目标一句“这一下你防住了吗”。目标回答 `None / Dodged / Parried`，只有 `None` 才真正结算伤害。
- 这也解释了为什么需要给 `BPI_CombatComponent` 加一个函数——现在的接口只有 4 个转发函数，没有“问一句”的入口。

### 2.5 位移只能有一个驱动

- 闪避有三种做法：动画根运动推动胶囊、用 `LaunchCharacter` 推胶囊、改 `MaxWalkSpeed` 硬走。**混用会位移翻倍或回弹**。
- 本轮选 `LaunchCharacter` 受控位移：距离读表、时长复用无敌时长、水平速度 = 距离 / 时长。前提是**闪避序列本身不要开根运动**（第 3 课核实）。
- 验位移时**同时看模型和胶囊**：模型跑得比胶囊远 = 根运动没关；胶囊走了模型没走 = Slot 没播/蒙太奇空。

**自检**：能解释“为什么招架不需要新建 Notify”“为什么伤害不能事后补血”“为什么闪避序列要关根运动”。

**预计**：0.5h（建议边看第 3 课的核实项边理解）。

## 第 4 课 M0-2 键位与输入方案定稿

**目标**：左 Shift 能“点按闪避、长按奔跑”，鼠标侧键 1 与 V 能触发招架请求（M0 阶段先打日志）。

### 4.1 招架键：直接加传统 InputKey（不改 IMC）

1. 打开 `/Game/Combo_Demo/BP/Components/AC_Combat` → EventGraph。
2. 右键 → `输入 → 键盘事件` → 依次添加三个事件：
   - `Thumb Mouse Button`（鼠标侧键 1，招架主键）
   - `Thumb Mouse Button 2`（侧键 2，留作备用/切枪，本轮不接）
   - `V`（招架备用键）
3. 从 `Pressed` 引脚各接一个 `Print String`（例：`Parry pressed (side 1)`），M3 时把这里换成 `TryParry` 函数调用。
4. 编译保存，PIE 按一下侧键与 V，确认屏幕上有字。

> 为什么不走 Enhanced Input：`AC_Combat` 现有四个输入全是这套，照搬最省事；IMC 也不用动，不会影响移动/奔跑。若以后要统一改 Enhanced Input，再整体迁移。

### 4.2 闪避键：左 Shift 点按/长按（**已定稿方案 A**）

**方案 A（2026-10-20 定稿，按此实施）**：按下立即闪避；按住 ≥0.15s 才进入奔跑。定稿理由：根运动已核实未启用，闪避位移完全由代码驱动、动作可随时打断，0.15s 的“起跑先闪一下”在首版可接受；响应最快，i-frame 起点好对齐。

1. 打开 `SandboxCharacter_CMC` → EventGraph，找到现有的 `IA_Sprint` 节点。
2. 新建变量：`bSprintCommitted`（bool）、`SprintHoldTimer`（Timer Handle）。
3. 把原来 `IA_Sprint` 接出去的“写奔跑输入状态”那段逻辑**整体后移**：新建自定义事件 `OnSprintHoldElapsed`，把那段逻辑接到它后面。
4. 连线：
   ```
   [IA_Sprint] Started ──► [调用 AC_Combat 的 TryToDodge]（M0 先接 Print String "Dodge"）
                       └─► [Set Timer by Event] Function=OnSprintHoldElapsed  Time=0.15  Looping=false
   [OnSprintHoldElapsed] ──► [Set bSprintCommitted = true] ──► 原来的“写奔跑状态”逻辑
   [IA_Sprint] Completed ──► [Clear and Invalidate Timer by Handle] (SprintHoldTimer)
                          └─► [Set bSprintCommitted = false]
   ```
5. 编译保存。PIE：轻点左 Shift → 出现 `Dodge` 日志；按住 → 0.15s 后开始跑；松开停跑。

**方案 B（备选，暂不采用）**：`Started` 起 0.12s 计时不立即闪避；计时到且按住 → 奔跑；`Completed` 且计时未到 → 闪避。代价是闪避滞后 0.12s。保留在这里只为将来手感返工时知道有这条路。

**记录**：附录 F 已填“方案 A”；规划 §0.7 与 §2 已同步。

**自检**：点按/长按两种操作的行为符合你选的方案；招架键两个都有日志；PIE 里移动、跳跃、蹲、轻击、蓄力全部没被破坏。

**常见翻车**：把 `IA_Sprint` 的 `Triggered` 与 `Started` 混用导致长按逻辑重复触发；`Completed` 时没清计时器，下一次点按直接被上一次的计时器带进奔跑。

**排错：点按一次打了两次 `Dodge`**

先看两条日志的时间差，一秒内就能定位：

| 现象 | 原因 | 修复 |
|---|---|---|
| 两条在同一帧/同时出现 | `IA_Sprint` 的 `Started` 与 `Triggered` 都接了 Print（数字动作按下时两个引脚都会触发一次） | 只留 `Started`，删掉 `Triggered` 上的线 |
| 第二条在松开时出现 | Print 同时接在 `Completed` 上 | `Completed` 只留“清计时器 + 复位”，不接闪避 |
| 第二条约晚 0.15s | Print 被复制到了 `OnSprintHoldElapsed` 里 | 那个事件只写 `bSprintCommitted` 和奔跑状态，不打印 Dodge |

验证办法：把文本改成带来源的 `Dodge@Started` / `Dodge@Completed` / `TimerReached`，一次点按看日志组合，问题当场现形。修完必须重跑四种手势（点按、长按、点按后立刻走动、按住中被打断）。

**预计**：0.5–1h（含手感实测）。

|---|---|---|

|---|---|---|
| `AC_Combat` | `bIsDead` / `bIsHitStunned` | bool 变量，默认 false |
| `AC_Combat` | `HitStunTimer` | Timer Handle 变量 |

### 10.1 先看整条链路（别急着连节点）

```
GE_Damage 结算伤害
  └─ 属性集广播「受到伤害」→ GASCombatBridge 转发
       └─ 玩家 BP：GASCombatOnDamageTaken(DamageInstigator, DamageCauser, DamageAmount, RemainingHealth)
            └─ 取 DamageInstigator 位置 → AC_Combat.HandlePlayerHit(DamageAmount, AttackerLocation)
                 ├─ 守卫 bIsDead
                 ├─ 禁移动 / 禁输入
                 ├─ SelectPlayerHitMontage(AttackerLocation) → 播受击蒙太奇
                 └─ SetTimer(combat.player.hitstun) → OnPlayerHitRecover → 恢复移动/输入
```

三条不能破的底线：

1. **不直接改 Health**：扣血只走 `GE_Damage`（`Data.Damage` SetByCaller）。属性集统一处理夹取、广播受击、判断死亡；直接 `SetAttributeBaseValueByName("Health")` 会绕过受击与死亡。
2. **不在受击里判无敌**：无敌由攻击方在结算前调 `TryDefendAttack` 拦截（第 13 课）；受击函数只兜底，不负责“该不该挨打”。
3. **不用 `Delay` 做硬直**：`Delay` 是 latent 节点，死亡/打断后清不掉；硬直必须 `Set Timer by Event` + `Clear and Invalidate Timer by Handle`，和闪避/招架同一口径。

### 10.2 在 `AC_Combat` 建变量与函数

**操作**

1. 打开 `AC_Combat` → 左侧变量面板 `+` 新建三个变量：`bIsDead`（Boolean，默认 false）、`bIsHitStunned`（Boolean，默认 false）、`HitStunTimer`（搜 **Timer Handle**，类型名 `TimerHandle`）。
2. 左侧函数面板 `+` 新建两个函数：`HandlePlayerHit`、`SelectPlayerHitMontage`（后者勾上返回值，类型 `Anim Montage`）。
3. 在 `AC_Combat` 的**事件图表（Event Graph）** 里右键搜 **Add Custom Event**，命名 `OnPlayerHitRecover`（计时器到点后真正执行恢复逻辑的入口，放在事件图表里）。

> **一个必须先讲清的边界（很多人卡在这）**：`OnPlayerHitRecover` 是事件图表里的 Custom Event，而 `Set Timer by Event` 要写在 `HandlePlayerHit` 这个**函数**里——**函数图里不能放 Custom Event，也不能把事件图表里的 Custom Event 直接拖到 `Event` 引脚上**（事件节点只能活在事件图/Ubergraph 里）。函数里要引用它，用 **`Create Event`** 节点：右键搜 **Create Event** → 节点上 `Function` 下拉里选 `OnPlayerHitRecover` → 把它的输出（Event 委托引脚）接到 `Set Timer by Event` 的 `Event` 引脚。`Create Event` 是纯节点，函数图里可以放。
>
> 三条都合法，按场景选：
> 1. **函数内 + `Create Event` 节点**（本课采用，推荐）：状态逻辑留在函数里，好维护；回调由事件图表里的 Custom Event 执行。
> 2. **把 `Set Timer` 挪到事件图表**：比如在玩家 BP 的 `GASCombatOnDamageTakenEvent` 里设计时器，或在 `AC_Combat` 里用某个事件设。代价是逻辑被拆成两处。
> 3. **`Set Timer by Function Name`**：把 `OnPlayerHitRecover` 改成普通函数，传函数名字符串。能跑，但名字是字符串，改函数名/拼错只有运行时才发现，不推荐。
>
> 另外两条硬约束：回调**必须无参**（带参数的回调编译器会报错或定时器不触发）；用 `Create Event` 时节点上的对象（`Self`）默认就是 `AC_Combat` 自己，不需要再赋值。

### 10.3 `HandlePlayerHit` 逐节点

**签名**：`HandlePlayerHit(DamageAmount : double, AttackerLocation : Vector)`，无返回值。

**节点顺序**（按编号接，括号里是右键搜索词）：

1. `Branch`（**Branch**），条件接 `bIsDead` → True 一路接 `Return Node`（**Return Node**）。**先判死再做事**，否则死亡后旧伤害还能播受击。
2. `Clear and Invalidate Timer by Handle`（**Clear and Invalidate Timer by Handle**），Handle 接 `HitStunTimer`。作用：连击时清掉上一个硬直计时器，否则第一刀的计时器会把第二刀提前“恢复”。
3. `Set bIsHitStunned`（**Set bIsHitStunned**）= `true`。
4. **先 `Cast To BPI_CombatComponent`**（**Cast To BPI_CombatComponent**，`Object = OwningCharacter`；`OwningCharacter` 在第 1 步 `Get Owner → Cast To Character` 处已存在）→ 从 `As BPI Combat Component` 拖出 `CallSetMovementEnabled` = `false`。
5. 从**同一个 Cast** 拖出 `CallSetInputEnabled` = `false`。禁止硬直中按攻击/闪避/招架。恢复时在 `OnPlayerHitRecover` 里打开。

> ⚠️ **这两步最容易被“直接调组件自己”坑掉（2026-10-21 实测故障）**：`AC_Combat` 自己也有同名函数（接口实现），但 **`CallSetMovementEnabled` 在组件里是空实现**、`CallSetInputEnabled` 只翻转组件自己的 `InputEnabled` 布尔（`ANS_InputDisabled` 用它，攻击入口并不读它）。所以不写 Target 直接调 `CallSetMovementEnabled(false)` 时，玩家的 `MovementEnabled` 根本没变 → **受击/死亡后仍然能走**。正确写法在 `AC_Combat.StartCharge` 里就有现成样例：`Cast To BPI_CombatComponent(OwningCharacter)` 再调，照抄它。
6. `Play Anim Montage`（**Play Anim Montage**）：`Target = OwningCharacter`、`Anim Montage = SelectPlayerHitMontage(AttackerLocation)`、`InPlayRate = 1.0`、`StartSectionName` 留空。`PlayAnimMontage` 内部默认 `bStopAllMontages=true`，会先停掉正在播的动作，不需要手动 Stop。
7. `Set Timer by Event`（**Set Timer by Event**），四件事：
   - 先拖一个 **`Create Event`** 节点：`Function` 下拉选 `OnPlayerHitRecover`（它来自事件图表；函数图里不能直接拖事件节点进来）。
   - `Event` 引脚 ← `Create Event` 的输出。
   - `Time = GetCombatParam(DT_Combat, "combat.player.hitstun").Value`、`Looping = false`。
   - `Return Value` 接 `HitStunTimer`。
8. （可选，验收前删）`Print String` 打 `DamageAmount` 和 `RemainingHealth`，方便确认 KO 前最后一刀。

```

    if bIsDead: return
    Clear and Invalidate Timer(HitStunTimer)
    bIsHitStunned = true

    (OwningCharacter as BPI_CombatComponent).CallSetInputEnabled(false)
```

**“硬直中再挨一刀”怎么处理（先定，别等联调）**：首版规则 = **每次命中都刷新硬直**（先清计时器再重设、重播受击）。这样连招打你两刀 = 两段硬直连续生效；“一次攻击只产生一次结果”由攻击方的 `HitActorsThisWindow` 去重保证（第 12 课），不靠玩家侧。把这个决定记到附录 F。

### 10.4 `SelectPlayerHitMontage` 逐节点

**签名**：`SelectPlayerHitMontage(AttackerLocation : Vector) → AnimMontage`。

**操作**

1. `Get Actor Transform`（**Get Actor Transform**）拿 `OwningCharacter` 的 Transform。
2. `Inverse Transform Location`（**Inverse Transform Location**）：`T = 上一步 Transform`、`Location = AttackerLocation` → 得到攻击者在玩家**局部空间**的位置。
3. `Break Vector`（**Break Vector**）拆出 `X`（前/后）、`Y`（右/左）。
4. `Abs`（**Abs**）分别取 `|X|`、`|Y|`。
5. `Greater Equal`（**Greater Equal**，float/double 版本）：`|X| >= |Y|`？
   - **True（前后方向）**：`Branch` 判 `X > 0` → True 返回 `AM_PlayerHit_F`，False 返回 `AM_PlayerHit_B`。
   - **False（左右方向）**：`Branch` 判 `Y > 0` → True 返回 `AM_PlayerHit_R`，False 返回 `AM_PlayerHit_L`。
6. 四条路径各接 `Return Node`（函数已有返回值，把蒙太奇资产拖进去）。**越界/空值兜底**：`X=Y=0`（攻击者与玩家同点）会走 `|X|>=|Y|` 的 True 且 `X>0` 为 False → 落到 `AM_PlayerHit_B`，不会空播；如果担心蒙太奇资产没指定，可在每条 Return 前加一次 `IsValid` 兜底到 `AM_PlayerHit_F`。

**为什么用局部空间而不是角度扇区**：局部空间比较 `|X|` 与 `|Y|` 天然处理 0/360 跨界，且和八向闪避的扇区映射（第 14 课）用的是同一套“前方 = +X、右方 = +Y”约定，两个功能的方向语义不会打架。

**坐标约定**（照这个记，别记反）：UE 里角色 `X+` 是前、`Y+` 是右。所以 `Y > 0` = 攻击者在玩家右侧 = 玩家**右侧中招** → 播 `_R`。

### 10.5 `OnPlayerHitRecover`

**操作**

1. `Branch` 判 `bIsDead` → True 直接 `Return`（死亡后不允许任何旧计时器把控制还回来）。
2. `Set bIsHitStunned = false`。
3. `Cast To BPI_CombatComponent`（`OwningCharacter`）→ `CallSetMovementEnabled(true)`。
4. 从同一个 Cast → `CallSetInputEnabled(true)`。
5. **不要在这里再塞一个 `Delay`**：计时器已经等了 `combat.player.hitstun`，回调里再 `Delay 0.38` 等于恢复要 0.76s；更严重的是 `Delay` 是 latent 节点，开始执行后中途死亡也**清不掉**，延迟到点仍会把输入打开。如果跟着旧版本加过 `Delay 0.38`，现在删掉。

**M2/M3 之后要补的**：恢复前检查 `bIsDodging` / `bParryWindowActive` / `bCounterReady`，如果玩家在受击前正在别的状态，别无条件开输入（第 18 课的 `CleanupAll` 统一处理）。首版先只做受击，写完在代码里留一行注释 `// M2/M3: 见 CleanupAll`。

### 10.8 抄 NPC 侧的正解：抄骨架、换五处

NPC 侧（`BP_MasterNPC` + `AC_NPC`）与玩家用**同一个 GASCombatBridge 插件**，事件签名与这些节点的调用完全一致，所以“结构”可以照抄；但 **`ApplyHitReaction` 不能整段复制**——它带着敌人专用数据键、敌人骨架蒙太奇和敌人专用宿主。

| NPC 侧 | 玩家侧 | 处理 |
|---|---|---|
| `BP_MasterNPC` 的「受到伤害时」事件（`DamageInstigator`, `DamageCauser`, `DamageAmount`, `RemainingHealth`） | `SandboxCharacter_CMC` 同名事件（组件名 `GASCombatBridge`） | ✅ 直接照抄节点 |
| 「战斗初始化完成」里 `按名字设置属性基础值("MaxHealth"/"Health")`（`SetAttributeBaseValueByName`） | 同名事件，但取数键换 `player.hp.max`（NPC 是 `enemy.shadow.hp`） | 🔧 换键 |
| 「施加效果」（`ApplyEffectWithValues`，参数 `Target`、`GE_HitStun`、SetByCaller `Data.Duration`） | 完全一致 | ✅ 可抄 |
| `AC_NPC.SelectHitMontage`：`InverseTransformLocation(OwnerTransform, AttackerLocation)` → 比较 `\|X\|`/`\|Y\|` → 四向索引 | `AC_Combat.SelectPlayerHitMontage`，返回 `AM_PlayerHit_F/B/L/R` | ✅ 算法照抄，🔧 换蒙太奇 |
| `AC_NPC.HandleDeath`：`bDead` 守卫 → `CancelAllAbilities` → `AddLooseTags(State.Dead)` → `DisableMovement` → 胶囊 `NoCollision` → 播 `AM_Hit_Death`（硬编码） | `AC_Combat.HandlePlayerDeath`，播 `AM_PlayerHit_Death`；玩家有 `Ragdoll_Start/_End`，死亡表现可选布娃娃 | ✅ 骨架照抄，🔧 换蒙太奇与收尾 |
| `AC_NPC.ApplyHitReaction` 的硬直时长：读 `combat.enemy.*`，且大硬直分支**误读 `combat.enemy.parry_stun`（已知 P0）** | 玩家读 `combat.player.hitstun`，首版不分大小硬直 | 🔧 必须换键，别把缺陷一起抄过来 |
| `AC_NPC` 的 `bFromParry` 参数 | 玩家 M1 不需要（招架是玩家打敌人时的判定，走第 13 课 `TryDefendAttack`） | ❌ 不要抄 |
| 宿主：`AC_NPC`（敌人专用，变量/蒙太奇数组都硬编码敌人资产） | 宿主换成 `AC_Combat`，玩家状态集中一处好清理 | 🔧 换宿主 |

**结论一句话**：抄“三个事件 + 「施加效果」+ 方向比较算法 + 死亡守卫顺序”，不抄“函数体、数据键、蒙太奇、宿主”。跨资产复制整个函数会把敌人的资产硬引用一起带过来，改漏一处就是静默取 0 或播不出动作；按上表逐段重建更稳。

**为什么**

- 方向判定用局部空间比较，比算角度扇区稳（不用处理 0/360 跨界）。
- 受击入口放在 `AC_Combat`，因为闪避/招架/攻击的状态都在它身上，后面清理逻辑能集中处理。
- 硬直时长读 `combat.player.hitstun`，不写 0.38。
- 禁移动/禁输入都走**玩家**的同一套开关（`BPI_CombatComponent` 接口实现，最终落在玩家 BP 的 `MovementEnabled` 上），和攻击/闪避共用同一套开关；在 `AC_Combat` 里写调用时记住：**没写 Target = 组件自己 = 空实现**（`CallSetMovementEnabled` 在组件里没逻辑）。

### 10.9 死亡/硬直门禁三处：入口、状态、清理

一句话：**“恢复回调里判 `bIsDead`”只挡得住计时器，挡不住玩家的手**。要让死亡后真的不能动、不能打，门禁必须同时出现在三处：

| 位置 | 要做什么 | 为什么 |
|---|---|---|
| ① 入口（输入事件） | 左键/重击/侧键/闪避/招架这些输入事件的**最前面**加 `Branch(NOT bIsDead)`，False 直接返回；受击硬直期把 `bIsHitStunned` 一起算进去 | 输入事件与状态机是两条线：`bIsDead` 只是组件变量，入口不读它 → 死后照样出招 |
| ② 状态（调用目标） | 所有 `CallSetMovementEnabled` / `CallSetInputEnabled` 都打到 `OwningCharacter` 的 `BPI_CombatComponent` 接口上（`Cast To BPI_CombatComponent` → 调） | 组件自己的实现是空壳/半壳；玩家的 `MovementEnabled` 才是 `IA_Move` 真正读的开关 |
| ③ 清理（计时器/委托） | 死亡时用 `Clear and Invalidate Timer by Handle` 清掉硬直/闪避/招架/反击所有计时器；不留 `Delay`、不留写死时长的恢复路径 | 旧计时器回调会把控制还回来；`Delay` 即使清了计时器也仍会执行完 |

**按这三处自查的实际问法**（比“我明明判了 bIsDead”有用）：

1. 死后按左键：左键事件第一行有没有 `Branch(NOT bIsDead)`？（没有 → 就是这里漏）
2. 死后按 WASD：`Cast To BPI_CombatComponent` 那根线在不在？（不在 → 玩家的 `MovementEnabled` 没被写 false）
3. 死后 0.4 秒内又“活”了一下：`OnPlayerHitRecover` 里有没有 `Delay`？死亡时 `HitStunTimer` 清了吗？

**最小修复顺序**（照这个顺序，每步单独 PIE 验证）：

1. 在 `LightAttack` 函数入口加 `Branch(NOT bIsDead) → Return`（最外层攻击门禁：调试键、缓冲输入都绕不过函数本身）；
2. 在左键/重击输入事件的最前面各加一次同样的 `Branch`（入口层，防输入缓冲把死亡后的点击排队）；
3. 把 `HandlePlayerHit` / `HandlePlayerDeath` / `OnPlayerHitRecover` 里的 `Call*` 全部改成先 Cast 到玩家再调；
4. 删掉 `OnPlayerHitRecover` 里残留的 `Delay`，恢复只走一次；
5. 死亡 PIE 全验：左键、右键蓄力、侧键 1/2、V、WASD、跳跃 → 全部无反应；出招到一半死亡 → 动作停止且不再恢复。

### 10.10 加门禁时最容易漏的四处（2026-10-21 第二轮实测）

第一轮按 §10.9 改完后用户报出四个新问题，全部是“门禁加错/漏加”，对照修：

| 现象 | 根因 | 修法 |
|---|---|---|
| **常态不能攻击，死亡后反而能攻击** | 条件接反：`if (bWeaponInHand AND bIsDead)`——把 `bIsDead` **直接**接进了 `AND`/`Branch`，等于“只有死了才能打”。`LightAttack`、`StartCharge` 两处都中了 | 在 `bIsDead` 后面插一个 **`NOT Boolean`** 节点再接 `AND`：`bWeaponInHand AND NOT bIsDead` / `… AND NOT bIsDead`。口诀：**守卫永远写成 NOT**，把 `bIsDead` 直接接条件 = 反了 |
| **死亡后还能装备/卸下** | 装备/卸下走的是 `EventGraph` 里那个 `InputKey`（左 Alt）事件，它不属于 `CombatGraph`，第一轮只改了攻击链 | 在这个 `InputKey` 事件最前面加 `Branch(NOT bIsDead)`；以后做侧键 1/2、V 的事件时**第一行就加**，别等出问题再补；F1–F4 调试键同样要加，否则死后还能用调试键播动作 |
| **死亡后还能转视角，人物模型也跟着转** | 鼠标/右摇杆走的是玩家 BP 的 `IA_Look` / `IA_Look_Gamepad` → `AddControllerYawInput` / `AddControllerPitchInput`，全程没有门禁；角色是“跟随控制器 Yaw”旋转，所以镜头一转模型就转 | 在这两个事件最前面加门禁：`Get Component By Class (AC_Combat) → Cast To AC_Combat → Get bIsDead → Branch`（`NOT`，True 直接断开）→ 再进原来的 `AddControllerYaw/PitchInput`。别只关角色 Yaw（那样视角还在转，会让你以为没生效） |
| **受击一次后永远不能动 / 一直硬直** | ① `OnPlayerHitRecover` 里恢复用的 `CallSetMovementEnabled(true)` / `CallSetInputEnabled(true)` 还是**没 Target**（调到组件自己=空实现）；② `HandlePlayerHit` 末尾的 `Clear and Invalidate Timer by Handle(HitStunTimer)` 如果排在 `Set Timer by Event` 之后，会把刚设的计时器清掉 | ① 恢复也改成 Cast 到玩家再调（和死亡路径一致）；② 执行顺序必须是“先清旧计时器 → 再设新计时器”，`Clear` 不能挂在 `Set` 后面 |

**PIE 验收清单（每项独立试，不要连按）**：常态左键/右键能打 → 死亡后左键/右键/装备键/侧键/V/WASD/跳跃/鼠标视角全部无反应 → 受击后 0.38s 恢复移动与攻击 → 出招中死亡动作停止且 1 秒内不自己恢复。

## 第 11 课 M1-3 玩家死亡

**目标**：血量到 0 只触发一次死亡，之后控制彻底关闭。

**前置**：第 10 课。

**操作**

1. 玩家 BP 选中 `GASCombatBridge` → 事件区 `+` → 选 `死亡时`（`GASCombatOnDeath`）。参数：`Killer`、`DamageCauser`。
2. 接 `AC_Combat` 新函数 `HandlePlayerDeath(Killer : Actor)`：
   ```
   if bIsDead → return
   bIsDead = true
   Montage_Stop(所有动作蒙太奇：先记下再逐条 Stop，或 StopAllMontages)
   清理计时器（受击/闪避/招架/反击，M2/M3 后逐个补进 CleanupAll）

   ```

**自检**：按 T 连续打自己到 0（把测试伤害调大）→ 死亡只出现一次日志；然后**逐个试按键**：WASD 不动、左键/右键/侧键 1/2/V/跳跃全部无反应、出招到一半死亡动作停住且 1 秒内不会自己恢复；再打它不会有受击反应。

**常见翻车**：只在受击里判血，死亡事件没人接；死亡后旧计时器回调又把输入恢复（第 18 课的清理必须覆盖死亡路径）；**攻击入口没有 `bIsDead` 守卫**——即使 `bIsDead=true`，左键事件照样会调到 `LightAttack`（§10.9 的①）；`CallSetMovementEnabled` 调在组件自己身上，玩家仍然能走（§10.9 的②）。

**预计**：0.7h。

### 11.1 死亡后镜头与朝向怎么真正收口（细讲版）

**现象**：死亡后鼠标一动，镜头还在转，人物模型也跟着转。

**为什么会有两条独立的旋转来源**（都跟 `AC_Combat.bIsDead` 无关）：

| # | 来源 | 在哪个资产里 | 怎么验证 |
|---|---|---|---|
| ① | 鼠标/右摇杆 → `AddControllerYawInput` / `AddControllerPitchInput`，直接改 **Controller 的 Yaw/Pitch** | 玩家 BP `SandboxCharacter_CMC` 的 `IA_Look`、`IA_Look_Gamepad` 事件 | 全工程 T3D 缓存里搜 `AddControllerYawInput`/`AddControllerPitchInput`，只有玩家 BP 这 8 处（鼠标/手柄各一对 + ubergraph 副本），没有别处 |
| ② | Controller 的 Yaw 被改后，**角色身体**跟着 Controller 转：玩家 `UpdateRotation_PreCMC` 会切 `CharacterMovement` 的 `bUseControllerDesiredRotation` / `bOrientRotationToMovement`，其中 `bUseControllerDesiredRotation` 打开时角色会平滑转向 Controller 朝向 | 玩家 BP `UpdateRotation_PreCMC` + CharacterMovement | 死亡后关掉 ①，模型自然不转；若还转，再看 ③ |
| ③ | `AC_Combat.ReceiveTick` 里还有一句 `SetActorRotation(Yaw = RInterpTo(当前, CachedInputRotation.Yaw, 13))`，把角色朝“上次攻击时的输入方向”转 | `AC_Combat.EventGraph / ReceiveTick` | 死亡后角色会朝最后一次出招方向慢慢转正；想彻底静止就把组件 Tick 关掉 |

所以**只关角色朝向是没用的**（镜头还在转，你会以为没生效）；正确做法是在 **①的入口**把输入拦掉，②③自然静止。

**修法 A（推荐，先把功能做对）：在玩家 BP 的两个 look 事件前面加 `bIsDead` 门禁**

> ⚠️ 先纠一个易错点（2026-10-21 用户实操截图）：`Get Component By Class` 的 `Component Class` 选了 `AC_Combat` 之后，**`Return Value` 引脚本身就是 `AC_Combat` 类型**，直接拉 `Get bIsDead` 就行，**不需要再 `Cast To AC_Combat`**。而如果把 `Cast To` 当纯数据节点用（exec 不接），cast 不会执行、`As AC Combat` 可能读到空值。要么不用 Cast，要么把 exec 也串进链里（`Triggered → Cast → Branch`）。

1. 打开 `/Game/Blueprints/SandboxCharacter_CMC` → `EventGraph`，找到 `IA_Look`（鼠标）和 `IA_Look_Gamepad`（手柄）两个 `EnhancedInputAction` 节点。
2. 空白处右键搜 **`Get Component By Class`** → `Class` 引脚选 **`AC_Combat`**（不是 `ActorComponent`）。
3. 从它的 `Return Value` 直接拉出 **`Get bIsDead`**（把 AC_Combat 里的 `bIsDead` 变量拖进来，或在引脚上拖出后搜 `bIsDead` 选**获取**；**不要**选“设置 bIsDead”）。
4. 接 **`NOT Boolean`**（搜 `NOT Boolean`），得到“还活着”的布尔。
5. **断开** `IA_Look` 的 `Triggered` → `AddControllerYawInput` 的连线，改成：
   `IA_Look.Triggered → Branch`，`Branch.Condition = NOT 结果`；`Branch.False → AddControllerYawInput`（原来的链），`Branch.True → 留空`（什么都不接）。
   - 注意原来 `AddControllerYawInput` 的 exec 输出还接着 `AddControllerPitchInput`（上下看），它是链式的，所以**只拦 yaw 这一头就同时拦住了俯仰**。
6. 手柄那条 `IA_Look_Gamepad` 同样处理（它后面先经过几个 `Promotable Operator` 再进 yaw/pitch，门禁要加在**这些运算之前**）。
7. `bIsDead` 不能是私有变量：选中 AC_Combat 的 `bIsDead`，看细节面板 **Private** 没勾（默认不勾，能跨蓝图读）。

**修法 A′（更省、更不容易接错，推荐和 A 二选一）：用玩家自己的 `bIsDead` 镜像**

死亡事件本来就在玩家 BP 里接（`GASCombatOnDeath → AC_Combat.HandlePlayerDeath`），顺手在那里加一句 **`Set bIsDeadLocal = true`**（玩家 BP 新建布尔变量，比如 `bIsDeadLocal`），look 事件里直接读这个本地布尔 → `NOT` → `Branch`。
优点：不用每帧 `Get Component By Class`、不用跨蓝图 Cast，门禁和死亡事件共用同一个来源；以后做复活时在同一处置回 false 即可。

**修法 B（可选，省每帧查找）：把组件缓存成变量**

玩家 BP 加变量 `CombatComponent`（类型 `AC_Combat`，对象引用），在 `ReceivePossessed`（或 `GASCombatOnCombatReady`）里 `Get Component By Class (AC_Combat) → Cast → Set CombatComponent`；之后 look 事件里直接用 `CombatComponent → Get bIsDead`。
注意：`ReceivePossessed` 时组件已创建完毕，是安全的；不要放在 `ConstructionScript`（PIE 下副本还没生成）。
修法 A 每帧 `GetComponentByClass` 的开销可以忽略（look 事件一帧最多一次），**先把 A 做对再考虑 B**。

**补充：想连③也彻底静止**

在 `AC_Combat.HandlePlayerDeath` 末尾加 **`Set Component Tick Enabled`（Target = 组件自己 `self`，`bEnabled = false`）**。
安全性：死亡路径已经 `CallWeaponTrace(false)`，Tick 里的武器检测本来也不会结算；Tick 关掉后，`ReceiveTick` 的试转和武器检测都不再跑。
**不要**用玩家 BP 的 `Set Actor Tick Enabled(false)`——那会连动画、移动组件一起停，死亡蒙太奇也播不出来。

**排错清单**

| 还转？ | 检查 |
|---|---|
| 鼠标转、手柄不转 | 只改了 `IA_Look`，`IA_Look_Gamepad` 漏了 |
| 上下看还能动、左右不能 | 门禁加在了 `AddControllerPitchInput` 之后；应在 `AddControllerYawInput` 之前 |
| 完全不转但活着也不能看 | `Branch` 的 True/False 接反了，或 `NOT` 漏了/多加了一个 |
| 死亡后不转、但角色模型自己慢慢转正 | 这是来源③，按上面“补充”关 `AC_Combat` Tick |
| 死亡后视角不转，但重开 PIE 又转 | `bIsDead` 没在死亡路径里真正置 true，或被复活/重置逻辑写回 false |

**验收**：死亡后鼠标上下左右 + 手柄右摇杆 → 镜头不动、模型不转；活着时鼠标/手柄视角都正常；死亡后左键/右键/装备键/侧键/V/WASD/跳跃仍全部无反应（前几节的门禁不能因为这次改动被破坏）。

**预计**：0.3h。

#### 12.2.1 「前向 × 50」到底是什么（向量入门）

**先说结论**：`前向 × 50` = **“从敌人身体中心，沿他面朝的方向，往前 50 厘米的那个点”**。它不是“50 米”，不是“50 倍”，单位是**厘米**（UE 默认 1 单位 = 1 cm）。

拆开讲：

1. `Get Actor Forward Vector`（获取 Actor 前向向量）返回一个**长度为 1** 的向量，指向该 Actor 的正面。敌人朝正前方（世界 +X）时它是 `(1, 0, 0)`；敌人转 90° 后它就变成 `(0, 1, 0)`——**它永远跟着敌人的朝向走**，这就是为什么用它而不是写死 `+X`。
2. `Multiply` 一个 `50`（类型选 **Float**）：`(1,0,0) × 50 = (50,0,0)`，长度变成 50 cm。于是 `敌人位置 + 前向×50` 就得到“身体正前方 50 cm 处”。
3. 为什么起点要往前挪 50？敌人胶囊体半径约 42 cm，起点放在身体中心会让检测球**先包住自己**（而且半径 60 > 50，就算挪 50 cm 也仍然与自己的胶囊重叠）。所以**必须**在 `Actors to Ignore`（忽略 Actor）里填 `Owner`——这是这个函数最容易漏的一步。
4. 为什么终点是 `前向×160`？球体检测是**扫掠**（一个球从 Start 一路扫到 End，扫过的整个“胶囊形”体积都算命中），不是单点。50→160 覆盖的是敌人挥击能碰到的前方一段：`50 - 60` 到 `160 + 60`，也就是从贴近身体到前方约 2.2 m。
5. 半径 60：给挥砍留的“宽度/厚度”。太小（比如 20）只有刀尖正中才算命中；太大（比如 120）会隔空打人。

**节点连法**（`Sphere Trace For Objects` / 搜 `Sphere Trace`；为什么不用 `By Channel` 见 §12.2.3）：

```
Start = Get Actor Location(Owner)  +  (Get Actor Forward Vector(Owner) × 50)
End   = Get Actor Location(Owner)  +  (Get Actor Forward Vector(Owner) × 160)
Sphere Trace For Objects（按对象类型进行球体追踪）
    Start = 上面 Start
    End   = 上面 End
    Radius = 60
    Object Types = [ Pawn ]       ← 玩家是 Pawn 对象类型；点数组里的 + 加一个元素，下拉选 Pawn（枚举数组，不能改类型）
    Trace Complex = false
    Actors to Ignore = [ Owner ]          ← 千万别漏
    Draw Debug Type = For Duration / Duration = 2  ← 调试期打开，PIE 里能直接看到那个球扫过的范围
    Out Hit → Break Hit Result → Hit Actor
```

> 如果坚持用 `Sphere Trace By Channel`，默认的 `Visibility` 通道在本项目里扫不到玩家（玩家胶囊/网格用的 `Pawn`、`CharacterMesh` 预设都忽略 `Visibility`，见 `Config\DefaultEngine.ini` 的 `+Profiles=(Name="Pawn"...)` 与 `(Name="CharacterMesh"...)`），表现就是“敌人出招、球是红的、什么都不发生”。

**调试技巧**：先把 `Draw Debug Type` 设成 `For Duration` + `2` 秒，PIE 里让敌人出招，你会看到一串绿球沿着敌人面前扫过去——这就是“前向×50 到 ×160、半径 60”的几何意义，比看数字直观。确认范围合理后再关掉 Debug。
**三个数字怎么调**：50 = 起点离身体多远（差不多是“手的位置”）；160 = 挥击能碰到的前后距离；60 = 挥击宽度。调参时先动 160 和 60，50 一般不用改（战斗手感偏短就加 160，偏“隔空打”就减 60）。这三个是手感参数，**不写进 DT**，做成 `AC_EnemyAttack` 的三个 Float 变量（`TraceForwardOffset` / `TraceLength` / `TraceRadius`）方便边 PIE 边调。

**常见翻车**：忘了 `Actors to Ignore = Owner` → 敌人自己算命中；终点写成“位置×160”（乘的是位置不是前向）→ 检测点飞到地图外；`Multiply` 的类型是 Vector×Vector 而不是 Vector×Float → 连不上或数值错；半径和朝向用反（把半径当距离）→ 永远打不到人。

**自检**：PIE 站在敌人 2.5m 内 → 每约 2 秒挨一刀，掉 `enemy.shadow.atk`（10）血并播受击；走远 → 停止出招。

**常见翻车**：Notify 找不到组件 = 组件 Tag 没设；敌人攻击 Montage Slot 不对 = 敌人不动；没有 `bAttacking` 守卫 = 同一时间叠多刀；没去重 = 一刀多次结算；`OwningNPC` 的 Cast 结果没接 `Set` = 一读就报“结果为无”；`DoAttackHit` 被接进 `BeginPlay`（或别的常驻事件）= 一进 PIE 全地图刷错；守卫写成 `NOT bAttacking AND bIsParryStunned` = 守卫完全失效。

#### 12.2.2 报错排查：「尝试读取 AC_EnemyAttack_C 中的属性 OwningNPC 时，结果为无」

**看到这条不要怀疑引擎/插件**：它的意思是“`DoAttackHit` 跑到读 `OwningNPC` 那一步时，这个变量还是**空（None）**”。不是“蓝图识别不了组件的 owner”，而是**从来没有给 `OwningNPC` 赋过值**。

四个常见原因（按概率排序）：

| # | 原因 | 现象 | 修复 |
|---|---|---|---|
| 1 | `ReceiveBeginPlay` 里只放了一个 `Cast To Character`，`As Character` 输出**没有接** `Set OwningNPC`（你这次就是它） | 一进 PIE 就报错，且敌人完全不攻击 | 把 `Cast` 的 `As Character` 接上 `Set Owning NPC` 节点（`Set Owning NPC` 的 exec 接 Cast 后面的白线） |
| 2 | `Set OwningNPC` 放在别的事件里（比如某个调试键），BeginPlay 没执行到 | 同上 | 统一放 `ReceiveBeginPlay` 第一段 |
| 3 | Cast 失败（Owner 不是 Character） | 同上报错、`As Character` 为空 | `AC_EnemyAttack` 必须挂在 Character 类（`BP_MasterNPC`）上 |
| 4 | 变量声明了但默认值为空，又没人 Set | 同上 | 同上，靠 Set 解决 |

**正确写法是“Cast → Is Valid → Set → 再起计时器”**，一段话讲清：

```
ReceiveBeginPlay
  → Cast To Character (Object = Get Owner)
      Cast Failed → Print String("AC_EnemyAttack 挂错 Actor 了")   ← 调试期必有
      As Character → Set Owning NPC
  → Is Valid (Owning NPC)
      True  → Set Timer by Event (Delegate = AttackLoop, Time = AttackInterval, Looping = true)
      False → Print String("OwningNPC 仍为空，检查 Cast 是否接到 Set")
```

**第二类错误：`DoAttackHit` 被接到常驻事件上。** 你这次的 4 条报错还有第二个来源——`BP_MasterNPC` 的 `ReceiveBeginPlay` 里挂了一个 `AC_EnemyAttack.DoAttackHit`。一进 PIE，4 个敌人实例同时在 BeginPlay 调 `DoAttackHit`，而那一刻 `OwningNPC` 还没赋值（或干脆没赋值），于是 4 条报错。**`DoAttackHit` 只应该由 `AN_EnemyAttackHit` 通知触发**，别的事件里不要接它（`BeginPlay`、`Tick`、`ReceiveActorBeginOverlap` 一律不接）。

**Notify 侧要真正串 exec。** 只有数据线（`Get Owner` → `Find Component by Tag`）而 exec 还是 `Entry → Result` 直连的话，`DoAttackHit` 根本不会被调用，表现是“敌人出招了但打不到人、也没有报错”。正确链条：

```
Received_Notify
  → Get Owner
  → Find Component by Tag (Tag = "EnemyAttack")
  → Is Valid
      True  → Cast To AC_EnemyAttack → 调 DoAttackHit
      False → Print String("Notify 没找到 EnemyAttack 组件：检查组件 Tags")
```

顺带检查：`BP_MasterNPC` 里 `AC_EnemyAttack` 组件的 **Component Tags** 必须填 `EnemyAttack`（没有它 `Find Component by Tag` 必然返回空）。

**还有两个容易一起错的地方**：

1. **守卫写反（⚠️ 2026-10-22 实测更正）**：`DoAttackHit` 开头应当是 **`if (NOT bAttacking OR bIsParryStunned) → return`**，也就是“没在出招、或者被招架硬直了，才返回”。**不要写成 `if (bAttacking OR bIsParryStunned) → return`**——因为 `AttackLoop` 是**先**把 `bAttacking = true`、**再**播蒙太奇的，Notify 在 0.4981s 触发时 `bAttacking` 一定是 `true`，这个守卫会把整段（Print、球、结算）全部跳过，表现就是“敌人照常挥刀，但既没有 Print、也没有 Debug 球、玩家不掉血”，而且**不报任何错**。同理，写成 `if (NOT bAttacking AND bIsParryStunned)` 也错（守卫失效，空闲时也会检测）。
2. **检测结果没接线**：`Sphere Trace` 的 **`Out Hit` → `Break Hit Result` → `Hit Actor`** 必须真的连到 `Array Contains` 的 `Item to Find`、`Array Add` 的 `New Item` 和「对目标造成伤害」的 `Target` 上。**把检测节点的 `Return Value`（bool，表示“是否命中”）接到这三个引脚是类型不匹配**：`Array Add` 上会出现红色 `ERROR!`/编译错误（T3D 里表现为 `ErrorType=1`），整个函数编译不过，PIE 跑的还是上一次成功编译的旧版本 → 表现同样是“改了没反应”。悬空的 `Knot` 就是空值，表现是“有检测但没伤害”。

**最后一个变量别忘**：`AttackLoop` 里算距离/朝向用的是 `Player`，它也要赋值——在 `AttackLoop` 开头 `Set Player = Get Player Character(0)`（`Player Index = 0`）。`Player` 为空时距离算不出来，敌人永远不会出招。

**预计**：1.5h。

#### 12.2.3 敌人出招了，但玩家不掉血、也没有受击

先分两类：**通知没进来**（`DoAttackHit` 根本没执行）和 **通知进来了但球没扫到玩家**。用 Debug 画球一步区分。

0. **动手之前先点一次「编译」**。蓝图有红色编译错误时，PIE 里跑的是**上一次成功编译的旧版本**——你会看到“改了节点、PIE 里毫无变化”，而且没有新报错。`Array Add` 上出现 `ERROR!` 条就是这个状态（最常见原因：把检测节点的 `Return Value` 接到了数组/对象引脚上，见下）。

1. 在 `DoAttackHit` 里把 `Draw Debug Type` 设成 `For Duration`、`Duration = 2`，PIE 里站到敌人面前看球。
2. **看不到任何球** → `DoAttackHit` 没被调用，查三处：
   - `AN_EnemyAttackHit` 的 `Received_Notify` exec 链是否真的串到了 `DoAttackHit`（应为 `Entry → Find Component by Tag → Is Valid → DoAttackHit`）。只有数据线、exec 还直连 `Result` 的话，函数根本不会执行；在 `Is Not Valid` 上接一个 `Print String` 就能看见。
   - 敌人在播的蒙太奇上有没有这个 Notify：`AttackLoop` 播的必须是 `AttackMontage` 变量，且这个变量填了 `AM_EnemyAttack_Text`（填成空则连动画都没有）。
   - `BP_MasterNPC` 上 `AC_EnemyAttack` 组件的 **Component Tags** 里有没有 `EnemyAttack`（`Find Component by Tag` 找不到就静默什么都不做——不报错）。
3. **有球、但一直是红的（不命中）** → 球扫不到玩家。最常见的是**通道不对**：项目 `Config\DefaultEngine.ini` 里 `Pawn` 与 `CharacterMesh` 两个碰撞预设都忽略 `Visibility`，而玩家胶囊/网格正是这两个预设，所以 `By Channel + Visibility` 的球会**直接穿过玩家**；玩家打敌人能中，是因为敌人（`BP_MasterNPC`）的胶囊预设挡 `Visibility`——**单向能打就是这个不对称造成的**。
   修法：换成 **`Sphere Trace For Objects`**，`Object Types` 里放一个 **`Pawn`**，其余参数不变。不要靠把玩家胶囊改成 `BlockAll` 解决（会连带影响相机、导航等系统）。

   > **`Object Types` 是一个枚举数组，不用（也不能）“改变量类型”。** 它的类型固定是 `EObjectTypeQuery`（对象类型查询）的数组。操作就一步：点数组引脚里的 **`+`** 加一个元素 → 元素下拉里选 **`Pawn`**。不需要 `Make Array`、不需要 `Cast`、也不需要把它提升成变量。如果下拉列表里看到的是 `WorldStatic / WorldDynamic / Pawn / PhysicsBody / Vehicle / Destructible` 这一串，说明枚举找对了，`Pawn` 就在里面（中文界面里同样显示 `Pawn`）。点右上角“眼睛/放大镜”切换成非上下文敏感搜索，能避免列表被过滤得只剩一两条。
   >
   > **找不到 `+` 就不用找了。** 数组元素的 `+` 在**图表里的节点本体**上（`Object Types` 那一行最右端；节点拉宽一点、或选中节点后在图上找），**节点详情面板里通常不显示它**。如果还是看不到，直接换等价节点 **`Sphere Trace By Profile`（按配置进行球体追踪）**，`Profile Name` 填 **`Pawn`**——这是 Name 字符串输入，完全不涉及枚举数组。原理：项目 `Pawn` 预设只把 `Visibility` 设为忽略，其余通道都是 Block，按这个配置做球体检测就能扫到玩家胶囊（验证阶段也可临时用 `By Channel` + `Trace Channel = Camera`，玩家胶囊挡该通道，但仅作验证手段）。
   >
   > **`By Profile` 没有 `Visibility` 选项是正常的**：它用 `Profile Name` 取代了 `Trace Channel`，下拉里列的是**碰撞预设名**（`Pawn` / `CharacterMesh` / `BlockAll` / `NoCollision`…），不是通道名（`Visibility`、`Camera` 那些属于 `By Channel` 的 `Trace Channel`）。换完节点后如果**连 Debug 球都不显示**，按顺序查三处：① 新节点的 exec 是否真的接进来了（在 `DoAttackHit` 函数入口接个 `Print String` 当场验证）；② `Draw Debug Type` 是不是 `For Duration`、`Duration` 是否 > 0；③ 节点是否被误删了后面的 exec 链。Debug 球是“函数被执行才会画”，不显示首先说明**这段代码根本没跑到**，而不是检测通道的问题。
4. **球变绿（命中）但仍不掉血** → 结算环节逐个查：
   - `Out Hit → Break Hit Result → Hit Actor` 是否真的连到 `Array Add.New Item` 和「对目标造成伤害」的 `Target`（悬空 `Knot` = 空值）；
   - 「对目标造成伤害」的 `DamageEffectClass` 是不是 `GE_Damage`、`Source` 是不是 `OwningNPC`、`Level = 1`；
   - `CurrentAttackDamage` 是不是 0（`GetEnemyParam` 的 `Table` 要接 `DT_Enemy`、`Key = enemy.shadow.atk`；在 `AttackLoop` 里 `Print String` 打一下最省事）；
   - 命中 Actor 是不是玩家本人（加上 `Cast To SandboxCharacter_CMC` 判断），以及玩家是不是已经 `bIsDead`（死了不再进受击，见第 10 课门禁）。
5. 顺手再修两处：
   - `DoAttackHit` 开头的守卫应为 **`if (NOT bAttacking OR bIsParryStunned) → return`**。写成 `if (bAttacking OR bIsParryStunned) → return` 会把整段挡死（`AttackLoop` 播蒙太奇前已把 `bAttacking=true`）；写成 `AND` 则守卫失效。
   - `Array Add` 前用 `Contains` 去重，避免一次挥击多次结算。

> **⚠️「既没有 Print、也没有球」的第一嫌疑就是守卫（2026-10-22 本项目实测确认）**：`Print String("执行攻击函数")` 和 `Sphere Trace` 都在 **`else` 分支**里。只要 `if (bAttacking OR bIsParryStunned)` 为真，函数会“执行了但一行都没跑”，现象是——敌人照常挥刀、Notify 正常触发、**没有 Print、没有球、不掉血、也不报错**。判断方法：把 `Print String("进入DoAttackHit")` 放在 **守卫之前**（函数入口第一行），PIE 里每挥一刀都会打印一次 → 说明 Notify 链没问题，问题就在守卫方向。改完守卫后，再把 Print 挪回 `else` 分支里。

**自检**：PIE 站到敌人正前方 2m 内 → 球扫过时变绿 → 玩家掉 `enemy.shadow.atk`（10）血并播受击；站到 3m 外 → 球不绿、不掉血；按 T 打自己仍正常。

**预计**：0.5h。

#### 12.2.4 敌人不鞭尸：跨蓝图读“玩家死了没”

**现象**：玩家已经死亡（`AC_Combat.bIsDead == true`），敌人还在继续出招、甚至继续结算伤害。

**为什么**：`AttackLoop` 只判断了“距离够不够近”，没有任何“目标还活着吗”的判断；玩家死后尸体还在原地，距离一直满足，于是每 `AttackInterval` 继续挥刀。

**跨组件取玩家死亡布尔的做法**（`bIsDead` 是 `AC_Combat` 上的普通变量，蓝图之间可直接读，不需要接口、不需要事件）：

```
Player (AC_EnemyAttack 里已赋值的 Character)
  → Get Component By Class（按类获取组件）
      Target = Player
      Component Class = AC_Combat          ← 类选择器里选 AC_Combat（不是 Cast）
  → Return Value（此引脚已经是 AC_Combat 类型，不需要再 Cast）
  → Is Valid
      False → 玩家没挂组件（理论上不会发生），按“活着”处理或直接 return
      True  → Get bIsDead（右键搜 bIsDead）
```

要点：

- `Get Component By Class` 的 `Return Value` 是**“按 `Component Class` 决定的输出类型”**（引擎用 `DeterminesOutputType` 实现，`Runtime/Engine/Classes/GameFramework/Actor.h:3805` 同款元数据），`Component Class` 选 `AC_Combat` 时返回的就已经是 `AC_Combat` 引用，**不用再 `Cast To AC_Combat`**（本项目 Mover 蓝图里同样用法，返回引脚直接是 `MoverComponent`）。
- **一定要先 `Is Valid`**：玩家身上没有该组件时 `Return Value` 是空，直接拉 `bIsDead` 就会报你熟悉的那句“尝试读取…属性 bIsDead 时，结果为无”。
- 读不到 `bIsDead` 时，把节点右键菜单的 **Context Sensitive（上下文关联）关掉**再搜。

**插到两个地方（双保险）**：

1. **`AttackLoop`（主修，让它停手）**：放在 `Set Player = Get Player Character(0)` 之后、距离判断之前。
   ```
   if (玩家无效)          → return
   if (Player 的 bIsDead) → return     ← 新增：玩家死了就不再出招
   if (距离 > AttackRange) → return
   ...
   ```
   如果死亡时还想让敌人做个“收刀/转身离开”的表现，可在这里先播个蒙太奇或设个计时器再 return；首版直接 return 就够 A01–A14 用。
2. **`DoAttackHit`（兜底，防其他调用路径）**：命中后、`Array Add`/对目标造成伤害之前。
   ```
   Break Hit Result → Hit Actor
     → if (Hit Actor 的 bIsDead) → return   ← 不 Add、不结算、不播受击
     → Array Contains（去重）→ Array Add → 对目标造成伤害
   ```
   注意这里的 `bIsDead` 是**命中到的那个 Actor** 的组件，不是 `Player` 变量（平时是同一个，但用 Hit Actor 更准，也顺便挡住“别的玩家/召唤物”）。

**要不要用 `and` 拼进原守卫**：可以，但语义要理清——`DoAttackHit` 开头的守卫是“**该不该继续**”，条件写成 `if (NOT bAttacking OR bIsParryStunned OR TargetIsDead) → return`（都是 OR，任一成立就退出）。这里**不要**用 `AND` 拼死亡判断：`bAttacking AND NOT bIsParryStunned AND NOT TargetIsDead` 是“继续”的条件，写成一个大布尔更容易接反；入门阶段建议**用连续的 Branch 逐个判**，好读也好查。

**为什么不用别的方式**：

- 不读 `Health` 属性来判断：玩家死亡时 `Health` 可能被 GE 改成 0，但读属性要走 GAS 节点，而且“血=0 但还没播死亡”的瞬间语义不一致；`bIsDead` 是 `HandlePlayerDeath` 里第一时间置的，最贴近“已经死了”。
- 不靠“攻击里不结算伤害”来假装停手：那样敌人会永远贴着尸体挥刀，观感更差。

**自检**：PIE 里让敌人把玩家打死 → 玩家倒地后敌人**不再挥刀**（`AttackLoop` 已 return）；重开 PIE → 敌人恢复出招；玩家死亡瞬间若正好有一刀在挥，那一刀不应再让玩家播受击或掉血。

**常见翻车**：`Return Value` 上忘了 `Is Valid` → 报“读取 bIsDead 结果为无”；把 `Get Component By Class` 的 `Target` 接到 `Self`（组件自己不是 Actor）→ 编译不过；只改了 `DoAttackHit` 没改 `AttackLoop` → 不结算了但还在挥刀（看起来仍像鞭尸）。

**预计**：0.3h。

#### 12.2.5 报错排查：「尝试读取非UClass中的属性 CallFunc_…_结果为无」

**现象**（2026-10-22 本项目实测）：PIE 里功能正常（该掉血掉血、该死停手），但日志一直刷两条：

```
尝试读取非UClass中的(real)属性 CallFunc_BreakHitResult_HitActor，结果为无。 节点：分支  图表：DoAttackHit
尝试读取非UClass中的(real)属性 CallFunc_GetComponentByClass_ReturnValue_2，结果为无。 节点：分支  图表：DoAttackHit
```

**含义**：这两条**不是逻辑错误，是“在对象为空时读了它的属性”**。报错里的名字不是变量，而是**上游纯节点（pure）的输出引脚名**：

- `CallFunc_BreakHitResult_HitActor` = `Break Hit Result` 的 `Hit Actor` 引脚 → 说明**球没扫到人**时（`Out Hit` 是空结构）就执行到它了，`Hit Actor` 自然是 `None`；
- `CallFunc_GetComponentByClass_ReturnValue_2` = 第二个 `Get Component By Class` 的 `Return Value` 引脚 → 它的 `Target` 是 `None`，所以返回 `None`；紧接着的分支去读它的 `bIsDead`，于是在**空对象上读属性**。

**为什么会发生在“没命中”的帧**：蓝图的**纯节点（没有白色 exec 引脚的节点）会在任何读取它输出的地方被求值**。你把 `Hit Actor → Get Component By Class → bIsDead` 这条链直接接进了分支条件；即使这一帧球没命中，只要执行流走到那个分支，条件链就会**从头到尾算一遍** → 空对象被读 → 报错。

**修法：按“先确认非空，再往下走”的顺序拆成带 exec 的分支**（不要塞进同一个 `AND`/`OR` 条件——纯节点在条件里会**两边都算**，`Is Valid` 为假也拦不住另一半）：

```
Sphere Trace By Profile（exec）
  → Branch（Condition = 追踪节点的 Return Value（bool））      ← 读 bool 是安全的
       False → 结束（没命中，什么都不做）
       True  → Break Hit Result → Hit Actor
               → Branch（Condition = Is Valid(Hit Actor)）    ← 先确认命中的是人
                    False → 结束
                    True  → Get Component By Class（Target = Hit Actor，Class = AC_Combat）
                            → Branch（Condition = Is Valid(Return Value)）  ← 再确认组件在
                                 False → 结束
                                 True  → Branch（Condition = Get bIsDead）
                                           True  → 结束（死了不结算）
                                           False → Array Contains（去重）→ Array Add → 对目标造成伤害
```

要点：

- **`Is Valid` 本身可以吃空对象**（它就是个“判空”函数），所以 `Is Valid(Hit Actor)` 不会报错；会报错的是“读空对象的成员”。
- 判断 `bIsDead` 的那条链，必须放在**两次 `Is Valid` 都为真之后**；换句话说，`Get Component By Class` 的 `Target` 只在 `Hit Actor` 有效时才被求值。
- 也可以用 `Out Hit → bBlocking Hit` 代替 `Return Value`，效果一样（结构体引脚永远存在，读它安全）。
- 这类报错**只污染日志、不改行为**，所以“功能没问题但有红字”时优先查“哪条纯节点链在空对象上被求值”。

**自检**：PIE 里在敌人面前左右横跳（一半挥刀落空、一半命中）持续 30 秒，Output Log 过滤 `Attempted to read` / “尝试读取” 应为 0 条；命中时照常掉血与受击，没命中时什么都不发生。

**预计**：0.2h。

### 12.2.6 敌人自己的死亡守卫（v1.27 补；v1.29 改写法：死亡方主动通知组件）

**现象**：敌人被打死、死亡动作播完后仍会站起来继续攻击玩家。

**根因（资产实证）**：`AC_EnemyAttack` 的 `AttackLoop` / `DoAttackHit` 只查了 `bAttacking`、`bIsParryStunned`、`Player` 的 `bIsDead`（而且这个 `bIsDead` 是「按类取 `AC_Combat` 组件再读玩家状态」），**没有一处查「自己（`OwningNPC`）已死」**；`AC_NPC.HandleDeath` 又只做了 `DisableMovement` 与 `SetCollisionEnabled`，既不清 `AttackLoop` 的循环计时器，也不 `StopAnimMontage`、不复位 `bAttacking`。于是死亡动画一结束，攻击蒙太奇照播——表现就是「站起来了」。（补充：`AC_NPC` 是挂在角色上的**组件类**，`OwningNPC` 是 `Character`，所以 `Cast To AC_NPC` 永远失败、编译能过但运行时恒为 False；组件之间也不能直接读对方变量——必须改用 `Get Component By Class` 或下面推荐的「推模型」。）

**Step 1｜先给 `AC_EnemyAttack` 加两个自己的变量**
`AC_EnemyAttack` 是组件，只能靠自己身上的状态——不要试图去读 `AC_NPC` 的变量。加：`bDead`(bool，默认 false)、`AttackLoopTimer`(TimerHandle)。找到 EventGraph 里 `Set Timer by Event` 那个节点，把它的 **Return Value** 存进 `AttackLoopTimer`（后面死亡时要用它清计时器）。

**Step 2｜在 `AC_EnemyAttack` 新建 `StopCombat` 函数：让它自己收拾自己**

函数体（每步都连成一条 exec 链，用 `OwningNPC` 或 `self` 取自己）：

- `Set bDead = true`；
- `Clear and Invalidate Timer by Handle`（Handle = `AttackLoopTimer`）；
- `Set bAttacking = false`；`Set bIsParryStunned = false`；
- `Array Clear`（Target = `HitTargetsThisSwing`）；
- `OwningNPC → Get Mesh → Stop Anim Montage`，Montage 填 `AttackMontage`（**只停攻击蒙太奇**；不要用 `Montage Stop` 全停，会连死亡蒙太奇一起停掉）。

**Step 3｜给 `AttackLoop` / `DoAttackHit` 加自身死亡门**
`AttackLoop`：在**第一道 `OwningNPC` 有效性判断之后**插 `Branch`，`Condition = Get bDead`，true 直接结束。`DoAttackHit`：把开头那道 `if (NOT bAttacking OR bIsParryStunned)` 并入 `OR bDead`——这样即使攻击已经起手，也不会再结算伤害。两处都只读**自己的** `bDead`，不跨组件。

**Step 4｜`AC_NPC.HandleDeath` 通知攻击组件停工**
在 `AC_NPC.HandleDeath` 末尾（`bDead` 已经置 true 之后、`DisableMovement` / `SetCollisionEnabled` 那一带）：`Get Owner → Get Component By Class(AC_EnemyAttack) → Is Valid → 调 StopCombat()`。清理动作全在 `StopCombat` 里，这里只负责「通知」，所以不需要从组件外部去动它的计时器和变量。


> 备选写法（拉模型，不推荐）：`OwningNPC → Get Component By Class(AC_NPC) → Get bDead`。能通，但要求在 `AC_ENEMY` 侧读别人的状态，接口一变就断；推模型只需对方提供一个函数。


**Step 5｜PIE 验收**
把敌人打死，观察 10 秒：不再出现「执行攻击函数」日志、不再播攻击蒙太奇、玩家血量不变；重新开局/重刷敌人后行为正常。

**自检**：敌人死亡动作播完后保持倒地/消失；死亡瞬间正在挥的那一刀不结算伤害；玩家在敌人尸体旁站 10 秒不被攻击。

**常见翻车**

- 只加了 `AttackLoop` 的门、没清计时器：本轮循环不会再来，但计时器仍按 `AttackInterval` 把 `AttackLoop` 吵醒去 return，Log 会刷、白耗性能（功能上已停手）。
- 只在 `DoAttackHit` 加门：蒙太奇照播，视觉上仍然「死了还挥刀」。
- 用 `Cast To AC_NPC` 来读 `bDead`：`AC_NPC` 是组件类、`OwningNPC` 是 Character，Cast 恒失败（不报错，所以最容易骗过自己）。正确姿势是 `Get Component By Class(AC_NPC)`，或者干脆用上面的推模型。

> 归入附录 G 案例 1：**死亡是横切状态，任何「每隔 N 秒循环」的计时器都必须有死亡清理**。

### 14.1 TryToDodge 细讲：向量怎么变成可比大小的 float

**你问的那一步就是这里**：`Get Last Movement Input Vector` 返回的是 `Vector`（世界空间，长度 0–1），`0.1` 是 `Float`——**两者不能直接比**。蓝图里也不存在“向量 < 浮点数”这种节点；必须先把向量**取长度**变成标量：

| 顺序 | 节点（中文显示名 / 内部名） | 输入 | 输出 | 作用 |
|---|---|---|---|---|
| 1 | `Get Last Movement Input Vector`（GetLastMovementInputVector） | Target = `OwningCharacter` | `Vector` | 玩家这一帧想往哪走（世界空间，已含八方向合成） |
| 2 | **`Vector Length XY`（VSize2D）** | `Vector` | `Float` | **关键一步**：把“方向+大小”压成一个数字（只取水平面） |
| 3 | `>=`（GreaterEqual_FloatFloat） | A = 长度，B = `0.1` | `bool` | 死区判断：小于 0.1 视为“没推方向” |
| 4 | `Branch`（分支） | Condition = 上一步 bool | 两条 exec | True = 有方向，False = 无方向 |
| 5A | True：`Normalize`（归一化 / Normalize） | `Vector` | 单位 `Vector` | 长度变 1，后面算角度才稳定 |
| 5B | False：`Get Actor Forward Vector` → `Multiply (Vector × Float, B = -1)` | — | 反向单位 `Vector` | 后撤方向 |
| 6 | `Play Anim Montage` / `SelectDodgeMontage` | 方向 | — | 后续步骤 |

> 为什么用 **`Vector Length XY`** 而不是 `Vector Length`：`Vector Length` 含 Z，角色站在斜坡、跳起、被击退时会带 Z 分量，容易把“没按方向”误判成“有方向”。`Vector Length XY` 只看前后左右。

**函数签名（以资产实测为准，别自己加参数）**

工程里已经实现的 `AC_Combat.TryToDodge` 是**无参函数**（`void TryToDodge()`），方向在函数内部取、在函数内部合并，调用方不需要传任何数据：

```
TryToDodge()                                   // 无参数
  ├─ Branch(CanStartDodge())
  │    True → SelectDodgeMontage(MoveDirWorld = Select(…)) → Play Anim Montage → Set bIsDodging
  └─ False → Print String("当前无法进行闪避")
```

- 方向来源：`Get Last Movement Input Vector`（Target = `OwningCharacter`）。
- 死区判断：`Vector Length XY(输入) >= 0.1` → 接到 `Select` 的 **`Pick A`** 引脚。
- `Select` 的输出（世界空间单位向量）只喂一处：`SelectDodgeMontage.MoveDirWorld`；蒙太奇由 `SelectDodgeMontage` 返回后再接 `Play Anim Montage` 的 `Montage` 引脚。
- 调用点：玩家 BP 的 `IA_Sprint` 里 `Started → 拖出自身变量 AC_Combat → 调 TryToDodge`（无参，数据引脚一个都不用接）。

> **不要再给 `TryToDodge` 加 `DodgeInput` 参数**（旧版手册写过“两种签名都行”，那是错的）：签名定成无参后，所有调用点都必须无参。想单独测某个方向，就在函数里临时把 `Get Last Movement Input Vector` 换成 `Make Vector` 常量，测完改回，不要改签名。
>
> **优化（可选）**：如果第 15 课要拿“本次闪避方向”做位移，建议在 `TryToDodge` 里加一个 `DodgeDirection`(Vector) 变量，`Select` 输出先 `Set DodgeDirection`，再把它接 `SelectDodgeMontage` 与 `Launch Character`——这样“方向”只有一个来源，以后改公式不用改两处。

**必须知道的三件事**

1. `Get Last Movement Input Vector` 是“移动意图”的合成结果，**不是速度**，也不是原始轴值（`S_PlayerInputState` 里的 X/Y）。它是世界空间向量，所以**不需要**再乘 Right/Forward——那一步已经由输入系统做完了。
2. 同帧陷阱：按下方向键和按 Shift 在同一帧时，`Get Last Movement Input Vector` 可能还是 0（输入处理顺序）→ 才会出现“偶尔跳成后撤”。这就是 0.1 死区的来源；不是 bug。
3. 顺序不能反：**先判长度、再归一化**。0 向量归一化还是 0，长度判断就失效了。

**自检（不用进 PIE 也能测 §5.4 的方向表）**

| 传入 `DodgeInput` | 期望扇区 | 期望蒙太奇 |
|---|---|---|
| `(0,0,0)` | 后撤分支 | `AM_Dodge_B_180` |
| `(1,0,0)`（角色前向） | 0 | `AM_Dodge_F_0` |
| `(0,1,0)`（角色右向） | 2 | `AM_Dodge_R_90` |
| `(-1,0,0)` | 4 | `AM_Dodge_B_180` |
| `(1,1,0)` 归一化后 | 1 | `AM_Dodge_F_R_45` |

（向量方向按“世界 X 前、Y 右”记；若角色旋转过，用 `Get Actor Forward Vector` 做基准换算，别直接拿世界 X。）

**自检**：PIE 按 W 再点 Shift → 前扑；只点 Shift → 后撤；A/S/D 与四个斜向各自对应正确（八向各试 3 次）。

### 14.2 两个分支怎么合流：为什么 `Branch.False` 不用接执行线

**先记住一条硬规则**：蓝图的 **exec（白线）输入引脚只能接一根线**。所以 `Branch.True` 和 `Branch.False` **不可能同时接到同一个后续节点**——“False 分支没地方接”不是你的错，是这种写法本身合不进去。

**正确做法：exec 只留一条主线，用纯节点 `Select` 合并两条数据**（`Select`，中文「选择」：输入 `A`、`B` 两个候选值 + **`Pick A`** 一个 bool，输出 `Return Value`；`Pick A` 勾上/为真取 `A`，否则取 `B`）。

> **引脚名以资产实测为准**：本项目图里 `Select` 的 bool 输入引脚叫 **`Pick A`**（内部名 `bPickA`），不是旧版手册写的 `Condition`。你拖出 `Select` 节点后看它下半部分的勾选框就是 `Pick A`。

把第 2 个 `Branch` **整个删掉**，改成：

```
CanStartDodge ──Branch(False → Print "当前无法进行闪避")
                  True ↓
        ┌──────────────────────────────────────────────┐
        │ Select (Vector)                              │
        │  Pick A = (Vector Length XY(方向) >= 0.1)     │
        │  A      = Normalize(方向)                     │
        │  B      = GetActorForwardVector × (-1)        │
        └──────────────────────────────────────────────┘
                  │ Return Value（方向）
                  ↓
        SelectDodgeMontage(方向) → Play Anim Montage
```

要点：

- `Select` 是**纯节点**（没有白线），只负责“二选一给个值”，不参与执行流；执行流从 `Branch.True` 直接接 `SelectDodgeMontage` / `Play Anim Montage`。
- `Pick A` 就是那个 `>= 0.1` 的 bool；`A` 接“有输入时的单位向量”，`B` 接“后撤方向”。
- 想更好调试：把 `Select` 的输出先 `Set DodgeDirection`（局部变量），后面几步都读它，PIE 里能直接看到这个值。
- 后撤方向别用“世界 -X”：角色转身后世界 -X 不是背后的方向。用 `Get Actor Forward Vector × (-1)`（`Multiply (Vector × Float)`，B 填 `-1.0`）。

> 如果你坚持用两个 `Branch`：`True` 和 `False` 就必须各自复制一份后续节点（`Set 方向 → SelectDodgeMontage → Play`），两条线各自走完。能用，但节点翻倍、以后改一处要改两处——不推荐。

### 14.3 `Normalize` / `Normalize In Place` 到底怎么用

你截图里的红条 ERROR 来自拖错了节点：**`Normalize In Place (Vector2D)` 是“原地归一化”版本**，它的 `A` 是 **by-ref（按引用传入的变量）**，只能接一个**变量**，不能接计算结果；而且截图里 `A` 根本没接 → 直接红 ERROR。

| 你的输入 | 用哪个节点 | 说明 |
|---|---|---|
| `Vector`（`Get Last Movement Input Vector` 就是它） | **`Normalize`** | A = 向量，Tolerance = `0.0`，`Return Value` = 单位向量 |
| `Vector2D` | **`Normalize 2D`** | 同理，别用 In Place |
| 确实要给变量原地归一 | `Normalize In Place` / `Normalize 2D In Place` | A 接**变量的引用**（拖变量进来），节点返回 bool（是否变了），结果写回那个变量 |

**本项目建议**：全程走 `Vector`（3D）——`Get Last Movement Input Vector` 本来就是 Vector，`Vector Length XY` 只取水平长度用于死区判断，`Normalize` 用 3D 版即可，不要中途换成 Vector2D，否则每换一次都要转换节点，容易接错。

**顺序再确认一遍**：`长度判断（Vector Length XY + >= 0.1）` → `Normalize`。先归一化再判长度，0 向量归一化仍是 0，死区就失效了。

**常见翻车**：`Get Last Movement Input Vector` 在刚按下方向时可能还是 0 → 用“长度 <0.1 就后撤”兜底（本课已含）；索引方向对不上（用 W/A/S/D 四个基准校正）；蒙太奇为空（回第 7 课）；用 `Normalize In Place` 接计算结果 → 红条 ERROR（改用 `Normalize`）。

### 14.4 引脚分两种颜色：白箭头 vs 圆点（为什么 In Place 永远接不上）

蓝图里只有两类引脚，先分清这个，后面所有“接不上”都能自己判断：

| 长什么样 | 叫什么 | 能接什么 | 例子 |
|---|---|---|---|
| **白色三角箭头** | 执行引脚（exec） | **只能接白色三角箭头** | `Branch` 的 True/False、`Play Anim Montage` 的入口 |
| **彩色圆点/菱形** | 数据引脚 | **只能接同类型的数据圆点**（Vector 接 Vector、Float 接 Float、bool 接 bool） | `Normalize` 的 `Return Value`、`Select` 的 `A`/`B` |

**`Normalize In Place` 为什么接不上 `Select`**：In Place 的意思是“**把传进来的那个变量本身改掉**”，所以它：

- 没有“结果输出”圆点（结果写回变量里了，不在引脚上）；
- 它的 `A` 是**输入**（还带着 by-ref 菱形标记），只能接一个**变量**，不能接别的节点算出来的东西；
- 它还带白色 exec 箭头（因为它要改数据，属于“有执行顺序”的节点）。

而 `Select` 的 `A` 要的是**一个向量数据**。所以：`Normalize In Place` 的白色箭头 → 接不进 `Select` 的圆点；它的 `A` 是入口不是出口。**这两个节点天生接不上，不是你操作问题。**

**你要的是纯节点 `Normalize`（不带 In Place、没有白色箭头）**：`A` 是输入、`Return Value` 是输出，输出圆点接 `Select.A` 即可。

**怎么一眼认出来**：拖节点时看它有没有白色箭头。**有白色箭头 = 它参与执行流**；`Normalize`（纯节点）只有圆点、没有白色箭头。

### 14.5 `SelectDodgeMontage` 细讲（节点级，一个不落）

**本课产出**：`AC_Combat` 上多一个数组变量 `DodgeMontageBySector`（8 个闪避蒙太奇），函数 `SelectDodgeMontage(MoveDirWorld : Vector) -> AnimMontage` 能按“输入方向相对角色朝向”的夹角返回对应方向的那一个。

**第 0 步：先把数据放好（不用连线）**

> **先对齐现状（2026-10-22 实测）**：`AC_Combat` 里 `DodgeMontageBySector` 变量**已声明但还没有默认元素**（空数组），`SelectDodgeMontage` 函数**已建成但函数体是空的**（只有入口/返回两个节点，恒返回 `None`）。所以这一步你要做的两件事就是：① 把 8 个元素填进数组；② 把下面第 1–3 步的节点接进 `SelectDodgeMontage`。填完、连完，`Play Anim Montage` 才有东西可播。

`AC_Combat` 新建变量（若已存在就跳过）：

| 变量名 | 类型 | 用途 | 默认值怎么填 |
|---|---|---|---|
| `DodgeMontageBySector` | `TArray<AnimMontage>`（数组） | 0→7 号扇区对应的蒙太奇 | 编译后到组件实例的 Details 面板里按下面的顺序加 8 个元素 |

**数组下标与蒙太奇的对应关系（这个顺序就是“真相”，以后调方向只动这里）**：

| 数组下标 | 角度范围（相对角色正前方） | 蒙太奇 | 按键直觉 |
|---|---|---|---|
| 0 | -22.5° ～ +22.5° | `AM_Dodge_F_0` | W |
| 1 | +22.5° ～ +67.5° | `AM_Dodge_F_R_45` | W+D |
| 2 | +67.5° ～ +112.5° | `AM_Dodge_R_90` | D |
| 3 | +112.5° ～ +157.5° | `AM_Dodge_B_R_45` | D+S |
| 4 | +157.5° ～ ±180° | `AM_Dodge_B_180` | S |
| 5 | -157.5° ～ -112.5° | `AM_Dodge_B_L_45` | S+A |
| 6 | -112.5° ～ -67.5° | `AM_Dodge_L_90` | A |
| 7 | -67.5° ～ -22.5° | `AM_Dodge_F_L_45` | W+A |

（正角度 = 角色右侧，因为 UE 里 Yaw 正向从 +X 转向 +Y，而 +Y 是角色右方。）

**第 1 步：算“方向相对角色的夹角”**

| 顺序 | 节点 | 引脚怎么接 | 类型 |
|---|---|---|---|
| 1 | 函数输入 `MoveDirWorld` | 由 `TryToDodge` 传入；来源是那个 `Select` 的输出：有输入时= `Normalize(Get Last Movement Input Vector)`，无输入时= `-Get Actor Forward Vector`，**两种都是单位向量** | `Vector` |
| 2 | `Get Actor Rotation` | Target = `OwningCharacter` | `Rotator` |
| 3 | `Find Look At Rotation` | **Start 保持默认 `(0,0,0)`**，Target = `MoveDirWorld` | `Rotator` |
| 4 | `Normalized Delta Rotator` | **A = 第 3 步的 Rotator，B = 第 2 步的 Rotator** | `Rotator` |
| 5 | `Break Rotator` | 输入 = 第 4 步输出；只取 `Yaw` | `Float`（-180…180） |

四个坑，一次说清：

- **`Start` 必须是 `(0,0,0)`**，不是角色位置。`Find Look At Rotation` 是“从 Start 看向 Target”的朝向；Start 用原点时，它退化成“这个方向本身的 Yaw”。把 Start 换成角色位置，算出来的就是“角色看向那个点”的朝向，方向感会整个偏掉。
- **A/B 顺序是 A − B**。A=方向、B=角色，得到“方向在角色右边多少度”；接反了会左右镜像（W 正常、D 却播 `L_90`）。
- 用 **`Normalized Delta Rotator`**，不要用 `Delta (Rotator)`。后者不平滑到 ±180°，跨 0° 时会从 179 跳到 -179。
- 角色在斜坡上的 Pitch/Roll 不用管：我们只 `Break` 出 `Yaw`。

**第 2 步：夹角 → 扇区编号（0…7）**

| 顺序 | 节点 | 接法 | 中间值示例（W 时） | 中间值示例（S 时） |
|---|---|---|---|---|
| 6 | `Add (Float)` | `Yaw` + `360.0` | 0 + 360 = 360 | 180 + 360 = 540 |
| 7 | `Fmod` | A = 第 6 步，B = `360.0` | 360 % 360 = 0 | 540 % 360 = 180 |
| 8 | `Add (Float)` | 第 7 步 + `22.5` | 22.5 | 202.5 |
| 9 | `Divide (Float)` | 第 8 步 ÷ `45.0` | 0.5 | 4.5 |
| 10 | `Floor`（向下取整） | 第 9 步 → 整数 | 0 | 4 |
| 11 | `Percent (Integer)` / `%` | 第 10 步 `% 8` | 0 | 4 |

为什么是 `+22.5` 再 `÷45`：每个扇区 45° 宽，方向角落在“扇区中心 ±22.5°”内就算这个扇区。先加半宽（22.5）再除，就等价于“四舍五入到最近的扇区”。`% 8` 是防止 8（360° 附近）冒出来。

**第 3 步：扇区 → 蒙太奇，返回**

| 顺序 | 节点 | 接法 |
|---|---|---|
| 12 | `Get Array Item`（拖出 `DodgeMontageBySector` 后搜 `Get`，选 **`Get (a copy)`**） | Array = `DodgeMontageBySector`，Index = 第 11 步 `Sector` |
| 13 | `Return Node` | 返回值接第 12 步输出 |

`Get Array Item` 是**纯节点**（没有白箭头），所以函数里执行流是“函数入口 → 直接连 Return Node”，中间这些算角度的节点全挂在 Return Node 的数据输入链上。**不要**给它们接白线。

**为什么用数组而不是 `Select` / `Switch`**

| 方案 | 可行性 | 说明 |
|---|---|---|
| `Select` 节点 | ❌ 做不了 8 选 1 | 只有 `Condition` + A/B 两路；要 8 路得嵌 3 层，节点爆炸 |
| `Switch on Int` + 8 个分支 | ⚠️ 能但难写 | 是**执行流**节点，每个分支都得到 Return Node；8 条线容易漏 |
| **数组 + `Get Array Item`** | ✅ 推荐 | 一条数据链、顺序一目了然、以后加“空中闪避/连闪”只要换数组 |

**调试顺序（10 分钟定位一切）**

1. 在 `TryToDodge` 里加 4 个 `Print String`：`MoveDirWorld`、`DeltaYaw`、`Angle01`、`Sector`，再接一个 `Get Array Item` 结果的 `Get Display Name`。
2. 站定不动，只按 W：期望 `MoveDirWorld≈(1,0,0)`、`DeltaYaw≈0`、`Angle01≈0`、`Sector=0`。
3. 四个基准 W / A / S / D 依次试：`DeltaYaw` 应为 0 / -90 / 180 / +90，`Sector` 为 0 / 6 / 4 / 2。
4. **整体平移**（比如 W 播了 `F_R_45`）：说明公式没问题、数组顺序错了，按偏移量挪数组元素，别改公式。
5. **左右镜像**（W 对、D 播 `L_90`）：A/B 接反了，把 `Normalized Delta Rotator` 的两个输入互换。
6. 让角色原地转 90° 再按 W：如果还播 `F_0`，说明用的是**相对角**，正确；如果变成别的方向，说明有节点偷偷用了世界角。

**常见翻车**：`Find Look At Rotation` 的 `Start` 接了角色位置（角度全乱）；`Normalized Delta Rotator` 的 A/B 接反（左右镜像）；用了 `Delta (Rotator)`（跨 0° 跳变）；`MoveDirWorld` 没归一化（角度还凑合，但后续位移长度会不对）；数组只填了 3、4 个元素 → 下标 5/6/7 取到空 → `Play Anim Montage` 静默不播；数组顺序填错（最丢人，因为看起来“都对”）；蒙太奇骨架不是 `SK_UEFN_Mannequin` 或没挂 `DefaultSlot`（回第 7 课）。

**预计**：1h。

### 14.6 闪避永远走 False：按顺序查这 6 个条件（2026-10-22 实测）

`CanStartDodge` 在资产里的实际公式（T3D 读取，不是推测）：

```text
Can = NOT bIsDead
      AND NOT bIsHitStunned
      AND NOT bIsParrying
      AND NOT bIsDodging
      AND NOT bWeaponBusy
      AND IsMovingOnGround(CharacterMovement)
      AND (DodgeChainLeft > 0)
```

**已定位的根因**：`DodgeChainLeft` 虽然声明了，但 `AC_Combat` 与玩家 BP 的 T3D 里**只有 VariableGet、没有任何 VariableSet**，所以它恒为 0 → 最后一项 `DodgeChainLeft > 0` 恒 false → 永远走 False、只打印“当前无法进行闪避”。这不是你接错线，是变量从来没被初始化。

**30 秒验证**：`AC_Combat` → Class Defaults → `Dodge Chain Left` 填 `2` → 编译 → PIE 按 Shift。能进 True 就证明是初始化问题。

**正式写法**（`AC_Combat` → Event Graph → `Event BeginPlay`，接在原有链最前面）：

```text
Event BeginPlay
  → Set DodgeChainLeft = Int( GetCombatParam(Table = DT_Combat, Key = "combat.dodge.chain").Value )
  → Print String( Conv_IntToString(DodgeChainLeft) )     // 自检：应打印 2
  → （原来的 Spawn Weapon On Back 等逻辑保持不变）
```

> `GetCombatParam` 的 `Table` 引脚必须接 `DT_Combat` 资产引用（不能接 DataTable 变量）——这个坑在第 5 课踩过。

**其余 5 项自查**（初始化后若仍 False，按这张表逐个打印）：

| 条件 | 快速验证 |
|---|---|
| `bIsDead` | `Print String(Conv_BoolToString(bIsDead))`；活着应为 false |
| `bIsHitStunned` | 同上；受击硬直结束（§10.5 的 `OnPlayerHitRecover`）后应回 false |
| `bIsParrying` | 招架还没做，应一直 false |
| `bIsDodging` | **成功闪一次后全工程没有地方复位它**（第 17/18 课才做计时器与 `CleanupDodge`）→ 第二次按 Shift 必 False，这是预期现象，不是新 bug |
| `bWeaponBusy` | 装备/卸下蒙太奇结束时必须干净回 false；卡在 true 会同时挡闪避和攻击 |
| `IsMovingOnGround` | 站着应 true；出生下落瞬间、被地形卡住时可能 false，用 `Get Character Movement → Is Moving On Ground` 打印 |

**顺手确认两件事**：

1. **`CanStartDodge` 在图里只被调用了一次**（2026-10-22 逐节点复核过）。实际接线是 `FunctionEntry → CanStartDodge(函数带执行引脚) → Branch.execute`，同时 `CanStartDodge.ReturnValue → Branch.Condition`。读图工具的输出里会看到两遍 `(call CanStartDodge)`（一遍当语句、一遍当 if 条件），那是**渲染假象，不是两个节点，不要照着删**。之所以调用节点自己带 `execute/then`，是因为 `CanStartDodge` 有 `Return Node`、不是纯函数，这是正常写法。
2. `Greater (int)` 节点的 `B` 引脚默认 `0`，保持 0 即可；别改成 2，那会变成“剩余次数 > 2”。

**常见翻车**：以为“走 False 就是输入没接上”——实际 `TryToDodge` 已经被调到了（有 Print 输出就说明输入链是通的），False 只是门禁返回 false；把 `DodgeChainLeft` 的默认值当初始化（Class Defaults 的默认值在打包/新建实例时生效，但本项目组件是 SCS 挂着的，**运行时仍要确认它真是 2**，打印一次最稳）。

**预计**：0.5h。

## 第 15 课 M2-2 闪避位移与碰撞

**目标**：闪避推动胶囊与模型一起移动，距离读数，碰墙不穿墙。

**前置**：第 14 课。

**操作**

1. 先在 `TryToDodge()` 里把“这次闪避的方向”存下来（新增变量 `DodgeDirection : Vector`；`Select` 的输出先 `Set DodgeDirection`，再把它接 `SelectDodgeMontage.MoveDirWorld`）。然后播完蒙太奇后追加：
   ```
   Distance = GetCombatParam(DT_Combat, "combat.dodge.distance")
   Duration = GetCombatParam(DT_Combat, "combat.dodge.iframe")
   Speed    = Distance / Duration
   Launch Character(Target = OwningCharacter, Velocity = DodgeDirection * Speed,
                    bXYOverride = true, bZOverride = false)
   Set Timer by Event(CreateEvent(DodgeMoveStop), Duration, Looping=false) → 返回值存 DodgeMoveStopTimer
   ```
   > 两个容易漏的点：① 新增计时器句柄变量 **`DodgeMoveStopTimer`**（`TimerHandle`），否则后面第 18 课清不掉；② `Speed` 单位是 cm/s，`combat.dodge.distance` 是厘米（400），`combat.dodge.iframe` 是秒（0.3）→ 1333 cm/s，别把距离当米。
2. 事件 `DodgeMoveStop`：`Launch Character(Target = OwningCharacter, Velocity = (0,0,0), bXYOverride = true, bZOverride = false)`（保留 Z，避免闪避中悬空速度被清）。
3. 编译保存，PIE 实测：无输入闪避看位移方向（应为后撤）；按 W 闪避向前；对着墙闪 → 停下不穿墙。

**为什么**

- 位移时长复用 `combat.dodge.iframe` 是本轮定下的决定（规划 §0.6），少一个键，且“位移与无敌同起同止”最直观。
- 用 `LaunchCharacter` 而不是 `AddMovementInput`：后者需要持续 Tick 喂输入，还会被 CMC 摩擦/加速曲线改写距离；`LaunchCharacter` 一次性给速度，距离可预期。
- 必须用 `bXYOverride = true`：否则和玩家当前的移动速度叠加，距离会随是否在跑而变化。

**自检**：平地无方向闪避 → 后撤约 4 米（400cm，允许摩擦误差）；按 W → 前扑；对墙 → 停在墙前；模型与胶囊没有明显分离。

**常见翻车**：`bXYOverride` 忘开 → 距离忽大忽小；位移没在结束/打断时清零 → 角色持续滑行；序列本身带根运动 → 位移翻倍（回第 3 课关根运动）。

**预计**：1h。

## 第 16 课 M2-3 无敌窗口

**目标**：无敌窗口内的近战攻击完全无效（不掉血、不硬直、不打断），窗口外正常受伤；同一次挥击跨窗口结束不补伤害。

**前置**：第 15 课；第 13 课拦截插槽。

**操作**

1. `TryToDodge()` 里加（计时器句柄 `DodgeInvincibleTimer` 第 14 课已建）：
   ```
   bInvincible = true
   Set Timer by Event(CreateEvent(EndInvincible), Duration, Looping=false) → 返回值存 DodgeInvincibleTimer
   ```
   （`Duration` 就是上面算好的 `GetCombatParam(DT_Combat, "combat.dodge.iframe")`，别另外再读一次写死 0.3）
2. 事件 `EndInvincible`：`bInvincible = false`。
3. 把 `AC_Combat.TryDefendAttack` 的桩改成（**实测它现在还是空存根，只返回 None**）：
   ```
   if bInvincible → Print String("Defend: Dodged") → return Dodged
   return None
   ```
   > `bIsDodging` 不用参与判断：无敌窗口由 `bInvincible` 表达，动作期由 `bIsDodging` 表达，两者分开才不会“动作提前结束但无敌还在”时判错。
4. `AC_EnemyAttack.DoAttackHit` 的 Result 分支补上：`Dodged → Print String("Dodged")`（不结算伤害）。**实测：`DoAttackHit` 里 `ResolveDefense → Switch on E_DefenseResult` 已接好，`None` 分支才是结算伤害；你只需补 `Dodged` 分支的打印。**
5. 同一次挥击去重：`DoAttackHit` 里**先**把目标加进 `HitTargetsThisSwing`（`Array Contains` 判过之后、`ResolveDefense` 之前），再做拦截与结算——这样同一挥击在无敌结束后不会再打一次。**实测这条顺序是对的，别改动。**

### 16.1 Step 3 逐节点接法（v1.24 补写 / v1.26 更正位置）

Step 1/2/4 在资产里已经完成，**只剩这一步**（这也是当前唯一挡在第 16 课的东西）。**实现位置（v1.26 更正）**：不是 `AC_Combat`，而是**玩家 BP `SandboxCharacter_CMC` → 左侧「我的蓝图 → 接口」→ `BPI_CombatComponent` → `TryDefendAttack`**（带 `f` 图标的**函数**，不是菱形事件——它带 `DefenseResult` 输出引脚，引擎不允许实现成事件）。原因：敌人 `DoAttackHit` 调 `BPFL_Defense.ResolveDefense`，后者对**被命中对象**做 `DoesImplementInterface` 后调用接口；敌人传入的 Target 是 `Player` 角色，所以真正执行的是玩家 BP 的覆写。`AC_Combat` 里那份同名实现只有「接口被按在组件对象上调用」时才会跑，**本链路不会碰它**（在那张图上改不会生效）。玩家这张图现在有 3 个节点：`函数入口 → Print String("Defend: None") → 函数结果(DefenseResult 默认 None)`。

1. 删掉中间那句 `Print String("Defend: None")`（或把 `In String` 改成 `Defend: Dodged` 留用）。
2. `函数入口` 的 `exec` 接一个 **`Branch`（分支）**；`Condition` 接 **`Get bInvincible`**：先从“组件”面板把 `AC_Combat` 拖进图（玩家 EventGraph 里已有 14 处现成的 `AC_Combat` 引用节点，可直接复制一个），再从它拉出 `Get bInvincible`（`bInvincible` 是组件上的变量，不能当自己的变量直接拖；`Target` 接这个 `AC_Combat` 节点）。
3. `Branch` 的 **`True`** → **`Print String`**，`In String` 填 `Defend: Dodged` → 连到 **函数结果 A** 的 exec；函数结果 A 的 `DefenseResult` ← **`Literal enum E_DefenseResult`** 选 **`Dodged`**。
4. `Branch` 的 **`False`** → **函数结果 B** 的 exec；函数结果 B 的 `DefenseResult` ← `Literal enum E_DefenseResult` 选 **`None`**。
   - 放两个函数结果节点是允许的；若坚持只用一个，就用 `Select` 在数据侧汇合两条枚举，**不要两条线都怼到同一个数据引脚**。
5. 确认原来的 `Print String("Defend: None")` 已删除/停用（它会在每次挨打时刷误导日志）。
6. `Compile` → `Ctrl+Shift+S` 保存。

> **别写第二个判定点**（v1.26 已按实测更正）：现在唯一被调用的判定点是**玩家 BP 的覆写**；`AC_Combat` 里那份同名实现不在调用链上（不是“转发”，实测玩家覆写里没有任何对组件的调用）。如果你更希望把判定集中在组件里，就必须让玩家覆写**显式**调 `AC_Combat → TryDefendAttack(Attacker, bAttackParryable)` 并把返回值接回 `DefenseResult`（见 §16.2 修法 A 后的“可选做法”），两条都改才生效；只改一处 = 不变。

**怎么算接对了**：玩家 BP 的 `TryDefendAttack` 图节点数从 3 变成 ≥5（入口 / 分支 / `AC_Combat`+`bInvincible` / 打印 / `Literal enum` / 结果）；编译无红叉；`DefenseResult` 上能看到来自 `Literal enum` 的连线，而不是还写着 `NewEnumerator0`；`AC_Combat` 里那份仍是 2 节点空桩（**不用改**，改了也走不到；想删掉那条接口实现也可以）。

**自检（接完立刻做，不必等第 23 课）**：
- PIE，站在敌人攻击范围里，等它挥刀、在刀临近命中时按左 Shift 闪避 → 日志应依次出现 `Defend: Dodged`（玩家侧）与 `BeDodged`（敌人侧；Step 4 的打印串资产实测是 `BeDodged`，不是 `Dodged`），**玩家血量不动、不播受击蒙太奇**。
- 不闪避直接挨刀 → 没有 `Defend: Dodged`，正常掉血 + 受击。
- 等闪避动作完全结束（`EndInvincible` 到点）再挨刀 → 正常受伤（证明 `bInvincible` 被复位）。
- 若「怎么砍都不掉血」：查 `CombatGraph` 里 `EndInvincible` 事件是否还在、`Set Timer by Event` 的 `Event` 是否接的 `Create Event(EndInvincible)`、时长是否用的 `Duration`（不是 0）。

**常见翻车**：① 把 `bIsDodging` 也接进条件——无敌看 `bInvincible`，动作期看 `bIsDodging`，混用会在「动作提前结束但无敌还在」时判错；② 忘记 `Literal enum` 节点、下拉保持默认 `None`，True 分支也返回 `None`（打不出 `Dodged`，敌人不进 Dodged 分支）；③ 在「我的蓝图 → 接口」里双击出来的图是函数图，别往里放 `Set Timer`/`Delay`——这一步不需要计时器。

**为什么**

- 无敌是“本次攻击不生效”，不是“回血”。事后回血会照样触发受击/死亡/奖励事件。
- 去重放在拦截之前：A03 要求“同一挥击跨越窗口结束不补伤害”，靠的是攻击侧记录“这一刀已经问过这个目标了”。

**自检**（A03）：让敌人出招，在刀即将命中的窗口内闪避 → 无伤害无硬直；窗口外闪避/不闪 → 正常扣血；故意让无敌在刀命中前结束（调 `combat.dodge.iframe` 很小）→ 仍然会被这一刀打中一次，但**不会**因为同一刀跨帧再打一次。

**常见翻车**：无敌计时器在受击/死亡时没清 → 死后还无敌（第 18 课）；把去重放在结算之后 → 一刀多帧多次结算。

**预计**：0.8h。

### 16.2 2026-10-24 复勘（二）：两个“刹车” bug 的真因（PIE 反馈后定位）

> 用户 PIE 反馈两件事：① 闪避时挨打照样掉血、没有无敌；② 被打一次后“一直处于受击状态”，再也闪避不了。T3D 全链路复核后确认：**两个独立 bug**，都能定位到具体节点。

**Bug A｜闪避没有无敌：判定写在了一张永远不会被调用的图上**

**修法 A（在玩家覆写里直接判，最少改动）**

1. 打开 `SandboxCharacter_CMC` → 我的蓝图 → 接口 → `BPI_CombatComponent` → `TryDefendAttack`。
2. 删掉中间那句 `Print String("Defend: None")`（或把 `In String` 改成 `Defend: Dodged` 留用）。
3. 入口 → `Branch`；`Condition` ← `Get bInvincible`：从“组件”面板把 `AC_Combat` 拖进图（EventGraph 里已有 14 处现成的 `AC_Combat` 引用节点，可直接复制一个），再从它拖出 `Get bInvincible`。

### 16.3 2026-10-24 复勘（三）：`ResolveDefense` 把返回值丢了

**现象**：玩家覆写已能打印 `Defend: Dodged` 并返回 `Dodged`，但闪避中仍受击、掉血，敌人侧从不打印 `BeDodged`（全部日志 0 次命中）。

## 第 17 课 M2-4 连闪与恢复

**状态**：✅ **已完成并验收通过**（用户 2026-10-26 PIE，自述 A04 连闪上限 / 0.85s 恢复 / 0.5s 衔接全部通过）。

**目标**：连闪上限读表（`combat.dodge.chain`），超限被拒；恢复（`combat.dodge.cooldown`）后可再闪；衔接（`combat.dodge.chain_window`）生效。

**前置**：第 14–16 课。

**操作**

1. 在 **`AC_Combat` 组件自己的 EventGraph**（不是玩家 BP `SandboxCharacter_CMC`）里，找到已有的 `Receive Begin Play`，接在原有逻辑后面补一行（**2026-10-26 已落地并随本课验收通过**：此前缺这一行时 `DodgeChainLeft` 恒 0、`CanStartDodge` 恒 false，按 Shift 只会打印“当前无法进行闪避”）：
   ```
   DodgeChainLeft = Int(GetCombatParam(DT_Combat, "combat.dodge.chain"))   // 开局 2 次，不用等恢复
   ```
   > **为什么在组件侧**：`DodgeChainLeft` 是 `AC_Combat` 的变量，`CanStartDodge` / `TryToDodge` / 两个计时器回调也都在组件里；写到玩家 BP 里要先 `Get Component By Class(AC_Combat)` 才能 Set，既绕又可能早于组件 BeginPlay 踩空。玩家 BP 侧不参与这条初始化。不要新建一个叫 `BeginPlay` 的自定义事件来冒充它。

2. `TryToDodge()` 里，播蒙太奇之后：
   ```
   // 衔接窗口：动作期 = chain_window，过后可接下一次动作
   bIsDodging = true
   Clear and Invalidate Timer by Handle(DodgeActionEndTimer)      // 先清旧的，再设新的
   Set Timer by Event(CreateEvent(EndDodgeAction), GetCombatParam(DT_Combat, "combat.dodge.chain_window"), false)
        → 返回值存 DodgeActionEndTimer

   // 消费一次连闪额度（先判能不能再减，避免减成负数）
   DodgeChainLeft = Max(DodgeChainLeft - 1, 0)

   // 每次闪避都重启恢复计时：最后一次闪避结束 0.85s 后补满
   Clear and Invalidate Timer by Handle(DodgeRecoverTimer)
   bDodgeRecovering = true
   Set Timer by Event(CreateEvent(OnDodgeRecovered), GetCombatParam(DT_Combat, "combat.dodge.cooldown"), false)
        → 返回值存 DodgeRecoverTimer
   ```
   > **`Set Timer by Event` 的返回值一定要接进 `DodgeRecoverTimer`**（拖 `Return Value` 存句柄）；否则 `Clear and Invalidate Timer` 永远清的是空句柄，连闪会被提前重置。顺序必须是“先 `Clear` 旧句柄 → 再 `Set` 新计时器”，反了会把刚设的计时器清掉。
3. 事件 `EndDodgeAction`：`bIsDodging = false`。
4. **同样在这张 `AC_Combat` EventGraph 里**新建事件 `OnDodgeRecovered`：`bDodgeRecovering = false`；`DodgeChainLeft = Int(GetCombatParam(DT_Combat, "combat.dodge.chain"))`（补满次数）。
5. `CanStartDodge()` 打印失败原因时区分两种：`DodgeChainLeft == 0` → 打印 `Dodge: no chain`；`bIsDodging` → 打印 `Dodge: busy`。

**为什么这么设计**：只用一个 `DodgeChainLeft` 表达“还能闪几次”，恢复计时到期才补满；“在恢复中”就是“次数为 0”，不需要额外的布尔开关。每次闪避都重启恢复计时，等价于规划里的“最后一次闪避结束后开始恢复计时”——因为最后一次之后没有人再重启它。

**自检**（A04）：连按闪避 3 次 → 第 3 次出现 `Dodge: no chain` 日志；停手约 0.85s 后再按 → 又能闪 2 次；每次闪避间隔小于衔接窗口（0.5s）时按不出来。

**常见翻车**：次数在“闪避成功”和“闪避尝试”两处各减一次 → 少一半次数；恢复计时器不重启 → 连闪中途被提前重置；用 Tick 计时 → 帧率不同结果不同。

**预计**：1h。

### 17.6 复勘（三）：闪避次数不恢复 & 无敌被秒关（2026-10-26 资产实证）

> **来源**：`sync(force=true)` 重采 `AC_Combat`（2026-10-26 16:10:30 保存，1,484,715 B），引脚级还原 `TryToDodge`（55 节点）与 `CombatGraph` 的 `OnDodgeRecovered` / `EndDodgeRecovered` / `EndInvincible` / `DodgeMoveStop`；`DT_Combat` 数值：`combat.dodge.chain=2 次`、`combat.dodge.cooldown=0.85 秒`、`combat.dodge.chain_window=0.5 秒`、`combat.dodge.iframe=0.3 秒`。**未跑 PIE**，结论只基于资产连线。

#### 一、`DodgeChainLeft` 为什么「不恢复」

- 全资产里 `DodgeChainLeft` 只有两类写入：① `ReceiveBeginPlay` 用 `GetCombatParam(DT_Combat, "combat.dodge.chain")` 赋初值；② `TryToDodge` 里 `Max(DodgeChainLeft - 1, 0)` 递减。**没有任何「补回」的写入**。
- `OnDodgeRecovered` 事件体**只有一个节点**：`Set bDodgeRecovering = true`；`EndDodgeRecovered` 也只有 `Set bDodgeRecovering = false`。第 17 课 Step 4 要求的 `Set DodgeChainLeft = Int(GetCombatParam(DT_Combat, "combat.dodge.chain"))` 没有做 → 次数用完后永远是 0。
- 更糟的是：`OnDodgeRecovered` / `EndDodgeRecovered` / `EndInvincible` 在 `TryToDodge` 的链尾被**直接调用**（`Call Function` 调同名 Custom Event），根本没等计时器触发 → 恢复时序被打乱。

#### 二、比「次数不恢复」更早卡死的三处

1. **`bIsDodging` 全资产没有置 false 的地方**：只有 `TryToDodge` 置 true、`CanStartDodge` 读取。而 `CanStartDodge` 含 `NOT bIsDodging` → 闪第一次之后永远 false，表现就是「再也闪不出来」，很容易被误认成「次数没恢复」。第 17 课 Step 2/3 的「动作结束计时器 + `EndDodgeAction` 事件」目前不存在：没有 `DodgeActionEndTimer` 变量，也没有 `EndDodgeAction` 事件。
2. **无敌被自己秒关**：`TryToDodge` 里 `SetTimerByEvent(Delegate = EndInvincible, Time = combat.dodge.chain_window)` 的结果存进了 `DodgeInvincibleTimer`，紧接着下一句 `Clear and Invalidate Timer by Handle(DodgeInvincibleTimer)` 把它清掉；链尾又**直接调用** `EndInvincible`（→ `bInvincible = false`）。等于 `bInvincible = true` 设完立刻被关，闪避全程没有无敌。
3. **恢复计时器用的时长不对**：`SetTimerByEvent(Delegate = OnDodgeRecovered, Time = combat.dodge.chain_window)` 存进 `DodgeRecoverTimer` —— 目标事件是对的（`CreateDelegate` 实证 `SelectedFunctionName="OnDodgeRecovered"`），但时长应该用 `combat.dodge.cooldown`（0.85s）而不是 `chain_window`（0.5s）。

#### 三、按现有节点怎么改（不要重做整张图，只调整这 7 处）

| # | 位置 | 现在 | 改成 |
|---|---|---|---|
| 1 | `TryToDodge` 链尾 | 直接调用 `OnDodgeRecovered` / `EndDodgeRecovered` / `EndInvincible` | **删掉这三个直接调用**，恢复只由计时器触发 |
| 2 | `TryToDodge` 无敌计时器 | `EndInvincible` + `Time = chain_window`，存 `DodgeInvincibleTimer`，随后被 `Clear` | `Time = combat.dodge.iframe`（0.3s），存 `DodgeInvincibleTimer`，**删掉那条 Clear** |
| 3 | `TryToDodge` 动作结束 | 缺失 | `GetCombatParam(combat.dodge.chain_window)`（0.5s）→ `SetTimerByEvent(Event = EndDodgeAction)` → `Set DodgeActionEndTimer`（**新建变量** `DodgeActionEndTimer`，类型 TimerHandle） |
| 4 | `TryToDodge` 递减之后 | 无条件 `bDodgeRecovering = true` + 恢复计时器 | `Set DodgeChainLeft = Max(DodgeChainLeft - 1, 0)` 之后接 `Branch(DodgeChainLeft > 0)`：**True → 本次结束**（还能连闪）；**False →** `Set bDodgeRecovering = true` → `GetCombatParam(combat.dodge.cooldown)`（0.85s）→ `SetTimerByEvent(Event = OnDodgeRecovered)` → `Set DodgeRecoverTimer` |
| 5 | 新建事件 `EndDodgeAction` | 无 | 事件体：`Set bIsDodging = false`（这是第 17 课关键一步，目前完全缺失） |
| 6 | `OnDodgeRecovered` 事件体 | 只有 `Set bDodgeRecovering = true` | 改成：`Set DodgeChainLeft = Int(GetCombatParam(DT_Combat, "combat.dodge.chain"))` → `Set bDodgeRecovering = false` → `Print String("闪避次数已恢复")` |
| 7 | `EndDodgeRecovered` | 只有 `Set bDodgeRecovering = false`，且被直接调用 | 并入 `OnDodgeRecovered` 或直接删掉（避免两处改同一状态） |

> 已经接对、不要动的部分：`DodgeMoveStopTimer` ← `Create Event(DodgeMoveStop)`（`Time = combat.dodge.iframe`）、`DodgeRecoverTimer` ← `Create Event(OnDodgeRecovered)` 这两个委托目标是对的；`DodgeChainLeft` 的 `Max(X-1, 0)` 也是对的。

## 第 18 课 M2-5 退出清理与中断

**目标**：任何异常退出路径都不留无敌、计时器、锁输入、滑行速度。

**前置**：第 14–17 课。

> **v1.32 改写提示**：本课 Step 2 原先按异步 `Play Montage` 节点的 `On Completed` / `On Interrupted` 写法；本项目一直是 `Play Anim Montage` **函数**节点（没有这两个引脚）。函数派请按本课末尾 **§18.3** 收口，Step 2 第一条用 §18.3 的 ① 或 ② 替换。

**操作**

1. `AC_Combat` 新建函数 `CleanupDodge()`（**实测还没有这个函数，要新建**）：用 `Clear and Invalidate Timer by Handle` 清 `DodgeInvincibleTimer`、`DodgeActionEndTimer`、`DodgeMoveStopTimer`（第 15 课新建的那个句柄）；`bInvincible=false`；`bIsDodging=false`；`Launch Character(Target=OwningCharacter, Velocity=(0,0,0), bXYOverride=true, bZOverride=false)`。
   > **注意：不要在这里清 `DodgeRecoverTimer`**。否则被打断一次之后就再也不会补满连闪额度，表现为“挨打后永远只能闪一次”。它只在死亡清理里清（人死了不需要恢复）。
   > 清理顺序建议：先清计时器 → 再清布尔 → 最后停速度（先后无所谓，但三个都要有；只清计时器会让 `bIsDodging` 卡住）。
2. 在以下位置调用它：
   - 闪避蒙太奇结束 / 被打断（**函数节点看 §18.3**；异步 `Play Montage` 节点才是 `On Completed` / `On Interrupted` 两个都接，不接会卡在 `bIsDodging`）；
   - `HandlePlayerHit()`（受击打断闪避，且受击本身已被拦截则不会走这里）；
   - `HandlePlayerDeath()`；
   - `Play Anim Montage` 返回 0（播放失败，打印日志并清理）。
3. 蓄力互斥：**实测 `TryToDodge` 里还没有蓄力判断**，在 `Branch(CanStartDodge)` 之前加 `if bIsCharging → 调 CancelCharge()`（它已经清了计时器、停了 Montage、清了蓄力状态），再进闪避。
4. 同样给招架/反击准备清理函数（下一课用），死亡清理里统一调用 `CleanupAll`（闪避 + 招架 + 反击 + `HitStunTimer`）。

**自检**（A11 的一部分）：蓄力中按闪避 → 蓄力取消且后续松开右键**不**会补一记重击；闪避中被打中（窗口外）→ 之后能正常移动、能再闪；闪避中死亡 → 输入与移动彻底关闭，10 秒后再没有“恢复”发生。

**常见翻车**：只清计时器不清标志位（`bInvincible` 残留）；函数节点上没有 `On Interrupted` 可接，于是没人调 `CleanupDodge`（被打断就卡在 `bIsDodging`，见 §18.3）；死亡后旧计时器回调把输入恢复。

**预计**：0.8h。

### 18.3 函数节点（`Play Anim Montage`）怎么收口

`Play Anim Montage` 是普通函数，播完不会回调；异步 `Play Montage` 节点才有 `On Completed` / `On Interrupted`。函数派用下面两种方式之一（推荐 ①，第 17 课已有计时器可直接复用）：

**① 复用第 17 课的计时器（最省事，本项目默认）**

- `EndDodgeAction` 事件里已经置 `bIsDodging=false`，在它后面接 `CleanupDodge()` ——「闪避动作结束」就以这个 `combat.dodge.chain_window`（0.5s）收口点为准。
- 被打断的路径由显式调用点兜住：`HandlePlayerHit()`（受击）、`HandlePlayerDeath()`；攻击/蓄力入口的互斥见 Step 3。
- 优点：零新节点；缺点：清理时点由计时器决定，不是蒙太奇真实长度。

**② 绑 AnimInstance 的蒙太奇结束委托（最接近异步节点语义）**

- `Get Anim Instance`（玩家 Character → `Get Mesh` → `Get Anim Instance`）→ `Bind Event to On Montage Ended`。引擎侧依据：`UAnimInstance::OnMontageEnded` 是 `UPROPERTY(BlueprintAssignable)`，见 `Runtime/Engine/Classes/Animation/AnimInstance.h:756`。
- 回调节点参数：`Montage`（UAnimMontage）与 `bInterrupted`（bool）。正常播完 = false；被顶掉 / `Montage Stop` / 受击打断 = true。
- 回调里：`Branch(Get bIsDodging)`（或比较 `Montage == CurrentDodgeMontage`）→ `CleanupDodge()`。**要过滤**，否则攻击/受击蒙太奇结束也会清掉闪避状态。
- 绑定放在 `AC_Combat` 的 `ReceiveBeginPlay`（`Get Owner → Get Mesh → Get Anim Instance → Bind Event to On Montage Ended`）；Character 销毁时 AnimInstance 一起销毁，无需解绑。
- 优点：时点精确；缺点：多一个委托概念、要记得过滤。

**两种播放节点在本项目里的分布**（别以为自己接错了）：

- 玩家 `SandboxCharacter_CMC`：闪避/攻击/受击蒙太奇全部是 `Play Anim Montage` 函数，图里没有任何异步 `Play Montage` 节点。
- `AC_Combat`：只有「武器装备/卸下」两处用了异步 `Play Montage`（`EventGraph.K2Node_PlayMontage_0/_1`），所以那里确实有 `On Completed` 等引脚。
- `AC_EnemyAttack`：攻击蒙太奇用的是异步 `Play Montage`（`EventGraph.K2Node_PlayMontage_0`），所以 §12.1 的 `On Completed / On Interrupted → bAttacking=false` 对敌人成立。

**§18.3 常见翻车**：在函数节点上找 `On Completed`（找不到，见本节）；② 里忘过滤，攻击蒙太奇播完把闪避状态清掉；① 里只挂计时器、没兜住受击与死亡这两种打断。

## 第 19 课 M3-1 招架窗口与蒙太奇

> **v1.32 提示**：本课 Step 5 的「蒙太奇 `On Completed`」同样只适用于异步 `Play Montage` 节点；函数派请用 §18.3 的 ①/②（招架结束用 AnimInstance `On Montage Ended` 或计时器收口，回调里 `bIsParrying=false` + `CleanupParry()`）。

**目标**：按侧键 1 播招架动作，判定窗口 0.22s 只开一次；按住/连按不会刷新；落空进 0.45s 冷却。

**前置**：第 7 课招架蒙太奇；第 4 课招架键；第 18 课清理模式。

**操作**

1. `AC_Combat` 新建函数 `TryParry()`：
   ```
   if bIsDead || bIsHitStunned || bIsDodging || bIsParrying || bParryCooldown || bWeaponBusy → return
   if bParryWindowActive → return                       // 连按不刷新
   bIsParrying = true
   bParryWindowActive = true
   播 AM_Parry_L（先固定左；成功后第 20 课再按方向换）
   Set Timer by Event(CreateEvent(EndParryWindow), GetCombatParam("combat.parry.window"), false)
   ```
2. 事件 `EndParryWindow`：`bParryWindowActive = false`；若本次**没有**招架成功（用 `bParrySucceededThisAttempt` 标记）→ `bParryCooldown = true`；`Set Timer by Event(EndParryCooldown, GetCombatParam("combat.parry.cooldown"), false)`。
3. 事件 `EndParryCooldown`：`bParryCooldown = false`。
4. 第 4 课的侧键 1 / V 的 `Print String` 换成 `Call TryParry`。
5. 招架动作结束（蒙太奇 `On Completed`）→ `bIsParrying = false`；`CleanupParry()`（清窗口计时、`bParryWindowActive=false`）。招架动作期间输入锁定由 `ANS_InputDisabled` 自动恢复。
6. 编译保存，PIE：按侧键 → 播招架；窗口内连按 → 无第二次动作；落空后 0.45s 内按 → 无反应。

**为什么**：窗口是“点按后的有限时间”，不是“按住一直有效”。只有 `Pressed` 事件 + 一个短计时才能同时满足“点按触发”“按住不刷新”“连按不刷新”。

**自检**：招架动作播得出来；连按 5 次只播一次；日志能看出窗口开/关与冷却。

**常见翻车**：用 `InputKey Released` 或触发重复按键的事件 → 按住也会反复开窗；窗口计时器没清 → 冷却判定错乱。

**预计**：1h。

## 第 20 课 M3-2 招架判定

**目标**：只有“窗口内 + 正面 ±60° + 可招架攻击”才成功，四种非法条件全部失败。

**前置**：第 19 课；第 13 课拦截插槽。

**操作**

1. `AC_Combat.TryDefendAttack` 完善成：
   ```
   if bInvincible → return Dodged

   if bParryWindowActive && bAttackParryable:
       WorldDir = Normalize(Attacker位置 - OwningCharacter位置)
       LocalDir = Inverse Transform Direction(WorldDir, OwningCharacter 世界旋转)
       Dot = Dot Product(LocalDir, (1,0,0))                 // 角色前向
       Angle = GetCombatParam(DT_Combat, "combat.parry.front_angle")   // 半角，度；Table 引脚必须接 DT_Combat
       if Dot >= Cos(Degrees To Radians(Angle)):
           // 命中正面：按左右选招架动作（可选，好看）
           若 LocalDir.Y > 0 → 重播 AM_Parry_R，否则 AM_Parry_L
           bParrySucceededThisAttempt = true
           return Parried
   return None
   ```
2. 敌人侧 `AC_EnemyAttack.DoAttackHit` 的 `Parried` 分支（第 21 课细做）：先打日志 `Defend: Parried`。
3. PIE 验证四种失败：过早按（窗口外命中）、过晚按（刀已过）、背后攻击（把玩家转身背对）、不可招架攻击（把 `bNextAttackParryable` 关掉）。

**为什么**

- 用点积比“算角度扇区”稳：不用处理 0/360 跨界。
- 招架只挡“正面”意味着游戏想让你面向威胁，这也是范围规则（规划 §2）。
- `bAttackParryable` 由攻击方传入，保证“明确标记可招架”这条规则落在攻击定义上，而不是靠伤害类型猜。

**自检**（A06/A07）：正面窗口内 → 玩家不掉血、日志 `Parried`；四种非法 → 正常受伤且无反击资格；背后攻击即使窗口内也失败。

**常见翻车**：把 `Cos` 算成角度、把度当弧度 → 判定范围全错；用 2D 距离不做归一化 → 远距离也能招架；窗口结束没关 `bParryWindowActive` → 冷却后仍可招架。

**预计**：1h。

## 附录 C 翻车清单（22 条）

1. GAS 组件漏挂属性集 → 打不掉血、无敌、**不报错**。
2. 先设 `Health` 后设 `MaxHealth` → 当前值被旧上限夹掉。
3. `GetCombatParam` 的 `Table` 引脚接变量 → 编译不过或取空表；必须硬引用 DataTable 资产。
4. Key 拼错 → 静默返回 0。
5. 导入 DataTable 时编辑器开着 → 稍后编辑器保存把旧表写回，键消失。**先关编辑器再跑管道**。
6. 蒙太奇 Slot 不是玩家 AnimBP 里的 Slot → 不播。
7. 方向数组越界/蒙太奇为空 → 不播、不报错。
8. 序列根运动 + 受控位移 → 位移翻倍或回弹。
9. 用“事后补血”当无敌 → 受击/死亡/奖励事件照发。
10. 计时器在死亡/打断时不清 → 死后恢复输入、永久无敌。
11. 用 Tick 数帧做窗口 → 30/60/120FPS 行为不一致。
12. 带输出参数的接口函数当事件用 → 找不到事件节点（它是函数）。
13. 自定义事件不能跨蓝图调用 → 跨对象用**函数**或**接口消息**。
14. 敌人攻击不去重 → 同一刀多帧多次结算。
15. 招架成功没停敌人 Montage → 敌人继续播完这一刀。
16. 改了 `Docs/阶段一可执行计划/阶段一Demo排期与执行计划.md` 忘记重跑 `_build_docx.ps1` → .md/.docx 不同源。
17. 在**函数图**里直接拖事件图表的 Custom Event 到 `Set Timer by Event` 的 `Event` 引脚 → 拖不动（事件节点只能活在事件图）；用 `Create Event` 节点引用它。
18. 「Montage Stop」有三个同名节点：Target=**Anim Instance**（本项目用这个）、Target=**Character**（`Stop Anim Montage`，最省事）、Target=**Gameplay Ability**（GAS 技能节点，在 `AC_Combat`/角色 BP 里红条 ERROR）。看节点副标题区分。
19. `DoAttackHit` 守卫写成 `if (bAttacking OR bIsParryStunned) → return` → 播蒙太奇前已把 `bAttacking` 置 true，Notify 触发时必然返回，Print/检测/伤害全在 `else` 里 → **无 Print、无球、不掉血、不报错**。正确：`if (NOT bAttacking OR bIsParryStunned) → return`。
20. 把检测节点的 `Return Value`（bool）接到 `Array Contains.Item to Find` / `Array Add.New Item` / 对目标造成伤害.`Target` → 类型不匹配，`Array Add` 红条编译错误，PIE 跑旧版本（改了像没改）。正确：`Out Hit → Break Hit Result → Hit Actor` 后再接。
21. 敌人只判距离不判目标死活 → 玩家死后继续出招（鞭尸）。在 `AttackLoop` 与 `DoAttackHit` 里各读一次目标的 `bIsDead`（`Get Component By Class` → `Is Valid` → `Get bIsDead`，见 §12.2.4）。
22. 日志刷「尝试读取非UClass中的(real)属性 CallFunc_…_结果为无」但功能正常 → 纯节点链（`Break Hit Result → Hit Actor → Get Component By Class → Get bIsDead`）在**没命中**时也被求值，空对象被读属性。修法：`Branch(追踪 Return Value)` → `Is Valid(Hit Actor)` → `Is Valid(组件)` 逐级确认后再读 `bIsDead`（见 §12.2.5）。

### G.3 新增功能时必须做的 5 步（反查法）

1. **登记**：把新状态写进 G.4 状态登记表（在哪置 true、在哪置 false、哪些门必须检查、漏了的表现）。
2. **反查**：拿新状态逐个过 G.2 每一行，问「这个门要不要加它？」要加就当场改，不要留到以后再补。
3. **对称**：玩家侧加的守卫，敌人侧有没有同类入口？敌人加的，玩家侧有没有？两边只在有理由时才不对称，并写明理由。
4. **死亡**：新状态在死亡时怎么清？加进 `CleanupAll` / 敌人死亡清理；并且检查所有「每 N 秒循环」的计时器有没有死亡清理。
5. **回归**：按 G.5 跑一遍，重点三个场景——死后、受击后、闪避中。

### G.5 合并前回归清单（5 条，约 10 分钟）

1. **死后 10 秒**：逐键无反应、敌方不再出招、无残留无敌、无「输入被还回来」。
2. **受击一次后**：能恢复、能再闪、能再攻击（复位类症状）。
3. **闪避中挨刀**：只出现 `Defend: Dodged` + `BeDodged`，不掉血不硬直，且能继续闪。
4. **同一挥击跨窗口**：不补伤害（去重仍在拦截之前）。
5. **Output Log 过滤「尝试读取」= 0 条**（空对象读属性）。
