### 0.5 架构决策（v2 定稿，实施不得偏离）

1. **防御拦截位置**：在攻击方**施加伤害之前**，由攻击方调用目标的 `TryDefendAttack`，返回 `None` 才结算伤害（节点为「对目标造成伤害」/`ApplyDamageToTarget`）。禁止“事后补血”。本轮只把拦截接在敌人攻击路径上（玩家攻击 NPC 时 NPC 不防御），接口位保留。
2. **接口扩展**：`BPI_CombatComponent` 新增 1 个函数 `TryDefendAttack(Attacker: Actor, bAttackParryable: bool, out DefenseResult: E_DefenseResult)`；新增枚举 `E_DefenseResult`（`None` / `Dodged` / `Parried`）。接口函数的实际执行者只有 `SandboxCharacter_CMC`，它转发给 `AC_Combat`。
3. **练习敌人攻击入口**：新建组件 `AC_EnemyAttack` 挂 `BP_MasterNPC`：定时出招 → 播攻击 Montage → 命中窗口做一次前方球体检测 → 调 `TryDefendAttack` → 未防御才施加伤害；被招架时停 Montage 并调 `AC_NPC.ApplyHitReaction(bFromParry=true)`。
4. **位移驱动**：首版用**受控位移**（`LaunchCharacter`），位移时长 = `combat.dodge.iframe`，水平速度 = 闪避距离 / 时长。**闪避序列根运动已于 2026-10-20 编辑器核实为“未启用”，受控位移方案成立**（见 §0.7 第 7 项），无需额外改序列。
5. **计时口径**：窗口 / 冷却 / 资格全部用 `SetTimer`（游戏时间），不用固定帧数；首轮关闭顿帧与慢动作。
6. **Montage 约定**：玩家动作 Slot 统一 `DefaultSlot`；输入禁用复用 `ANS_InputDisabled`，武器检测复用 `ANS_WeaponTrace`；无敌与招架窗口**不用 NotifyState**，改用 `SetTimer` + 数据键（单一数值源，见 0.4 第 5 项）。
7. **硬直取数隔离**：`combat.enemy.parry_stun` 只用于招架；普通大硬直改读 `combat.enemy.hitstun_large`（修 P0）；杀生之影覆盖 `enemy.shadow.parry_stun` 走敌人侧覆盖分支。三条分支必须能各自独立调参（对应 A14）。
8. **反击伤害**：首版复用 `combat.dmg.heavy`，并记录为临时复用项；新键在 M5 之后另行评估。
9. **计时器回调的绑定方式（2026-10-20 实施中确认）**：所有计时器回调（`EndInvincible` / `EndDodgeAction` / `OnDodgeRecovered` / `EndParryWindow` / `EndParryCooldown` / `EndCounterWindow` / `OnPlayerHitRecover` / `EndParryStun` / `DodgeMoveStop`）做成**事件图表里的 Custom Event 且必须无参**；在**函数图**里设置 `Set Timer by Event` 时，`Event` 引脚必须接 `Create Event` 节点引用该事件（事件节点不能放进函数图，也不能直接拖入函数图引脚）。依据：`K2_SetTimerDelegate` 的委托为无参 `FTimerDynamicDelegate`（`Runtime/Engine/Classes/Kismet/KismetSystemLibrary.h:727`，`:731` 注释 “Event Can be a K2 function or a Custom Event”）；`K2_SetTimerForNextTick` 对带参回调打警告并返回空 Handle（`Runtime/Engine/Private/KismetSystemLibrary.cpp:689-709`）。
10. **节点称谓（2026-10-20 实施中确认）**：`GASCombatBridge` 是引擎 Marketplace 二进制插件（`E:\UE_5.7\Engine\Plugins\Marketplace\GASCombatBridge`，v1.1.0，无源码、带本地化），蓝图调色板**只显示中文显示名**，按 C++ 内部名搜不到。本规划与手册统一写「中文显示名（`内部名`）」。对照：对目标造成伤害=`ApplyDamageToTarget`、施加效果=`ApplyEffectWithValues`、按名字设置属性基础值=`SetAttributeBaseValueByName`、添加属性集=`AddAttributeSet`、取消所有技能=`CancelAllAbilities`、播放表现=`PlayGameplayCue`；事件：受到伤害时=`GASCombatOnDamageTaken`、生命归零=`GASCombatOnDeath`、战斗初始化完成=`GASCombatOnCombatReady`。引脚名仍是英文（`Source`/`Target`/`DamageEffectClass`/`DamageAmount`/`Level`/`EffectCauser`）。
11. **门禁三处同时生效（2026-10-21 实测故障后定稿）**：① **调用目标**——`CallSetMovementEnabled` / `CallSetInputEnabled` / `CallWeaponTrace` 一律 `Cast To BPI_CombatComponent(OwningCharacter)` 后再调，**不能直接调 `AC_Combat` 自己**：组件里的 `CallSetMovementEnabled` 是空实现、`CallSetInputEnabled` 只翻转组件自身 `InputEnabled` 布尔（供 `ANS_InputDisabled` 用），玩家 `IA_Move` 真正读的是玩家 BP 的 `MovementEnabled`；② **入口守卫**——攻击/闪避/招架输入事件与 `LightAttack` 等动作函数入口都必须自行判 `bIsDead`（硬直期再判 `bIsHitStunned`），只在恢复回调里判死亡挡不住死亡后出招；③ **清理**——死亡时清空所有状态计时器，且任何恢复路径不得使用 `Delay` 等无法取消的 latent 节点。对应 §5.3 与教学手册 §10.9。

## 2. 本轮范围与首版规则

| 项目 | 首版规则 |
|---|---|
| 闪避方向 | 地面八方向；按下时采样移动输入并确定方向；无输入默认后撤 |
| 位移与碰撞 | 角色胶囊和模型同步位移；保留场景碰撞，碰墙停止或受阻，不穿墙 |
| 闪避保护 | 只有无敌窗口内免受本轮近战攻击的伤害与硬直，前后仍可受击 |
| 连闪 | 次数上限读表；最后一次闪避结束后开始恢复计时，下一次合法连闪重启该计时；计时到期重置次数。动作中的衔接时刻由连闪窗口控制 |

| 招架失败 | 过早、过晚、背后攻击、不可招架攻击均正常结算伤害；落空进入招架冷却 |
| 招架成功 | 本次攻击失效；关闭攻击者当前攻击检测，令攻击者硬直；发送一次成功事件，授予一次反击资格 |
| 招架反击 | 成功后记录攻击者，在资格有效期内按左键发动专用反击；不按则到期失效；发动时消费资格，挥空不返还 |
| 反击目标 | 以本次被招架的攻击者为目标；发动前验证存活与可达范围；伤害仍由真实命中判定，不隔空扣血、不穿墙追击 |
| 动作限制 | 首版仅地面；死亡、受击硬直、装备切换期间不能启动闪避或招架 |
| 攻击衔接 | 蓄力允许被闪避取消；普通攻击仅在指定取消窗口允许转闪避或招架；反击未设置额外无敌待遇 |
| 范围边界 | 单机、一名近战练习敌人。完整敌人 AI、处决、空中防御和复杂特效不作为本轮完成条件 |

键位（v2 已核实）：招架沿用鼠标侧键 1，V 备用——两者当前**均未绑定**，且 `AC_Combat` 现有输入本身就是传统 `InputKey`，直接加事件即可，不改 IMC。闪避规划使用左 Shift，它与 `IA_Sprint`（按住奔跑）是唯一真冲突，M0 必须在下面两个方案中定稿并实测：

- **方案 A（手感优先，默认按此排步骤）**：按下左 Shift 立即闪避；按住超过 0.15s 再写入奔跑状态（现有 `IA_Sprint` 分支整体后移）。代价：起跑会先闪一下。
- **方案 B（零误触，判定延迟）**：按下后计时 0.12s，未松开=奔跑，松开=闪避。代价：闪避动作晚 0.12s 触发。

左 Alt 已用于装备，不直接复用。招架反击复用左键，只有合法反击资格时才进入专用分支。两方案的具体改法与实测方法见[教学手册](角色闪避与招架反击教学手册.md)第 4 课。

## 5. 实现必须满足的结构要求

### 5.1 防御先于扣血

统一处理顺序：命中候选 → 本次攻击是否已处理 → 闪避判定 → 招架判定 → 普通伤害与受击。

防御成功必须在施加伤害之前拦截。不要在伤害事件发生后通过补回血模拟无敌或招架，否则已发出的受击、死亡及奖励事件会产生错误副作用。

### 5.2 一次攻击只产生一次结果

同一次攻击对同一目标只结算一次。成功闪避、成功招架、正常受伤都需要记录结果；持续多帧的同一挥击不能在保护窗口结束后再次扣血。未来明确设计的多段攻击应使用不同段标识。

### 5.3 所有退出路径都清理状态

正常结束、受击打断、死亡、播放失败都必须清理该动作拥有的无敌状态、判定窗口、计时器和武器检测。恢复控制时检查当前状态，死亡角色不能因旧动作回调重新获得移动或攻击能力。

**死亡门禁要覆盖三条线，缺一条就会“死后还能动/打”（2026-10-21 实测）**：① 输入入口（左键/重击/侧键/闪避/招架事件与动作函数入口）自行判 `bIsDead`，不能只靠恢复回调；② 控制开关必须打到玩家接口（`Cast To BPI_CombatComponent(OwningCharacter)`），直接调组件自己是空实现；③ 状态计时器在死亡时清空，且恢复路径不得使用 `Delay` 等不可取消的 latent 节点。详见 §0.5 第 11 条与教学手册 §10.9。

取消蓄力时，处理蓄力计时器、暂停的 Montage、伤害数据及检测窗口；后续松开右键不能额外补出一击。输入缓冲必须有消费与清除规则，避免旧输入在状态恢复时意外触发。

Montage 完成与中断回调可用于组织清理，参见 [Epic Play Montage 文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/BlueprintAPI/Animation/Montage/PlayMontage)。具体接线需按项目 UE 5.7.4 验证。

### 5.4 位移只选定一种驱动方式

先检查素材是否具有可用根运动，再决定采用动画根运动或受控角色位移。避免动画位移与额外推动叠加。验收时同时观察模型与胶囊，参考 [Epic Root Motion 文档](https://dev.epicgames.com/documentation/unreal-engine/root-motion-in-unreal-engine?lang=en-US)。

### 5.5 时间与反馈分离

窗口和冷却以明确的游戏时间计时，不使用固定帧数作为逻辑时长。M0 记录窗口起点、终点及边界包含规则。首轮判定验证关闭顿帧与慢动作，基础通过后再检查反馈效果不会改变规则。

## 9. 后续反馈层（M6，不在本轮 A01–A14 验收内）

用户 2026-10-20 提问“闪避/招架成功后应有慢放特写类反馈，是否本轮做”。**本轮不做**，原因是 §5.5 与 §0.5 第 5 条已明确“首轮判定验证关闭顿帧与慢动作”：

- 慢动作 / 顿帧本质是**改变游戏时间**，会同时影响 `combat.dodge.iframe`(0.30s)、`combat.parry.window`(0.22s)、`combat.dodge.cooldown`(0.85s) 与全部 `SetTimer` 的边界；在判定尚未稳定前引入，会让 A03/A04/A06/A08 的失败无法区分“判定错”还是“时间被缩放”。
- 镜头特写依赖战斗状态机稳定（闪避/招架/受击/死亡互相打断），否则容易出现“镜头推近中被打死卡住”“输入被锁死”。
- A06 只要求“成功反馈一次”，本轮把它实现为**成功事件出口**（供后续表现层订阅），不做表现。

### 9.1 反馈层内容与顺序（M5 全部通过后再做）

1. **统一成功事件出口**：招架成功 / 极限闪避 / 反击命中各发一次事件（带攻击者、方向、位置），表现层只订阅事件，不写回判定状态。
2. **顿帧 HitStop**：命中瞬间 0.03–0.06s 局部时间冻结（攻击者+目标或短暂全局膨胀），先做这个，成本最低、手感收益最大。
3. **慢动作**：招架成功 0.15–0.3s 时间膨胀；实现上优先范围可控的局部方案，避免影响仍在跑的计时器与后续判定。
4. **镜头特写**：`Camera`/`SpringArm` 拉近 + FOV 变化 + 目标锁定（依赖角色相机组件，当前 `Camera` 组件 `NotUsedByDefault`，需先接入）；结束后必须复位并解锁输入，属于可选高成本项。
5. **特效 / 音效 / 屏幕震动**：Niagara + Sound + 相机抖动，挂在第 1 条的事件上。

### 9.2 反馈层验收（新增，不改变原判定口径）

加任何反馈后回归 A03、A06、A07、A09、A11 必须结论不变（免伤/招架成功/失败不奖励/资格一次/无残留状态），并新增记录：反馈时长、镜头是否复位、输入是否解锁、死亡打断时是否卡镜头。反馈层失败不得回退为“判定也一起放宽”。
