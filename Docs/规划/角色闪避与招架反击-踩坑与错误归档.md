# 角色闪避与招架反击 · 踩坑与错误归档

**文档版本**：v1.0（2026-10-29 从手册 v1.54 拆出） ｜ **状态**：活文档，遇到新坑就追加
**读者**：项目作者本人；排查问题时按「现象」检索
**正解所在**：`Docs/规划/角色闪避与招架反击教学手册.md`（下称「手册」）——本册只管「踩过什么」，**怎么接才对一律看手册**

> **用途**：本册收录 2026-10 做起防御/闪避/招架/反击以来**踩过的每一个坑、被推翻的错误写法、事故复盘、报错排查过程**。它的价值在检索：卡住时按现象关键词搜，找到根因和判据，再跳到手册对应课节改正解。
>
> **为什么不写进手册**：教学手册的用途是「照着做」，错误档案的用途是「遇到问题先查」。混在一起会让人分不清「该连哪根线」和「上次为什么连错」。

## 怎么用这本册子

1. **按现象搜**：`Ctrl+F` 搜屏幕上看到的东西——报错原文片段、打印内容、动作表现（「不出反击」「站桩」「掉血」「卡住」）。
2. **每条五段**：现象（你能看到的） → 根因（机制层面） → 正解（一句话 + 手册落点） → 判据（改完怎么确认） → 出自（日期/版本，便于回查）。
3. **改完回手册**：本册不给操作步骤，只给方向；具体怎么连线看手册对应 §。

## 主题：输入与键位


### K001 点按一次左 Shift 却打了两次 Dodge
- **主题**：输入与键位
- **现象**：PIE 里轻点左 Shift，Output Log 出现两条 `Dodge`。
- **根因**：`IA_Sprint` 的 `Started` 与 `Triggered` 都接了 `Print String`（数字动作按下时两个引脚各触发一次）；或是打印被复制到了 `OnSprintHoldElapsed` 里，或 `Completed` 上也接了打印。
- **正解**：只留 `Started` 接闪避；`Completed` 只接“清计时器 + `Set bSprintCommitted=false`”，不接闪避；`OnSprintHoldElapsed` 只写 `bSprintCommitted` 与奔跑状态。见手册 §4.2。
- **判据**：把日志文本改成带来源的 `Dodge@Started` / `Dodge@Completed` / `TimerReached`，一次点按只出现一条 `Dodge@Started`；再重跑四种手势（点按、长按、点按后立刻走动、按住中被打断）。
- **出自**：源手册 v1.54

### K002 松开左 Shift 后，下一次点按直接被带进奔跑
- **主题**：输入与键位
- **现象**：按住左 Shift 跑过一段，松手后再轻点左 Shift，角色没闪避而是直接开始跑。
- **根因**：`Completed` 引脚没接 `Clear and Invalidate Timer by Handle`，`SprintHoldTimer` 仍在计时；下一次点按进来后旧计时器先到点，把 `bSprintCommitted` 置 true 并接进奔跑逻辑。
- **正解**：`IA_Sprint.Completed` 接 `Clear and Invalidate Timer by Handle`（Handle = `SprintHoldTimer`）+ `Set bSprintCommitted = false`，再接原来的停跑逻辑。见手册 §4.2。
- **判据**：按住 1 秒松开 → 立刻轻点 → 出闪避动作而不是奔跑；点按/长按交替 10 次行为一致。
- **出自**：源手册 v1.54

### K003 死亡后还能装备/卸下武器
- **主题**：输入与键位 / 守卫与死亡清理
- **现象**：玩家 `bIsDead=true` 后按左 Alt 仍能切换武器。
- **根因**：装备/卸下走的是 `AC_Combat` 的 `EventGraph` 里那个 `InputKey`（左 Alt）事件，它不属于 `CombatGraph`；死亡门禁只加在攻击链上，这个事件没有。
- **正解**：在这个 `InputKey` 事件最前面加 `Branch(NOT bIsDead)`；侧键 1/2、V 与 `F1–F4` 调试键同样在事件第一行加。见手册 §10.9。
- **判据**：死亡后逐个按 左键 / 右键 / 左 Alt / 侧键 1 / 侧键 2 / V / `F1–F4` → 全部无反应。
- **出自**：2026-10-21

### K004 死亡后还能转视角，人物模型也跟着转
- **主题**：输入与键位 / 守卫与死亡清理
- **现象**：死亡后鼠标一动镜头还在转，角色模型跟着 Controller 一起转向。
- **根因**：`IA_Look` / `IA_Look_Gamepad` → `AddControllerYawInput` / `AddControllerPitchInput` 全程没有任何门禁，直接改 Controller 的 Yaw/Pitch；而角色身体在 `bUseControllerDesiredRotation` 打开时跟随 Controller 朝向，所以镜头一动模型就转。只关角色朝向无效。
- **正解**：在这两个事件的最前面加门禁：`Get Component By Class(Class = AC_Combat) → Get bIsDead → NOT Boolean → Branch`，True 直接断开；只拦 yaw 那一头就同时拦住俯仰（`AddControllerYawInput` 的 exec 还链着 `AddControllerPitchInput`），手柄那条要加在 `Promotable Operator` 运算之前。见手册 §10.9、§11.1。
- **判据**：死亡后鼠标上下左右 + 手柄右摇杆 → 镜头不动、模型不转；活着时视角正常；死亡后其余按键仍全部无反应。
- **出自**：2026-10-21

### K005 蒙太奇播不出来，或受击动作刚起就被动画蓝图抢回
- **主题**：动画与蒙太奇

## 主题：伤害与防御链路


### K011 直接减 Health，掉血了但什么反应都没有
- **主题**：伤害与防御链路
- **现象**：血量掉了，但没有受击动作、没有硬直、血量到 0 也不触发死亡。
- **根因**：用 `SetAttributeBaseValueByName("Health")` 直接改属性，一次绕过属性集的四个功能：护盾、夹取、广播受击、判断死亡。
- **正解**：伤害统一走 `GE_Damage`（`Data.Damage` SetByCaller），用「对目标造成伤害」（`ApplyDamageToTarget`）。见手册 §10.1。
- **判据**：掉血同时出现受击蒙太奇与硬直；血量到 0 触发 `GASCombatOnDeath`。
- **出自**：源手册 v1.54

### K012 挨打掉血但不播受击动作
- **主题**：伤害与防御链路
- **现象**：按 T 测试掉血正常，`AM_PlayerHit_*` 一个都不播。
- **根因**：「受到伤害时」事件没绑，或绑成了 AttributeSet 的数值监听器（数值变化也会触发，语义不同）。
- **正解**：绑 `GASCombatOnDamageTaken`（战斗语义），不要绑属性监听器。见手册 §10.6。
- **判据**：掉血的同时播 `AM_PlayerHit_*`，且方向随攻击者位置变化。
- **出自**：源手册 v1.54

### K013 在受击函数里判无敌，或扣完血再把血加回来
- **主题**：伤害与防御链路
- **现象**：无敌窗口内血量先掉又补回来；闪避中被打仍然进受击动作。
- **根因**：把“这一下算不算”放进了受击兜底里，而不是由攻击方在结算伤害**之前**问目标。
- **正解**：攻击方在 `对目标造成伤害` 之前先调 `ResolveDefense` → `BPI_CombatComponent.TryDefendAttack`，只有返回 `None` 才结算；受击函数只兜底，不负责该不该挨打。见手册 §2.4、第 13 课。
- **判据**：无敌/招架窗口内血量完全不变（不是先掉后补），且不播受击、不进硬直。
- **出自**：源手册 v1.54

### K014 血量变成 0，或停在 100 不跟表
- **主题**：伤害与防御链路
- **现象**：初始化后生命显示 0；或把表里 `player.hp.max` 改成 80 重开 PIE 仍是 100/100。
- **根因**：两条 `SetAttributeBaseValueByName` 顺序反了——先写 `Health` 再写 `MaxHealth`，`Health` 被旧的默认 `MaxHealth` 夹掉。
- **正解**：顺序固定“先 `MaxHealth` 后 `Health`”，两条都 `Target = Self`，值取 `GetCombatParam(DT_Combat, "player.hp.max")`。见手册 §9。
- **判据**：表里改成 80 重开 PIE → 80/80；改回 100 → 100/100。
- **出自**：源手册 v1.54

### K015 血量链完全不生效，打不掉血也不报错
- **主题**：伤害与防御链路 / 守卫与死亡清理
- **现象**：GAS 调试面板里属性区块为空或提示“没找到带技能系统组件的 Actor”；攻击没有伤害。

- **正解**：组件细节四项补齐（开始游戏时自动初始化 ✔ / 缺少组件时自动创建 ✔ / 自动创建时启用复制 ✔ / 挂载的属性集 = `GASCombatCoreAttributeSet`）；初始化绑「战斗就绪」`GASCombatOnCombatReady`。见手册 §3 第 1 项、§9。

### K016 用 `Source = Self` 测受击方向，永远播后向
- **主题**：伤害与防御链路
- **现象**：不管怎么打，受击动作永远是 `AM_PlayerHit_B`。
- **根因**：测试时 `Source = Self`，`AttackerLocation` = 自身位置，局部坐标是 `(0,0)`；`|X| >= |Y|` 走 True 分支、`X > 0` 为 False，于是固定落到 `_B`。
- **正解**：这是正确表现，不是 bug。验 F/L/R 必须用外部攻击者：用第 12 课的练习敌人（它用自身位置当 `DamageInstigator`），或临时生成一个 `Empty Actor` 摆在玩家前/左/右 100cm 处当 `Source`。见手册 §10.7。

- **出自**：源手册 v1.54

### K017 连击时硬直一次比一次短
- **主题**：伤害与防御链路
- **现象**：连续挨两刀，第二刀几乎立刻恢复控制。
- **根因**：`HandlePlayerHit` 里没先清 `HitStunTimer`，第一刀设的计时器到点就把控制还回来了。
- **正解**：`Set Timer by Event` 之前先 `Clear and Invalidate Timer by Handle`（Handle = `HitStunTimer`），且 `Clear` 必须排在 `Set` **之前**。见手册 §10.3、§10.9。
- **判据**：连按两次 T，总硬直长于单次的 0.38s，不被第一刀提前解除。
- **出自**：源手册 v1.54

### K018 硬直期间还能出招
- **主题**：伤害与防御链路 / 守卫与死亡清理
- **现象**：受击硬直时 WASD 不动，但左键还能打出去。
- **根因**：攻击入口不读 `InputEnabled`，只把组件自己的布尔置 false 不算禁用。
- **正解**：在 `LightAttack` 函数入口与左键/重击输入事件最前面加 `Branch(NOT bIsDead AND NOT bIsHitStunned)`；`InputEnabled` 只当状态位用。见手册 §10.9。
- **判据**：硬直期间左键/右键/侧键/V 全部无反应，WASD 无位移。
- **出自**：源手册 v1.54

### K019 受击一次后永远不能动，一直硬直
- **主题**：伤害与防御链路 / 守卫与死亡清理
- **现象**：挨一刀后再也不能移动也不能攻击。
- **根因**：①`OnPlayerHitRecover` 里恢复用的 `CallSetMovementEnabled(true)` / `CallSetInputEnabled(true)` 仍没写 Target（调到组件自己 = 空实现）；②`HandlePlayerHit` 末尾的 `Clear and Invalidate Timer by Handle(HitStunTimer)` 排在 `Set Timer by Event` 之后，把刚设的计时器清掉了。
- **正解**：恢复也改成 `Cast To BPI_CombatComponent(OwningCharacter)` 再调（与死亡路径一致）；执行顺序固定“先清旧计时器 → 再设新计时器”。见手册 §10.3、§10.5、§10.9。
- **判据**：挨一刀约 0.38s 后恢复移动与攻击；连挨两刀仍能恢复。
- **出自**：2026-10-21

### K020 用 `Delay` 做硬直时长
- **主题**：伤害与防御链路
- **现象**：恢复时间约 0.76s（正好是两倍）；或死亡后第 0.4 秒又“活”了一下。
- **根因**：`Delay` 是 latent 节点，开始执行后中途死亡也清不掉，延迟到点仍会把输入打开；叠在计时器后面等于时长翻倍。
- **正解**：硬直只用 `Set Timer by Event` + `Clear and Invalidate Timer by Handle`；`OnPlayerHitRecover` 里不要再塞 `Delay 0.38`。见手册 §10.1、§10.5。
- **判据**：恢复总时长 ≈ `combat.player.hitstun`（0.38s）；死亡后不再出现任何延迟恢复。
- **出自**：源手册 v1.54

### K021 敌人对着玩家尸体继续挥刀
- **主题**：伤害与防御链路 / 守卫与死亡清理
- **现象**：玩家已经死亡倒地，敌人每 2 秒继续出招，甚至继续结算伤害。
- **根因**：`AttackLoop` 只判断了“距离够不够近”，没有任何“目标还活着吗”的判断；尸体还在原地，距离一直满足。
- **正解**：两处插玩家 `bIsDead` 判断——`AttackLoop`（`Set Player = Get Player Character(0)` 之后、距离判断之前）与 `DoAttackHit`（`Array Add`/结算之前）；读法：`Get Component By Class(Target = Player, Component Class = AC_Combat) → Is Valid → Get bIsDead`。见手册 §12.5。
- **判据**：玩家死亡后敌人不再挥刀、`DoAttackHit` 不再结算；重开 PIE 敌人恢复出招。
- **出自**：源手册 v1.54

### K022 敌人被打死后站起来继续攻击
- **主题**：伤害与防御链路 / 守卫与死亡清理
- **现象**：敌人死亡动作播完后仍起身出招、继续打玩家。
- **根因**：`AC_EnemyAttack` 只查了 `bAttacking`、`bIsParryStunned` 与玩家 `bIsDead`，**没有一处查“自己（`OwningNPC`）已死”**；`AC_NPC.HandleDeath` 只做 `DisableMovement` 与 `SetCollisionEnabled`，既不清 `AttackLoop` 的循环计时器，也不 `StopAnimMontage`、不复位 `bAttacking`。
- **正解**：`AC_EnemyAttack` 加 `bDead` + `AttackLoopTimer`，写 `StopCombat`（置 `bDead` → 清 `AttackLoopTimer` → 复位 `bAttacking`/`bIsParryStunned` → `Array Clear` → 只 `Stop Anim Montage(AttackMontage)`）；`AttackLoop` 与 `DoAttackHit` 各加自身死亡门；`AC_NPC.HandleDeath` 末尾 `Get Owner → Get Component By Class(AC_EnemyAttack) → Is Valid → 调 StopCombat()`。见手册 §12.7。
- **判据**：打死敌人后观察 10 秒：不再出现「执行攻击函数」日志、不再播攻击蒙太奇、玩家血量不变。
- **出自**：v1.27 / v1.29

### K023 敌人受击硬直期间照样出招、照样结算
- **主题**：伤害与防御链路
- **现象**：玩家打中敌人，敌人确实进了受击硬直，但攻击照旧——受击动作刚起就被下一刀顶掉，硬直期间照样转向、照样结算伤害。
- **根因**：`AC_NPC.ApplyHitReaction` 只做“取时长 → `ApplyEffectWithValues(GE_HitStun_C)` → `PlayAnimMontage`”，**没有一处通知 `AC_EnemyAttack`**，硬直只活在 GAS 效果与动画层；`bIsParryStunned` 全资产没有置 true 的地方，`bIsHitStunned` 这个变量根本不存在；受击蒙太奇抢占攻击蒙太奇只触发异步 `Play Montage` 的 `On Interrupted` → `Set bAttacking=false`，下一个 `AttackInterval` 立刻重新起手。
- **正解**：`AC_EnemyAttack` 加 `bIsHitStunned` + `HitStunTimer`，写 `NotifyHitStunned(StunDuration: float)`（置位 → 清计时器 → 停攻击蒙太奇 → 清 `HitTargetsThisSwing` → 设 `EndHitStun` 计时器）与 `EndHitStun`（只复位）；`AttackLoop` / `DoAttackHit` 两个门都并入 `bIsHitStunned`；`ApplyHitReaction` 链尾 `Get Component By Class(AC_EnemyAttack) → Is Valid → 调 NotifyHitStunned(StunDuration)`。见手册 §12.8。
- **判据**：轻击命中后 0.35s 内敌人不出招；重击（伤害 ≥ `combat.enemy.hitstun_large_threshold` = 24 点）1.8s 不出招；连续命中三次不叠加成无限硬直；Output Log 无红字。
- **出自**：v1.36 / 2026-10-27

### K024 敌人一次挥击结算多刀
- **主题**：伤害与防御链路
- **现象**：同一刀把玩家打掉两三次血，或连播多次受击。
- **根因**：`DoAttackHit` 没有 `bAttacking` 守卫（同一时间叠多刀），或没做 `HitTargetsThisSwing` 去重。
- **正解**：开头守卫写成 `if bDead OR (NOT bAttacking OR bIsParryStunned OR bIsHitStunned OR Player.bIsDead) → return`；命中前 `Array Contains` 去重再 `Array Add`。见手册 §12.2、§12.5。
- **判据**：一次挥击只掉一次 `enemy.shadow.atk`（10）血，只播一次受击。
- **出自**：源手册 v1.54

### K025 「尝试读取 AC_EnemyAttack_C 中的属性 OwningNPC 时，结果为无」
- **主题**：伤害与防御链路
- **现象**：一进 PIE 就刷这条报错（4 个敌人 = 4 条），敌人完全不攻击。
- **根因**：①`ReceiveBeginPlay` 里 `Cast To Character` 的 `As Character` 输出**没有接** `Set Owning NPC`；②`Set OwningNPC` 放在别的事件里；③`Cast` 失败（Owner 不是 Character）；④变量声明了但默认值为空又没人 Set。另一路来源是 `DoAttackHit` 被接到了 `BP_MasterNPC` 的 `ReceiveBeginPlay` 上，4 个实例在 BeginPlay 同时调用它。
- **正解**：`Cast → Cast Failed 打印 → As Character → Set Owning NPC → Is Valid → Set Timer by Event`；`DoAttackHit` 只由 `AN_EnemyAttackHit` 触发，`BeginPlay` / `Tick` / `ReceiveActorBeginOverlap` 一律不接。见手册 §12.4。
- **判据**：一进 PIE 不再出现该报错；敌人按 `AttackInterval` 正常出招。
- **出自**：2026-10-22

### K026 数据键静默失效：表里看着加了，蓝图取到 0
- **主题**：伤害与防御链路 / 数据与工具
- **现象**：4 个新键“已经加进表里”，`GetCombatParam` 却返回 0；或过一分钟键自己消失。
- **根因**：四类都**不报错**：①UE 编辑器开着就导入 → 编辑器下次保存把旧表回写覆盖，键消失（搜 uasset 搜不到）；②`Key` 拼错一个字符 → `GetCombatParam` 静默返回 0；③键名含大写/空格/中文，或数值列写成 `0.5 秒` 这种带单位的文本 → 导出脚本只把该行记进 skip 清单，管道照样 `PASS`；④`Table` 引脚接到了 DataTable 变量而不是资产硬引用 → 编译不过或取到空表。
- **正解**：导入前关编辑器（`Get-Process UnrealEditor` 无输出）；键名只用 `a-z 0-9 . _`（正则 `^[a-z][a-z0-9._]*$`），数值列纯数字；`Table` 接 `DT_Combat` 资产硬引用；以 `_import_report.json` 的行数（23→27）与 uasset 字节搜索双证落地，不要只看 `PASS`。见手册 §5。

### K044 闪避全程没有无敌（链尾直接调计时器回调 + 设完立即 Clear）

### K106 exec 连线规则：普通节点只收一条，汇合要用重路由节点
- **主题**：蓝图节点语义

### K097 招架后敌人永久站桩（硬直时长取到 0）

- **现象**：招架成功、敌人也确实进了硬直，但**之后再也不出招**——不消失、不报红字、就是站着。`Output Log` 交替刷两条警告（一次招架能刷几十行）：

- **判据**：一次攻击只出现一行命中日志、血量只掉一次。

### K138 闪避键与奔跑冲突：选方案 A 点按即闪避，没选延迟判定
- **主题**：决策沿革 / 输入与键位
- **现象**：同一个键既要负责闪避又要负责奔跑，两种方案的手感与实现成本不同。
- **根因**：延迟判定（按住再区分）会让"按下立即闪避"多出判定延迟，闪避这种救场动作对手感最敏感；而点按/按住分流可以用时间阈值把两种用途分开。
- **正解**：**方案 A 定稿**——按下立即闪避，按住 ≥0.15s 奔跑。见第 4 课键位方案与附录 A「第 4–5 课键位方案 A」。
- **判据**：点按立刻出闪避动作；按住 0.15s 后进入奔跑、且不触发闪避。
- **出自**：2026-10-20；源手册 v1.54 附录 F（归档版） 第 1 行、附录 A.1。

### K139 招架可取消闪避后摇：选「刻意不检查 `bIsDodging`」+三条配套，没选「招架期间禁止闪避」
- **主题**：决策沿革 / 招架
- **现象**：`TryParry` 是否要检查 `bIsDodging`，两条规则互相矛盾（守卫规约要求对称守卫，操作手感要求可取消后摇）。
- **根因**：闪避后摇期间起招架能取消后摇、更有操作感；但若只豁免检查而不做清理，会残留无敌帧与位移，退化成脏状态。
- **正解**：**刻意豁免**，配套三条——① 招架起手调 `CleanupDodge()` 收尾闪避（清 `DodgeInvincibleTimer`/`DodgeMoveStopTimer`/`DodgeActionEndTimer` + `bInvincible=false` + `bIsDodging=false` + `LaunchCharacter(0,0,0)` 急停）；② `CleanupDodge` 不清 `DodgeRecoverTimer`（见 K116）；③ 招架起手清掉无敌帧是**必需**的——`TryDefendAttack` 的优先级是「无敌 → `Dodged`」先于「招架窗口 → `Parried`」，保留无敌帧会让闪避后按出的招架被判成闪避。见第 19 课设计决策注与待补缺口 #7/#13。
- **判据**：闪避中起招架 → 闪避动作立即收尾、无残留位移；招架成功拿到 `Parried` 而不是 `Dodged`。
- **出自**：v1.34（2026-10-27）；源手册 v1.54 附录 G.7（归档版）#7/#13 的行内说明。

### K140 招架分左右：选 `ThreatActor` + `NotifyIncomingAttack` 推送，没选「用接口 `Attacker` 决定初始蒙太奇」
- **主题**：决策沿革 / 招架
- **现象**：想在按键那一刻按攻击者方位选 `AM_Parry_L` / `AM_Parry_R`，但接口只有命中时才给出 `Attacker`。
- **根因**：**时序不成立**——`TryDefendAttack` 在刀已打中时才运行，而蒙太奇在按键那一刻就要播，中间隔着最长 0.22s 窗口，所以不能用它的 `Attacker` 决定**初始**蒙太奇。严格用接口 `Attacker` 只能把播放挪后，代价是按键到判定之间没有动作反馈。
- **正解**：① 资产先备齐（实查只有 `AM_Parry_L`，右手只有 `AS_Parry_R_Seq`，需复制出 `AM_Parry_R` 或改成双 Section）；② `AC_Combat` 加 `ThreatActor` + `NotifyIncomingAttack(Attacker)`（只用于选蒙太奇，不参与判定）；③ `AC_EnemyAttack.AttackLoop` 起手时推送 `OwningNPC`；④ `TryParry` 用 `IsValid(ThreatActor)` → `Dot(WorldDir, Get Actor Right Vector) > 0` → `Select`；⑤ `EndParryWindow` / `HandlePlayerDeath` 复位 `ThreatActor`；⑥ 左右反了只对调 `Select` 的 Option。见 §20.2。
- **判据**：左手来的攻击播 `AM_Parry_L`、右手来的播 `AM_Parry_R`；`ThreatActor` 在窗口关闭与死亡清理处被复位。
- **出自**：v1.39（2026-10-27）；源手册 §20.2、待补缺口 #18。
