## 1. `Apply Effect（动态数值）` 的 `Target` 为什么不能直接接组件自己？

**现象**：Step 9 里想把 `Target` 从 `AC_NPC` 组件自身取，连不上/不合法，节点上红字 `ERROR!`。

**根因**：`Target` 要的是 **Actor**，而 `AC_NPC` 是 `ActorComponent`——组件不是 Actor，也不是 Actor 的子类。

**做法**：`[Get Owner]`（组件 → 拥有它的 Actor）→ `Target`；之后逻辑里统一用变量 `OwningCharacter` 缓存它（`Get Owner` 后 `Cast To Character` 成功时 Set）。

**底层逻辑**：
- 插件函数签名（从 DLL 符号还原）：
  `UGASCombatStatics::ApplyEffectWithValues(AActor* Target, TSubclassOf<UGameplayEffect> EffectClass, const TMap<FGameplayTag,float>& SetByCallerValues, int32 Level, AActor* Instigator, AActor* EffectCauser)`
  → 蓝图引脚类型 = 参数的 UObject 基类，即 `Actor`。
- 同类先例：`AC_Combat` 的 `ApplyDamageToTarget`，`Source` 针类型是 `/Script/Engine.Actor`，实际接的是 `OwningCharacter`（`Character`，子类→父类合法）。证据：`Plugins/ComboMCP/cache/t3d/_Game_Combo_Demo_BP_Components_AC_Combat.t3d`（PlayWeaponTrace 图）。
- 为什么"组件"不行：`UActorComponent` 不是 `AActor` 的子类，蓝图不允许把组件当 Actor 传（`GetOwner` 才有意义）。

## 2. 编译报错：`"Set by Caller Values" 引脚当前的值无效：Map 输入（如 'Set by Caller Values'）必须连接输入（尝试连接一个 MakeMap 节点）`

**现象**：编辑器「编译器结果」面板红字，`编译 AC_NPC 失败。1 项重大问题`。

**根因**：`SetByCallerValues` 是 `TMap<FGameplayTag,float>`（**容器类型**）。蓝图里容器引脚不允许填写默认值，只能用数据线喂进来。

**做法**：从 `Set by Caller Values` 针拖出 → 搜 `Make Map` → `Make Map.Map` 接回该针。

**底层逻辑**：`E:\UE_5.7\Engine\Source\Editor\BlueprintGraph\Private\EdGraphSchema_K2.cpp:3017-3021`
`UEdGraphSchema_K2::IsPinDefaultValid()` 里：
`LOCTEXT("BadMapDefaultVal", "Map inputs (like '{PinName}') must have an input wired into them (try connecting a MakeMap node).")`
—— 引擎对 Array/Set/Map 三类容器针统一要求"必须连线"，因为引脚的文本框无法表达容器的默认值序列化格式。

## 3. `Make Map` 的键和值到底填什么？填错会怎样？

**填空**：
- `Key 0` = **FGameplayTag**，填 `Data.Duration`（用 `Make GameplayTag` 节点，或在 Map 的 Key 针上直接选标签）。
- `Value 0` = **float**，接时长变量 `StunDuration`（0.35 或 1.8）。

**为什么会是这个标签**：Step 8 的 `GE_HitStun` 里，`Duration Policy = Has Duration`，`Duration Magnitude` 选 `SetByCaller`，`Data Tag = Data.Duration`。`ApplyEffectWithValues` 只是把这张 Map 塞进 GameplayEffectSpec，真正查值的是 GE 自己——它按 `Data.Duration` 去 Map 里取。

**静默失败（最容易踩）**：标签写错（比如误选成 `Data.Duration.State.Stunned`）→ GE 在 spec 里找不到这个键 → 时长按 0 结算 → 硬直瞬间结束，**不报错、不掉血、只是没反应**。

**本项目实际踩过**：`Config\DefaultGameplayTags.ini:19` 曾把 `Data.Duration` 和 `State.Stunned` 两个标签写在一行（`Data.Duration.State.Stunned`，编辑器自动生成），标签选择器里就多出这个错标签，极易误选。`Data.Duration` / `State.Stunned` 本身是插件用 `AddNativeGameplayTag` 原生注册的，不需要写进 ini，所以这行可以直接删。

**验证方法（手册 :559 的手工法）**：控制台/调试面板施加 `GE_HitStun`，看受击者身上 `State.Stunned` 标签是否停留 0.35s——停留 = 链路通，闪一下 = 时长没喂进去。

## 4. 两条分支怎么共用一个 Map？「一对键值对只能存一个 Stun 啊」

**疑惑**：招架要 1.8s、普通受击 0.35s，`Make Map` 只有一对键值，是不是要同时存两个 `Stun`？

**结论**：不需要。**exec 是单线的**——一次函数调用只会走一条分支，只有一个 `SET StunDuration` 会执行；`Make Map` 是在调用瞬间用"当时"的 `StunDuration` 构造出 `{Data.Duration: 0.35}` 或者 `{Data.Duration: 1.8}`，GE 只查这一个键。

**做法**：
1. 局部变量 `StunDuration`（Float）。
2. 招架分支：`GetCombatParam("combat.enemy.parry_stun")` → `SET StunDuration` → exec 接 `ApplyEffectWithValues`。
3. 普通分支：`GetCombatParam("combat.enemy.hitstun")` → `SET StunDuration` → **同一条 exec 输入**（多条 exec 连同一个输入是合法的，每次只进一条）。
4. `Make Map.Value` 接独立的 `GET StunDuration`（不要接 SET 节点的输出针——那本质是 getter，能跑但看着容易误会）。

**底层逻辑**：分支不是并行；变量存的是"到达该节点时刻的值"。所以"一个 Map 一对键值"就够，多放两个同标签键反而会互相覆盖。

## 5. Step 10 验收：掉血了，但 NPC 没有受击动作

**根因**：伤害链路通了、表现链路没接。`AC_Combat → GE_Damage → 属性集 → 广播` 正常（所以掉血），但 `BP_MasterNPC` 的事件图里**没有**「受到伤害时 → `ApplyHitReaction`」这个绑定（当时保存的资产里 `ApplyHitReaction` 出现 0 次）。

**做法**（`BP_MasterNPC` 事件图）：
`AC_GASCombat` 组件拖出 → 添加事件 →「受到伤害时」→ 调 `AC_NPC.ApplyHitReaction`：
- `DamageAmount` ← 事件节点的 `DamageAmount`
- `AttackerLocation` ← `GetActorLocation(事件节点的 DamageInstigator)`
- `bFromParry` ← `false`（招架是 W8 的事）

**底层逻辑**：伤害广播的委托（`OnDamageTaken` / `OnDeath`）定义在 **`AC_GASCombat`**（插件 GAS 桥接组件）上；`AC_NPC` 是自建的普通组件，它只是"被通知者"，自己收不到这个事件。所以绑定必须发生在同时持有两个组件的 `BP_MasterNPC` 上。

**排查顺序**（以后同类问题照这个顺序走）：
1. 有没有掉血？没有 → 伤害链路（`AC_Combat`/GE/属性集）；
2. 掉血但没动作 → 事件有没有进来？（在 `ApplyHitReaction` 开头加 `PrintString）`
3. 事件进来了但没动作 → 蒙太奇有没有播？（看 `PlayAnimMontage` 的 Montage 是否为空、AnimBP 里有没有 Slot 节点）

## 6. Step 11：方向判定为什么用局部坐标？四象限怎么映射数组？

**为什么用局部坐标**：判断"敌人从哪个方向打来"要看**相对 NPC 自身朝向**的方向；用世界坐标或角度扇区都行，但角度要处理 `359°/1°` 跨界，局部坐标不需要。UE 的局部空间约定：**+X 朝前、+Y 朝右**。

**做法**（推荐一步写法）：
`[Get Actor Transform](OwningCharacter)` → `[Inverse Transform Location](T=上一步, Location=AttackerLocation)` → 得到 `LocalDir`。
等价于手册的「`AttackerLocation − Owner位置` 再 `Inverse Transform Direction`」，但少一个节点，也不会把 `Subtract` 的 A/B 接反（接反 = 左右镜像）。

**四象限 → 索引表**（对应 `MontageSmall` 默认值顺序 `[F, B, L, R]`）：

| 条件 | 索引 | 蒙太奇 |
|---|---|---|
| `|X| >= |Y|` 且 `X > 0` | 0 | `AM_Hit_F`（正面） |
| `|X| >= |Y|` 且 `X <= 0` | 1 | `AM_Hit_B`（背面） |
| `|X| < |Y|` 且 `Y > 0` | 3 | `AM_Hit_R`（右侧） |
| `|X| < |Y|` 且 `Y <= 0` | 2 | `AM_Hit_L`（左侧） |

**底层逻辑**：`E:\UE_5.7\Engine\Source\Runtime\Engine\Classes\Kismet\KismetMathLibrary.h:3991`
`static UE_INL_API FVector InverseTransformLocation(const FTransform& T, FVector Location)`；
同文件 `:3998` `InverseTransformDirection(const FTransform& T, FVector Direction)`。
—— 两函数的第一个参数都是 **Transform**，不是 Rotator（手册里写"World Rotation"容易让人接错 `Get Actor Rotation`）。

## 7. Branch D「数组取值」到底怎么连？（"我没能理解"那次）

要解决两件事，别混在一起：

**(a) 选哪个数组**：`MontageSmall` 和 `MontageLarge` 是**两个不同的变量**，蓝图不能用索引在变量之间挑，只能用 `Branch`（或 `Select`）二选一。所以 `Branch D` 的 `Condition` = `bLarge`。

**(b) 按索引取元素**：不是普通变量 GET（那输出整个 `TArray`），要用 `Get (a copy)` 节点（内部是 `K2Node_GetArrayItem`）：`Array` 输入针 + `Index` 输入，输出**单个** `AnimMontage`。
做法：空白处右键 → 搜 `Get (a copy)` → 把 `MontageSmall` 变量拖到它的 `Array` 针上；`Index` 接 `DirectionIndex`。

**`MontageLarge` 必须做越界兜底**：它现在只有 1 个元素（`AM_Hit_Large_F`），如果 `DirectionIndex` 是 2 或 3，直接取会返回 `None` → `PlayAnimMontage(None)` **静默不播**（看起来就是"侧面重击没反应"）。
做法：`[Array Length](MontageLarge)` → `[Subtract] A=Length, B=1` → `[Min (Integer)] A=DirectionIndex, B=Length-1` → 接 `Index`。
数值验算：Length=1 → `Min(2, 0) = 0` → 永远取 `[0]`；Length=4 时 Min 不改变索引，自动生效。

**收尾两种写法都行**：
- 函数里可以放**多个 `Return` 节点**，两个分支各接一个 Return（最省节点，推荐）；
- 或者各接一个 `SET ResultMontage`，两个 exec 汇到同一个 Return，Return 读变量。

## 8. Step 12：阈值分档，以及 `bFromParry` 到底控制什么？

**公式**（手册 :707-734）：
```
Threshold = GetCombatParam("combat.enemy.hitstun_large_threshold")   // 24
bLarge    = (DamageAmount >= Threshold) OR bFromParry
时长      = bFromParry ? parry_stun(1.8) : bLarge ? hitstun_large(1.8) : hitstun(0.35)
```

**`bFromParry` 是什么**：`ApplyHitReaction(DamageAmount, AttackerLocation, bFromParry)` 的第三个参数，语义 =「**这一次受击是不是招架（parry）造成的**」。
- 它**只控制**"去 `DT_Combat` 查哪一行时长"（true → `combat.enemy.parry_stun`）；
- 它**不控制**播哪个动画（那是 `bLarge` 的事）；
- 也**不控制**掉血/死亡。
- 现在没有任何地方传 `true`（手册 :649：招架是 W8 的事，先给常量 `false`）→ true 分支是"保留正确、暂时死代码"；将来 W8 在 `AC_Combat` 命中判定里传 true，`AC_NPC` 不用改。

**为什么这么设计**：招架也是硬直，只是时长不同，走同一个入口只换查哪个键，不复制第二条流程（手册 :623「别把『大硬直=1.8』写死在两个地方」）。

**数据现状**（`Scripts\DataPipeline\csv\DT_Combat.csv:2-6`，已核实）：
`combat.enemy.hitstun`=**0.35**、`combat.enemy.parry_stun`=**1.8**、`combat.enemy.hitstun_large`=**1.8**、`combat.enemy.hitstun_large_threshold`=**24**。
轻击 12/14/20 < 24 → 小硬直；重击 28 ≥ 24 → 大硬直。三个例子：
- 轻击 12、非招架 → 0.35s + `MontageSmall[方向]`
- 重击 28、非招架 → 1.8s + `MontageLarge[方向]`（现在只有前方）
- W8 招架 18、`bFromParry=true` → 1.8s（`parry_stun`）+ 大蒙太奇

**易混点**：`combat.enemy.parry_stun` 是"敌人被打出招架硬直"的时长；玩家自己挨打用 `combat.player.hitstun`（0.38）；`enemy.shadow.parry_stun`（1.5）是杀生之影专用。

## 9. 蒙太奇永远播「从后面被打」那一支

**根因①**：`AttackerLocation` 那根线接的是一个 `Get Actor Location` 节点，但它是**自调用**（`FunctionReference=(MemberName="K2_GetActorLocation", bSelfContext=True)`，`Target` 针悬空）——返回的是 **NPC 自己**的位置。
于是 `AttackerLocation − NPC位置 = (0,0,0)` → `|X|>=|Y|` = 真、`X>0` = 假 → `DirectionIndex = 1`（背面）→ 永远 `AM_Hit_B`。

**根因②**（加了 IsValid 兜底后仍然全走背面）：`IsValid` 的 `Object` 接的是**成员变量** `Damage Instigator`（带空格），这个变量在整个蓝图里**从来没有被 Set** → 恒为 `None` → `IsValid` 恒 false → 永远走 else 兜底 → 兜底里取的又是 NPC 自身位置 → 又是 index 1。

**做法**：
1. `IsValid.Object` 改接**事件节点的 `DamageInstigator` 输出针**（不要接那个同名成员变量，并把它删掉）；
2. 兜底分支别用 `0,0,0`：用 `GetActorLocation(GetOwner)` + `GetActorForwardVector(GetOwner) × -100`（当作"正后方挨打"）；
3. 判断放在调用 `ApplyHitReaction` **之前**（IsValid 为真用它位置，为假走兜底）。

**底层逻辑**：
- 蓝图里"自调用"节点（`Target` 空）等价于 `self`，所以组件函数 `GetActorLocation(self)` 拿的是**组件拥有者**的位置——这里恰好就是 NPC 自己。
- 成员变量默认值 `None`，没有任何 Set 就永远是 `None`，引擎**不会**自动帮你填。
- **名字一样不等于同一个东西**：事件节点上的 `DamageInstigator` 是事件的输出参数，蓝图里的 `Damage Instigator` 是成员变量——这是当初接错的真正原因。

**验算**：站在正前/正后/正左/正右打 → 期望 `DirectionIndex` = 0/1/2/3 → `MontageSmall[0..3]` = `AM_Hit_F/B/L/R`（前提：数组默认值顺序确实是 `[F,B,L,R]`）。

## 10. Step 13：「组件怎么可能引用另一个组件事件呢？？」

**用户是对的，我一开始教错了。** 原写法让人在 `AC_NPC` 里绑「死亡时」，这在物理上做不到。

**根因**：`OnDeath` / `OnDamageTaken` 这些委托定义在 **`AC_GASCombat`**（插件组件）上。蓝图里"添加事件"只能列出**当前蓝图自己类**的委托——`AC_NPC` 与 `AC_GASCombat` 是同一 Actor 上的**兄弟组件**，互相看不见对方的委托成员。

**正确架构**：
1. `AC_NPC` 里写**普通函数** `HandleDeath()`（不是事件）：`bDead` 守卫 → `SET bDead = true` → `GetOwner` → `Cast To Character` → 取消所有技能 → 添加游离标签 `State.Dead` → `Disable Movement` → `SetCollisionEnabled(NoCollision)` → `PlayAnimMontage(MontageDeath)`。
2. `BP_MasterNPC`（同时持有两个组件的 Actor）事件图：从 `AC_GASCombat` 拖出 → 添加事件 →「死亡时」→ 调 `AC_NPC.HandleDeath`。
3. 别在 `HandleDeath` 里依赖 `OwningCharacter`——它只在 `ApplyHitReaction` 里赋值，死亡路径上可能是 `None`；要用就自己 `GetOwner → Cast`。

**底层逻辑**：委托是实例级成员，蓝图的事件系统只能把"本蓝图类声明的委托"暴露成事件入口；跨组件必须由持有者 Actor 中转（这也是 UE 里 GAS 组件的常规用法）。

## 11. 「函数里没法调用 Delay 异步节点，是否需要把它包装成事件？？」

**结论**：对，需要。`Delay`、`Delay Until Next Tick`、`Play Montage` 的异步输出等 **latent** 节点不能放在蓝图函数（含 Pure/普通函数）里，只能放**事件图（Ubergraph）**；想复用就把整段逻辑做成**自定义事件**（放事件图），或把延迟部分放到 Actor 的事件图。

**证据**：
- `Delay` 声明带 `meta=(Latent, WorldContext=..., LatentInfo="LatentInfo")`：`E:\UE_5.7\Engine\Source\Runtime\Engine\Classes\Kismet\KismetSystemLibrary.h:665`
- 编译期报错原文：`E:\UE_5.7\Engine\Source\Editor\BlueprintGraph\Private\CallFunctionHandler.cpp:195-198`
  `"@@ contains a latent call, which cannot exist outside of the event graph"`
- 编辑器放置过滤：`EdGraphSchema_K2.cpp:755-764`，`LatentFunctionsNotAllowed` / `"Latent functions cannot be used here."`

**底层逻辑**：latent 函数需要"恢复执行点"（`LatentInfo` 里记录的 `ExecutionFunction`），蓝图只有事件图（`Ubergraph`）有这个概念——恢复函数名就是 `ExecuteUbergraph_<蓝图名>`（`CallFunctionHandler.cpp:221-224`）。所以它跟"谁调用你"无关，取决于"你在哪张图里"。

**本项目的结论**：Step 13 选的是"保留尸体不销毁"，`Delay` 后面本来没有动作 → **直接删掉 Delay**，`HandleDeath` 保持同步函数最干净。
以后真要延迟销毁：`Delay 3.0 → DestroyActor` 放在 `BP_MasterNPC` 的事件图里。纯同步的替代品是 `K2_SetTimer`（"Set Timer by Function Name"，`KismetSystemLibrary.h:897-898`，非 latent）。

## 12. 死亡动画播完，尸体站起来（而不是一直躺地上）

**根因**：`AnimMontage` 的 `bEnableAutoBlendOut` 默认 `true`，蒙太奇播完会自动 blend 回 AnimBP 的常态（本项目 `ABP_EnemyBase` 是 `SequencePlayer(AS_Idle_Seq) → Slot → Root`，没有状态机）→ 直接站回 Idle。

**做法**：打开 `Content/Combo_Demo/Animation/Montage/AM_Hit_Death` → 细节面板 → `Blend Option` → 取消勾选 **`Enable Auto Blend Out`**。

**代价（必须知道）**：Montage 之后不会自己停，`On Montage Ended` / `On Blend Out Started` 不再触发；以后做 Ragdoll / 复活 / 销毁尸体前要先 `Montage Stop`。

**底层逻辑**：
- `E:\UE_5.7\Engine\Source\Runtime\Engine\Classes\Animation\AnimMontage.h:704-706`：
  `/** When it hits end, it automatically blends out. If this is false, it won't blend out but keep the last pose until stopped explicitly */ bEnableAutoBlendOut`
- 默认值：`AnimMontage.cpp:66` `bEnableAutoBlendOut = true`。
- 运行时：`AnimMontage.cpp:2563-2583` 只有该标志为真才 `Stop`/开始 blend out；否则 `:2669-2681` 走 `bPlaying = false`，把 `Position` 夹到 section 末尾——**实例保持激活、Slot 权重保持 1、姿势定格在末帧**。

**正规替代（没做，以后升级用）**：`ABP_EnemyBase` 加 `bDead` 变量 + Dead 状态用非循环 `Sequence Player` 播 `AS_Hit_Death_Seq`，播完同样保持末帧，还能顺便做 Ragdoll 切换。

## 附：这次的排查方法论（可复用）

1. **先分清是"数据"还是"表现"**：掉血 = 数据链路通；没动作 = 表现链路。两条链分开验，别一起猜。
2. **看资产引脚，不看剧情**：`ComboMCP` 的 `flow`（DSL）读结构，`node_detail` 读引脚连线；离线缓存在 `Plugins/ComboMCP/cache/t3d/`，改完资产要 `sync` 才会更新。
3. **红字 `ERROR!` 一定要拿到正文**：编辑器「编译器结果」面板里的完整句子才定位得到引擎校验分支（例如 Map 输入必须连 `MakeMap`）。
4. **静默失败优先怀疑"输入是空/0/None"**：蒙太奇 `None` 不播、标签错按 0 结算、位置差为 0 取到背面——全都不报错。
5. **名字相同 ≠ 同一个东西**：事件参数 vs 成员变量、`GetActorLocation(self)` vs `GetActorLocation(instigator)`。
6. **引擎级问题查源码**：`ComboMCP` 的 `engine_source`（file:line）+ 官方文档镜像，先有证据再下结论；本次 `bEnableAutoBlendOut`、`Delay`、`InverseTransformLocation` 都是这样定死的。
