## 0. 一句话现状

连招攻击链路是**完整且能跑通**的：按左键 → 播放 `AttackMontages[ComboIndex]` → 索引自增并环绕 → 动画里的通知驱动输入门控和武器判定框。

装备链路也是**完整**的：左 Alt → 播装备/卸下蒙太奇 → 通知在动画中途生成/挂接武器。

**没做完的是三件事**：① 连招数组里的顺序疑似插错了；② 3 段蒙太奇还没接进去、也没加判定窗口；③ 输入缓冲只写不读，等于没生效。NPC 侧完全是空壳。

## 3. 连招数组：实测内容（**重点看这一节**）

`BP_MasterWeapon.AttackMontages` 的 CDO 实测值——**5 个槽位，全部非空，无空槽**：

| 下标 | Montage | 输入禁用窗口 | 武器判定窗口 | 时长 |
|---|---|---|---|---|
| 0 | `AS_Combo01_01` | 0 – 0.388 | ✅ 0 – 0.587 | 1.83s |
| 1 | `AS_Combo02_01` | 0 – 0.508 | ✅ 0 – 0.666 | 2.53s |
| 2 | **`AS_Combo03_02`** | 0 – 0.692 | ✅ 0 – 0.928 | 2.50s |
| 3 | **`AS_Combo03_04`** | 0 – 0.411 | ✅ 0 – 0.667 | 2.42s |
| 4 | **`AS_Combo02_04`** | 0 – 0.875 | ✅ 0 – 0.997 | 2.92s |

### ⚠️ 未进数组的 3 段，恰好就是唯一没有判定窗口的 3 段

| Montage | 在数组里 | 输入禁用窗口 | 武器判定窗口 |
|---|---|---|---|
| `AS_Combo02_02` | ❌ | 0 – 0.609 | **无** |
| `AS_Combo03_01` | ❌ | 0 – 0.664 | **无** |
| `AS_Combo02_03` | ❌ | 0 – 0.664 | **无** |

这不是巧合：**当时正在给这 3 段补 `ANS_WeaponTrace`，补完之前没把它们放进数组**。这就是断点。

### ⚠️ 数组顺序疑似插错位（头号嫌疑）

实际播放顺序**严格等于数组顺序**（`LightAttack` 就是取 `AttackMontages[ComboIndex]`）：

```
01_01  →  02_01  →  03_02  →  03_04  →  02_04  →  (回到 01_01)
```

按命名规律，合理的意图应该是 `01_01 → 02_01 → 02_04 → 03_02 → 03_04` 之类——**02 段的收尾 `02_04` 被排到了最后，03 段插在中间**。

这看起来像是手动往数组里拖资源时插错了位置。**接手第一件事就是确认这是不是有意为之**；如果不是，把 `02_04` 拖回下标 2 即可（纯数据改动，不碰任何图）。

## 4. 运行时流程（逐链路）

### 4.1 左键 → 普攻连招

按键：**鼠标左键**（`CombatGraph` 里的 `InputKey`，`InputKey=LeftMouseButton`）

```
LeftMouseButton.Pressed
  → CheckBufferedInput(AttackOrNot = NotAttack)          ← 判断是否允许输入
  → Branch( 上面这个函数的返回值 )
      True → LightAttack()
      → RetriggerableDelay(2.0)
      → ComboIndex = 0 ; CurrentBufferedInput = NotAttack
```

`LightAttack()` 内部：

```
Branch( bWeaponInHand )
  True → Is Valid(CurrentWeapon)
       → GetAttackMontages(CurrentWeapon)        [BPI_WeaponActor 接口消息]
       → Play Anim Montage( OwningCharacter, AttackMontages[ComboIndex] )
       → CachedInputRotation = GetInputRotation()
       → Set Component Tick Enabled(true)
       → GetAttackMontages(CurrentWeapon)        第二次调用（用于算长度）
       → IncrementInt( ComboIndex )              ← 标准宏，会写回变量
       → PrintText( 自增后的 ComboIndex )         ⚠️ 调试残留
       → Sequence
            then_0 → Branch( ComboIndex >= Array_Length(AttackMontages) )
                       True → ComboIndex = 0       ← 环绕
            then_1 → （此分支在当前图里无后续）
```

**连招窗口 = 2.0 秒**，用的是 `RetriggerableDelay`（可重触发），所以只有真正停手 2 秒才会把索引清零。

> 📌 历史问题已修复，不要再查：
> 早期版本用的是 `Array_LastIndex` + 普通 `Delay`，会导致「最后一段永远播不到」和「连到一半索引被清零」。
> 当前资产已改为 **`Array_Length` + `RetriggerableDelay`**，两个问题**都已解决**。
> （详见 `Plugins/ComboMCP/docs/连招索引清零诊断.md`，那份报告描述的是修复前的状态。）

### 4.2 左 Alt → 装备 / 卸下

按键：**左 Alt**（`EventGraph` 里的 `InputKey`，`InputKey=LeftAlt`）

```
LeftAlt.Pressed
  → Branch( bWeaponBusy == false )                     ← 防连点守卫
      → bWeaponBusy = true
      → Branch( bWeaponInHand )
          True  → Play Montage( AM_Unequip )           ← 异步节点
          False → Play Montage( AM_Equip )
```

两个 `Play Montage` 节点的委托引脚接线（已逐引脚核对）：

| 输出引脚 | 接到哪 |
|---|---|
| `OnNotifyBegin` | ✅ 接入装备/卸下处理链（由 montage 里 ~0.37s 处的 `AMS_Equipment` 触发） |
| `OnCompleted` | ✅ 接入同一条链（兜底） |
| `OnInterrupted` | 单独一条链，只复位 `bWeaponBusy`，**不做装备** |
| `OnBlendOut` / `OnNotifyEnd` | 未接 |
| `then` | 悬空（异步节点正常现象，不是断头） |

**武器是在动画播到 `AMS_Equipment` 那一帧才出现的**，不是按下去就出现——这是刻意的设计，手感上"手抓到位武器才到手"。

实际做装备动作的是三个 Custom Event / 函数：

```
EquipWeapon(DataRow)
  → Get Data Table Row(DT_WeaponDetails, DataRow)
  → Attach Actor To Component(CurrentWeapon → Mesh, Socket = SocksNames_Hand)
  → 更新 bWeaponInHand / EquippedWeaponRow / PendingWeaponRow

UnequipWeapon(DataRaw)
  → Get Data Table Row → Attach 到 SocksNames_Back
  → 更新 bWeaponInHand / EquippedWeaponRow

SpawnWeaponOnBack(DataRow)        ← BeginPlay 时调用，参数 "Spear"
  → 入口判重：if ( DataRow == EquippedWeaponRow && IsValid(CurrentWeapon) ) → 什么都不做（幂等）
  → Get Data Table Row → Load Asset Class(异步) → 有旧的就 Destroy，没有就 Spawn
  → Attach Actor To Component(→ Mesh, Socket = SocksNames_Back)     ← 背
  → 收尾：EquippedWeaponRow / bWeaponBusy / bWeaponInHand
```

三个 `Attach Actor To Component` 各自用的 socket（已逐个追到 `BreakStruct` 的输出引脚）：

| 所在函数 | Socket 来源 | 实际含义 |
|---|---|---|
| `EquipWeapon` | `SocksNames_Hand` | 拿到手上 |
| `UnequipWeapon` | `SocksNames_Back` | 收到背上 |
| `SpawnWeaponOnBack` | `SocksNames_Back` | 出生就在背上 |

**`bWeaponBusy` 是防连点标志**：过守卫后置 `true`，复位是由 `Play Montage` 的 `OnCompleted` / `OnNotifyBegin` 链尾做的（**不是立刻复位**），所以动画播完前重复按左 Alt 不会重复触发。

### 4.3 命中检测

`ANS_WeaponTrace`（动画里的状态通知）→ `CallWeaponTrace(true/false)` → 写 `Weapon Trace On`

`Tick` 每帧调 `PlayWeaponTrace()`：

```
if ( Weapon Trace On && Is Valid(CurrentWeapon) )
  → Get Weapon Mesh(CurrentWeapon)              [BPI_WeaponActor 接口消息]
  → 从网格取 Top / Bottom 两个插槽的当前世界坐标 → CurrentTopTrace / CurrentBottomTrace
  → Box Trace Single(
        Start = PreviousTopTrace,  End = CurrentTopTrace,
        HalfSize = MakeVector( 两点距离 / 2, 0, 0 ),
        Orientation = FindLookAtRotation(PreviousTopTrace, CurrentBottomTrace),
        TraceChannel = TraceTypeQuery1, bIgnoreSelf = true,
        DrawDebugType = ForDuration, DrawTime = 5.0 )
  → 命中则 PrintString( 目标身上 AC_NPC 组件的 DisplayName )   ⚠️ 调试残留
  → PreviousTopTrace / PreviousBottomTrace = 本帧的值（给下一帧用）
```

即：**用武器网格的上下两点连线扫一个盒子**，判定框宽度由两点距离推导。上一帧→当前帧的位移方式保证挥动过程中不会漏检。

### 4.4 转向对齐

`Tick` 里持续执行：

```
K2_SetActorRotation( OwningCharacter,
    Yaw = RInterpTo( 当前朝向, CachedInputRotation, DeltaTime, 13.0 ) )
```

`CachedInputRotation` 在**每次出招那一刻**由 `GetInputRotation()` 写入：

```
GetInputRotation() =
  FindLookAtRotation( 角色位置,
                      角色位置 + 移动输入方向 * 距离 )
```

其中移动输入方向来自 `GetCharacterMovementDirection()`，读的是 `CurrentMovementVector`。
→ **效果：出招瞬间角色转向左摇杆/移动键的方向。** 移动向量由角色推送进来（见 4.5）。

### 4.5 角色侧的接线（在 `Combo_Demo` 之外）

`/Game/Blueprints/SandboxCharacter_CMC`：

- 持有 `AC_Combat` 组件（Tag = `Combat`）
- 实现了 `BPI_CombatComponent` 的三个接口函数，做纯转发
- 把角色的移动输入打包成 `BS_MovementVector`，调 `AC_Combat.CallSetMovementVector`

> ⚠️ 观察项：`SandboxCharacter_CMC` **同时声明实现了 `BPI_WeaponActor`**（带 `GetAttackMontages` / `GetWeaponMesh` 两个图）。角色不是武器，这看起来是加接口时误选。当前无害（没有地方对角色调这两个函数），但建议清理掉以免误导。

## 9. 工具链：不开编辑器也能读这些资产

工程里有个自研插件 `Plugins/ComboMCP`，提供一套只读的 MCP 工具（`class_summary` / `flow` / `montage` / `audit` 等）。

**主力路径是离线 T3D 缓存**，不需要编辑器在运行：

```powershell
# 用 MCP 的 sync 工具收集（走 headless commandlet，首次约 1 分钟）
# 缓存落在 Plugins/ComboMCP/cache/t3d/
```

### ⚠️ 离线缓存的已知盲区

T3D 导出**不含 CDO 默认值**——变量初值、数组内容（比如 `AttackMontages` 里到底是什么）**读不到**。
要读这些必须跑 Python commandlet：

```powershell
& "E:\UE_5.7\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" `
  "E:\Unreal Projects\Animation_Sample\Animation_Sample.uproject" `
  -run=PythonScript -Script="<你的脚本.py>" `
  -unattended -nosplash -nop4 -nullrhi -DDC-ForceMemoryCache `
  -EnablePlugins=PythonScriptPlugin -stdout
```

> `-DDC-ForceMemoryCache` 是必需的：没有可写的 DDC 时引擎会直接 Fatal Error 退出。

本报告用到的探针脚本和原始输出都在 `Plugins/ComboMCP/cache/_probe/`：

| 文件 | 内容 |
|---|---|
| `probe_cdo_defaults2.py` / `cdo_defaults2.json` | **连招数组实测内容**、`AC_Combat` 全部初始值 |
| `probe_cdo_defaults3.py` / `cdo_defaults3.json` | 角色组件清单 + **Component Tag 实测** |
| `probe_cdo_defaults.py` / `cdo_defaults.json` | 数据表行名、CDO 的 T3D 导出 |
| `montages.json` | 各蒙太奇 Section / 时长 |

## 10. 接手建议

1. **先跑一遍 §7 的验证清单**，确认当前是"能跑"的状态，建立基线。
2. **再决定 §3 的数组顺序**——这是纯数据改动、风险为零，但影响整个连招手感。
3. **然后补那 3 段蒙太奇的判定窗口**（§6.2），这是断点所在，做完连招段数就从 5 段变 8 段。
4. 输入缓冲（§6.3）是独立的一块，可以单独排期。
5. NPC 侧（§6.10）工作量最大，基本是从零开始，建议单独立项。
