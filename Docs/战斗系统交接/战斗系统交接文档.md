## 4. 运行时流程（逐链路）

### 4.1 左键 → 轻击连招　右键 → 蓄力重击

**左键**（`CombatGraph` 的 `InputKey`）：

```
LeftMouseButton.Pressed
  → CheckBufferedInput(AttackOrNot = NotAttack)          ← 判断是否允许输入
  → Branch( 上面这个函数的返回值 )
      True → LightAttack()
      → RetriggerableDelay(2.0)
      → LightComboIndex = 0 ; CurrentBufferedInput = NotAttack
```

`LightAttack()` 内部（2026-10-19 `flow` 实测，31 节点）：

```
if ( bWeaponInHand )
  → GetLightAttackMontages(CurrentWeapon)        [BPI_WeaponActor 接口消息]
  → Play Anim Montage( OwningCharacter, LightAttackMontages[LightComboIndex] )
  → CurrentAttackDamage = GetCombatParam( Table = DT_Combat,
                          Key = "combat.dmg.light" + ToString(LightComboIndex + 1) )   ← 新增：从数据表取伤害
  → CachedInputRotation = GetInputRotation()
  → Set Component Tick Enabled(true)
  → GetLightAttackMontages(CurrentWeapon)        第二次调用（用于算长度）
  → IncrementInt( LightComboIndex )              ← 标准宏，会写回变量
  → PrintText( 自增后的 LightComboIndex )         ⚠️ 调试残留（实测仍在，2 秒，青色）
  → Sequence
       then_0 → if ( LightComboIndex >= Array_Length(LightAttackMontages) )
                   True → LightComboIndex = 0       ← 环绕
       then_1 → （此分支在当前图里无后续）
```

**连招窗口 = 2.0 秒**，用 `RetriggerableDelay`（可重触发），只有真正停手 2 秒才会把索引清零。

**右键**（`CombatGraph` 另一对 `InputKey` 事件，2026-10-16 新增）：

```
RightMouseButton.Pressed
  → CheckBufferedInput(NotAttack)
  → StartCharge()          ← 开始蓄力：写 bIsCharging / bChargeReady / ChargeTimerHandle
RightMouseButton.Released
  → ReleaseCharge()        ← 蓄满则走重击（HeavyAttack），未蓄满则 CancelCharge
```

> 蓄力各函数（`HeavyAttack` 14 / `ReleaseCharge` 26 / `CancelCharge` 11 / `ChargeTick` 2 / `StartCharge` 2 节点）的**逐引脚细节未核实**；对外表现是「按住右键蓄力、松开出重击」。

### 4.2 左 Alt → 装备 / 卸下

按键：**左 Alt**（`EventGraph` 的 `InputKey`）。

```
LeftAlt.Pressed
  → Branch( bWeaponBusy == false )                     ← 防连点守卫
      → bWeaponBusy = true
      → Branch( bWeaponInHand )
          True  → Play Montage( AM_Unequip )           ← 异步节点
          False → Play Montage( AM_Equip )
```

两个 `Play Montage` 节点的委托引脚接线（v1 逐引脚核对，v2 仅复核了函数桩仍在）：

| 输出引脚 | 接到哪 |
|---|---|
| `OnNotifyBegin` | ✅ 接入装备/卸下处理链（由 montage 里 ~0.37s 处的 `AMS_Equipment` 触发） |
| `OnCompleted` | ✅ 接入同一条链（兜底） |
| `OnInterrupted` | 单独一条链，只复位 `bWeaponBusy`，**不做装备** |
| `OnBlendOut` / `OnNotifyEnd` | 未接 |
| `then` | 悬空（异步节点正常现象，不是断头） |

**武器是在动画播到 `AMS_Equipment` 那一帧才出现的**，不是按下去就出现——刻意设计，手感上"手抓到位武器才到手"。

实际做装备动作的是三个函数：

```
EquipWeapon(DataRow)
  → Get Data Table Row(DT_WeaponDetails, DataRow)
  → Attach Actor To Component(CurrentWeapon → Mesh, Socket = SocksNames_Hand)
  → 更新 bWeaponInHand / EquippedWeaponRow / PendingWeaponRow

UnequipWeapon(DataRaw)
  → Get Data Table Row → Attach 到 SocksNames_Back
  → 更新 bWeaponInHand / EquippedWeaponRow

SpawnWeaponOnBack(DataRow)        ← BeginPlay 时调用，参数 "Spear"
  → 入口判重：if ( DataRow == EquippedWeaponRow && IsValid(CurrentWeapon) ) → 什么都不做（幂等）
  → Get Data Table Row → Load Asset Class(异步) → 有旧的就 Destroy，没有就 Spawn
  → Attach Actor To Component(→ Mesh, Socket = SocksNames_Back)     ← 背
  → 收尾：EquippedWeaponRow / bWeaponBusy / bWeaponInHand
```

三个 `Attach Actor To Component` 各自用的 socket：

| 所在函数 | Socket 来源 | 实际含义 |
|---|---|---|
| `EquipWeapon` | `SocksNames_Hand` | 拿到手上 |
| `UnequipWeapon` | `SocksNames_Back` | 收到背上 |
| `SpawnWeaponOnBack` | `SocksNames_Back` | 出生就在背上 |

**`bWeaponBusy` 是防连点标志**：过守卫后置 `true`，复位由 `Play Montage` 的 `OnCompleted` / `OnNotifyBegin` 链尾完成（**不是立刻复位**）。v2 未逐引脚复核这条链，标注**未核实**（若出现"按 Alt 没反应"，先查这里）。

### 4.3 命中检测

`ANS_WeaponTrace` → `CallWeaponTrace(true/false)` → 写 `WeaponTraceOn`（注意：变量名是 `WeaponTraceOn`，**没有空格**；v1 写的 `Weapon Trace On` 是显示名）

`Tick` 每帧调 `PlayWeaponTrace()`（现 **48 节点**，2026-10-18 扩展过）：

### 4.4 转向对齐

`Tick` 里持续执行：

```
K2_SetActorRotation( OwningCharacter,
    Yaw = RInterpTo( 当前朝向, CachedInputRotation, DeltaTime, 13.0 ) )
```

`CachedInputRotation` 在**每次出招那一刻**由 `GetInputRotation()` 写入：

```
GetInputRotation() =
  FindLookAtRotation( 角色位置, 角色位置 + 移动输入方向 * 距离 )
```

移动输入方向来自 `GetCharacterMovementDirection()`，读 `CurrentMovementVector`。
→ **效果：出招瞬间角色转向移动输入的方向。**

### 4.6 NPC 受击 → 硬直 → 死亡（2026-10-19 新增，手册 Step 9–13 落地）

```
[AC_Combat.PlayWeaponTrace 命中]
  → 对目标造成伤害(Source=OwningCharacter, Target=HitActor, GE_Damage, CurrentAttackDamage)
  → 属性集结算 → 广播「受到伤害时」(DamageAmount, …, DamageInstigator)
      │
      ▼  BP_MasterNPC.EventGraph（委托中转；组件之间不能互绑事件）
  ComponentBoundEvent 受到伤害时
      → IsValid(DamageInstigator)?
          ├ true  → AC_NPC.ApplyHitReaction(DamageAmount, GetActorLocation(DamageInstigator), false)
          └ false → AC_NPC.ApplyHitReaction(DamageAmount, GetActorLocation(GetOwner(AC_NPC)) + (-100,0,0), false)
      │
      ▼  AC_NPC.ApplyHitReaction(DamageAmount, AttackerLocation, bFromParry)
  Cast GetOwner → Character → Set OwningCharacter
    → if bDead → 直接结束
    → Threshold = GetCombatParam("combat.enemy.hitstun_large_threshold")        // 24
    → bLarge = (DamageAmount >= Threshold) OR bFromParry
    → StunDuration = bFromParry ? combat.enemy.parry_stun(1.8)
                               : bLarge ? combat.enemy.hitstun_large(1.8)
                               : combat.enemy.hitstun(0.35)
    → 施加效果（动态数值）(Target=OwningCharacter, EffectClass=HitStunEffect,
                          SetByCallerValues=MakeMap{Data.Duration: StunDuration}, Level=1)
    → PlayAnimMontage(Target=OwningCharacter, AnimMontage=SelectHitMontage(AttackerLocation, bLarge))
      │
      ▼  AC_NPC.SelectHitMontage(AttackerLocation, bLarge)
  LocalDir = InverseTransformLocation(GetActorTransform(OwningCharacter), AttackerLocation)   // NPC 局部空间
    → |X| >= |Y| ? (X > 0 ? 0 前 : 1 后) : (Y > 0 ? 3 右 : 2 左)
    → bLarge ? MontageLarge[Min(Index, Length-1)] : MontageSmall[Index]

[属性集：血从 >0 变 0] → 广播「死亡时」（只广播一次）
  → BP_MasterNPC.EventGraph → AC_NPC.HandleDeath
      → bDead 守卫 → Set bDead → 取消所有技能 → 添加游离标签 State.Dead
      → DisableMovement → 胶囊 SetCollisionEnabled = NoCollision
      → PlayAnimMontage(MontageDeath)（已关 AutoBlendOut → 定格末帧，尸体不站起）
```

**四个必须记住的结论**：

1. **委托绑在 `BP_MasterNPC`，不绑在 `AC_NPC`**：`AC_NPC` / `AC_GASCombat` 都只是组件，组件不能引用另一个组件的事件；只有同时持有两者的 Actor 才能中转。这也是「在 `AC_NPC` 里搜不到 `死亡时`」的原因。
2. **`bFromParry` 只决定时长档**（不决定播哪个动画）：`true` → `parry_stun`(1.8)；`false` 才按 `bLarge` 分 `hitstun_large`(1.8) / `hitstun`(0.35)。W8 之前没人传 `true`。
3. **`bLarge` 决定「播大/小蒙太奇」**：`DamageAmount >= 24 OR bFromParry`。`MontageLarge` 现在只有 `[Large_F]`，大硬直四个方向都播前方（越界靠 `Min` 兜底；取到 `None` 会静默不播）。
4. **方向必须在 NPC 局部空间算**：先 `InverseTransformLocation` 再比 X/Y；直接拿世界坐标判会因 NPC 朝向而左右/前后判反（这个坑实测踩过——`Get Actor Location` 又是无目标 self 调用时，差值恒为 0，会永远走「背面」分支）。

### ⚠️ 离线缓存的三个已知问题（v2 新增第 2、3 条）

1. **T3D 不含 CDO 默认值**——变量初值、数组内容（比如 `LightAttackMontages` 里到底是什么）读不到。要读必须跑 Python commandlet：

```powershell

  "E:\Unreal Projects\Animation_Sample\Animation_Sample.uproject" `
  -run=PythonScript -Script="<你的脚本.py>" `
  -unattended -nosplash -nop4 -nullrhi -DDC-ForceMemoryCache `
  -EnablePlugins=PythonScriptPlugin -stdout
```

> `-DDC-ForceMemoryCache` 是必需的：没有可写的 DDC 时引擎会直接 Fatal Error 退出。

2. **缓存同时存在「新旧两套路径」**：旧路径文件 `_Game_Combo_Demo_Component_AC_Combat*.t3d`（2026-09-27/30）仍在缓存目录里，与新路径 `_Game_Combo_Demo_BP_Components_AC_Combat*.t3d` 并存。**按文件名 grep 前先确认路径前缀。**
