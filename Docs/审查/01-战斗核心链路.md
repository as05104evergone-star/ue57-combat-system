## ① 一页结论

1. **轻连招是"数组索引 + 硬切蒙太奇"，不是 Section 连招。** `CombatGraph` 左键 → `LightAttack()` → 用 `LightComboIndex` 取 `BP_MasterWeapon.LightAttackMontages[Index]` → `PlayAnimMontage`。索引在 `LightAttack` 内用 `StandardMacros:IncrementInt`（by-ref 写回）自增，`GreaterEqual(LightComboIndex, Array_Length(数组))` 时归 0。`【T3D】`
2. **"连招窗口"实际是一个 2.0s 的重触发延迟**：`LightAttack` 之后串 `RetriggerableDelay(2.0)`（注释"打完一套设置延迟，防止无限连"）→ 到时把 `LightComboIndex=0`、`CurrentBufferedInput=NotAttack`。**它不是"接段窗口"，而是"多久不按就断招"的复位计时器**；真正的接段门控只有每段起手的输入禁用窗口（0.39 / 0.66 / 0.69 / 0.61 / 0.67 s）。`【T3D】`
3. **输入缓冲（`CurrentBufferedInput`）依旧"只写不读"**：全资产只有 2 个逻辑写点（`CheckBufferedInput` 的 else 分支、`CombatGraph` 延迟后复位），**0 个 `VariableGet`**。由于输入禁用窗口内 `CheckBufferedInput` 返回 `false`，窗口内的按键被**直接丢弃** → 手感层面的"按了没反应"就是这个。`【T3D】`
4. **蓄力（右键）是"播→暂停→计时 0.45s→恢复/停止"**，与轻攻击**没有互斥**：`StartCharge` 只检查 `bWeaponInHand && !bIsCharging && !bIsFalling`，而 `LightAttack` 只检查 `bWeaponInHand`。蓄力中按左键会**打断被暂停的蓄力蒙太奇**，但 `bIsCharging` 仍为 `true`、`ChargeTimerHandle` 仍在跑 → 释放时去 Resume 一个已被顶掉的蒙太奇。`【T3D】` + `【待PIE】`（实际表现）
5. **伤害链的蓝图部分是通的，但打不到 NPC 的第一嫌疑在碰撞通道**：`PlayWeaponTrace` 用 `BoxTraceSingle(TraceChannel=TraceTypeQuery1)`，而 `TraceTypeQuery1 = ECC_Visibility`（依据见 ④-3）；项目 `Config/DefaultEngine.ini` 里 **`Pawn` 与 `CharacterMesh` 两个碰撞预设对 `Visibility` 都是 `ECR_Ignore`** → 若 `BP_MasterNPC` 未覆盖胶囊/网格碰撞，**射线永远打不到 NPC**。`【引擎源码+T3D】` + `【待PIE】`
   > **2026-10-19 更新**：用户已在编辑器内确认 NPC 碰撞对 Visibility 可被射线击中 → 本嫌疑**解除**，伤害未到 NPC 的排查转向组件 Tag / `bWeaponInHand` / `GE_Damage` 链路。
6. **`HeavyAttack()` 是死代码**：无任何调用者（右键走 `StartCharge`/`ReleaseCharge`，直接 Resume 硬引用的 `AM_HeavyAttack02`）。`HeavyComboIndex` 全资产只有 1 处读取、**没有任何自增** → 即使将来接上，重击也永远只出第 1 段；且 `HeavyAttack` **不写 `CurrentAttackDamage`**。`【T3D】`
7. **受击/死亡表现完全没接**：`AM_Hit_B/F/L/R/Large_F/Death` 六个蒙太奇**零引用**（全缓存检索），`ABP_EnemyBase` 只有 `Root←Slot←SequencePlayer(单 idle)`，`BP_MasterNPC` 只在 `GASCombatOnCombatReady` 里把 `DT_Enemy["enemy.shadow.hp"]` 写进 `Health/MaxHealth`。git 提交 `77ed6f8`「打通 NPC 受击/血量/死亡的数据链路」目前只到**数据**，没有**表现**。`【T3D】`
8. **装备/卸下链是完整的**（左 Alt → 防连按 → 播 `AM_Equip/AM_Unequip` → `AMS_Equipment` 通知 → `EquipWeapon/UnequipWeapon` → `AttachToComponent` + `bWeaponInHand` + `bWeaponBusy` 复位），但**开局武器名硬编码 `"Spear"`、且包在 `Switch Has Authority` 里**（纯客户端 PIE 不生成武器）。`【T3D】`

## ④ 断点与风险

> 严重度：`blocker`（功能不通）/ `high`（明确错误行为）/ `medium`（一致性与可维护性）/ `low`（体验/清理）

### ④-1【high】输入禁用窗口内的按键被永久丢弃（预输入未消费）
- **现象**：每段攻击起手 0.39–0.69s 内按左键 → 被 `CheckBufferedInput` 写入 `CurrentBufferedInput` 并返回 `false` → `LightAttack` 不执行 → 该按键**再也不会被回放**。玩家连按手感 = "按了没反应"。
- **证据**：`CheckBufferedInput`（7 节点）+ `grep CurrentBufferedInput`（0 个 `VariableGet`）+ 蒙太奇 `ANS_InputDisabled` 窗口表。
- **最小修复方向**：在 `CallSetInputEnabled(true)` 之后加消费逻辑——若 `CurrentBufferedInput == Attack` 且当前无正在生效的禁用窗口，则补发一次攻击；并把 `E_InputBuffered` 扩成 `Light/Heavy/None`（或改成 `PendingLightAttack`/`PendingHeavyAttack` 两个 bool），否则无法区分轻重。

### ④-2【high】蓄力与轻攻击没有互斥（状态机可能撕裂）
- **现象**：蓄力中按左键 → `LightAttack` 通过（只校验 `bWeaponInHand`）→ `PlayAnimMontage(..., bStopAllMontages=true)` **顶掉被 Pause 的 `AM_HeavyAttack02`**；但 `bIsCharging` 仍 `true`、`ChargeTimerHandle` 仍在计时。随后松开右键 → `ReleaseCharge` 去 `Montage_Resume(AM_HeavyAttack02)`（该蒙太奇已不在播放）→ 表现/伤害都可能错乱（`CurrentAttackDamage` 被 `combat.dmg.heavy` 覆盖成"看不见的一击"）。
- **证据**：`StartCharge` 的三个条件 vs `LightAttack` 只有 `bWeaponInHand`；`AnimInstance.h:613` `bStopAllMontages = true`。
- **最小修复方向**：① `LightAttack` 首节点 guard 加 `NOT bIsCharging`（与 `StartCharge` 对称）；② 或更彻底：蓄力期间用 `CallSetInputEnabled(false)` + `CancelCharge` 的现有结构把"蓄力态"变成一个真正的输入态，`ReleaseCharge`/`CancelCharge` 结束时恢复。

### ④-3【blocker 嫌疑】武器射线打不到 NPC：`TraceTypeQuery1 = ECC_Visibility`，而 NPC 的碰撞预设忽略 Visibility
- **推导**：`UCollisionProfile::LoadProfileConfig` 构造 `TraceTypeMapping` 的顺序是 `ECC_Visibility`(index 0) → `ECC_Camera`(index 1) → 自定义 trace 通道（本工程 `ECC_GameTraceChannel1 = "Traversable"`，index 2），`ConvertToTraceType` 返回的就是该数组下标 ⇒ **`TraceTypeQuery1` = `ECC_Visibility`**。
- **工程配置**：`Config/DefaultEngine.ini` 中 `+Profiles=(Name="Pawn", …, CustomResponses=((Channel="Visibility",Response=ECR_Ignore)))` 与 `+Profiles=(Name="CharacterMesh", …, CustomResponses=((…),(Channel="Visibility",Response=ECR_Ignore)))`。ACharacter 默认胶囊用 `Pawn`、骨骼网格用 `CharacterMesh` ⇒ **两者都不响应 Visibility**。
- **后果**：`BoxTraceSingle(TraceTypeQuery1)` 对 NPC 无命中 → `ApplyDamageToTarget` 永不调用 → "有动作没伤害"。
- **证据**：`Runtime/Engine/Private/Collision/CollisionProfile.cpp:355-361`（Visibility/Camera 硬编码进 TraceTypeMapping）、`:804-820`（`ConvertToTraceType` 按数组下标返回）；`Config/DefaultEngine.ini` 上述两行。
- **仍需确认**：`BP_MasterNPC` 是否在蓝图里把骨骼网格/胶囊的 `Collision Profile` 改成 `BlockAll` 之类（T3D 不导出组件模板，见 ⑥-2）。
- **最小修复方向**（二选一，推荐 A）：
  - **A**：`BP_MasterNPC` 的骨骼网格 `Collision Profile = BlockAll`（或自定义 `Damageable` 预设，仅把 **Visibility** 设为 Block），保持代码不动；
  - **B**：把 `BoxTraceSingle` 的 `TraceChannel` 改成专门的 `WeaponTrace` 自定义 trace 通道（新建 `ECC_GameTraceChannel2`，默认 Ignore），并让 NPC 骨骼网格对该通道 Block —— 更干净但要同时改资产与配置。

### ④-4【high】`HeavyAttack()` 死代码 + `HeavyComboIndex` 永不自增
- **证据**：全缓存检索 `CallFunction HeavyAttack` = 0；`HeavyComboIndex` 只有 1 处 `VariableGet`（`GetArrayItem` 的 Index），**无自增/环绕**；`HeavyAttack` 不写 `CurrentAttackDamage`。
- **后果**：重击第 2 段 `AM_HeavyAttack01` 永远够不着；若将来接上这条链，第 1 段会沿用"上一次轻击"的伤害值。
- **最小修复方向**：要么删除 `HeavyAttack`（当前右键系统已替代），要么把它接成"轻连招第 3 段之后的重击派生/Shift+左键"，并补齐 `HeavyComboIndex` 自增 + `Array_Length` 环绕 + `combat.dmg.heavy{Index+1}` 取值。

### ④-5【medium】受击 / 死亡表现链完全缺失（数据到了、表现没到）
- **证据**：`AM_Hit_B/F/L/R/Large_F/Death` 六件蒙太奇**零引用**；`ABP_EnemyBase` AnimGraph 只有 `Root ← Slot ← SequencePlayer`；`BP_MasterNPC` 只有 `GASCombatOnCombatReady → SetAttributeBaseValueByName(Health/MaxHealth)`；`AC_NPC` 空壳。
- **附注**：`AM_Hit_*` 用的是 `SK_Mannequin` 骨架，与玩家当前 `SK_UEFN_Mannequin` 不同 → 若给 NPC 用需要对应骨架的 AnimBP。
- **最小修复方向**：`BP_MasterNPC` 订阅（或轮询）`Health` → `PlayAnimMontage(AM_Hit_F/B/L/R)`（按受击方向选）→ `Health<=0` 播 `AM_Hit_Death` 并停止大脑/碰撞；或在 `ABP_EnemyBase` 增加受击状态机。

### ④-6【medium】"锁移动"只打屏不生效
- **证据**：角色 `CallSetMovementEnabled` 真实体 = `SetVariableOnPersistentFrame(MovementEnabled)` + `PrintString`；`MovementEnabled` 无任何 `VariableGet` 参与 `UpdateMovement_PreCMC` / `CalculateMaxSpeed`。
- **后果**：蓄力期间可以自由移动（与 NodeComment"玩家有武器并且没在蓄力并且不在空中"的设计意图不符）。
- **最小修复方向**：在角色 `UpdateMovement_PreCMC`/`CalculateMaxSpeed` 里读 `MovementEnabled`，false 时把期望速度乘 0（或 `DisableMovement`），并在 `CallSetMovementEnabled` 里保留打印作为调试验证。

### ④-7【medium】`bIsFalling` 只读不写
- **证据**：`StartCharge` 读 `bIsFalling`，全资产无写入点 → 空中蓄力禁用从未生效。
- **最小修复方向**：在 `ReceiveTick` 或 `CharacterMovement` 事件里维护 `bIsFalling = MovementComponent->IsFalling()`（或直接改 `StartCharge` 读 `CharacterMovement->IsFalling()`）。

### ④-8【medium】`WeaponTraceOn` 可能卡在 `true`（`NotifyEnd` 丢失）
- **机制**：若 `ANS_WeaponTrace` 的 Begin 已触发而蒙太奇被 `Montage_Pause` 停住 / 被 `bStopAllMontages` 硬停且 End 通知未派发，则 `WeaponTraceOn` 保持 `true`（`SetComponentTickEnabled(false)` 从未被调用，Tick 永久运行）→ 武器在站立/移动时持续做扫描（只会对"新进窗口的 Actor"结算一次，但因去重表未清，表现是"贴脸站一会突然掉一次血"）。
- **证据**：`CallWeaponTrace` 只在 Begin/End 配对时清表；`PlayWeaponTrace` 每帧无条件；`SetComponentTickEnabled` 8 处全 true。
- **最小修复方向**：在 `Montage_Stop`/`Montage_Resume`/`ReleaseCharge`/`CancelCharge` 前后显式 `CallWeaponTrace(false)`；或给 `PlayWeaponTrace` 加"当前是否有攻击蒙太奇在播放"的二次守卫。

### ④-9【low】调试残留
- `LightAttack` 里 `PrintText(LightComboIndex+1, 屏+日志, 2s)`；
- `PlayWeaponTrace` 里 `PrintString(命中组件 DisplayName)`、`PrintString(CurrentAttackDamage)`；
- 角色 `CallSetMovementEnabled` 里 `PrintString(bMovementEnabled)`；
- `BoxTraceSingle` 的 `DrawDebugType=ForDuration, DrawTime=5.0`（画面常驻 5s 扫掠框）。
- **最小修复方向**：逐个删除或加 `if (bDebugCombat)` 开关。

### ④-10【low】`CancelCharge` 死代码 / 装备通知双触发
- `CancelCharge` 无调用者（应接到"下落/死亡/切武器取消蓄力"）。
- `K2Node_PlayMontage` 的 `OnNotifyBegin` 与 `OnCompleted` **都**连到同一个 `EquipWeapon/UnequipWeapon` 调用 → 蒙太奇播完会**二次调用**；`EquipWeapon` 有 `bWeaponInHand` 守卫（幂等），`UnequipWeapon` **没有**（会重复 Attach + 重复写 `EquippedWeaponRow`）。`【T3D】`，实际影响 `【待PIE】`。

**已知读取陷阱（后续复核注意）**

- 插件会把每个事件额外导出为一个同名"函数图"**桩**（`FunctionEntry → SetVariableOnPersistentFrame → CallFunction ExecuteUbergraph_AC_Combat EntryPoint=0`）；真实事件体在 `EventGraph` / `ExecuteUbergraph_AC_Combat`。判据：桩的 `FunctionEntry` 无 `FunctionReference(MemberName=…)`。
- `flow(format=dsl)` 对 `VariableSet` 的写入值、`GetArrayItem` 索引、`Knot` 会显示为裸名/`<deep>`，关键赋值需 `node_detail` 或直接解析 T3D。
- `audit` 的"孤立节点/执行流断头"绝大多数是 `ExecuteUbergraph` 生成桩的误报，不能当结论。
- 缓存里仍有旧路径资产（`_Game_Combo_Demo_Component_*`、旧 `AS_Combo*`），**不代表资产仍存在**，一律以当前路径与引用为准。
