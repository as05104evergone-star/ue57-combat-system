## 1. 阅读范围与结论边界

本次遍历了项目目录与 Content 文件清单，阅读了工程配置、文档地图、战斗交接、阶段计划、审查与复盘的相关章节，以及 ComboMCP / KBaseUE / 数据管线 / 版本脚本的主要入口与实现。通过 ComboMCP 离线解析抽查了玩家角色、玩家 AnimBP、战斗组件、NPC 组件、武器、NPC Actor、数值函数库和敌人 AnimBP；展开了 NPC 死亡及输入缓冲函数的执行流。

这不是对所有二进制资产逐个开编辑器的验收。贴图、网格和大部分动画素材完成了目录级盘点；没有启动 PIE、重新打包或验证编辑器内未保存的改动。已有“PIE 通过”结论来自项目作者在正式文档中的记录，本轮没有重新实测。

2026-10-19 浏览时仅新增本导览并补文档索引；2026-10-20 已修正文档、上游 Excel 引用与消费侧校验，详见 [P0 修复回执](Codex_P0修复回执_2026-10-20.md)。本轮未改游戏资产或项目配置，未提交或发布版本。没有向 DSH 会话发送消息或配置自动通信；共享文件及同一套 ComboMCP 是当前协作基础。

## 3. 系统定位方式

### 3.1 玩家与动画底座

玩家入口：`/Game/Blueprints/SandboxCharacter_CMC`；动画入口：`/Game/Blueprints/SandboxCharacter_CMC_ABP`。另有 Mover 版本，不应把 CMC 的战斗接入修改直接套到 Mover。

动画系统包含 Motion Matching、Chooser、BlendStack、状态记录、Root / Foot 修正等。战斗 Montage 经 `DefaultSlot` 接入。修改待机或跑步前读 `Plugins/ComboMCP/docs/Epic动画架构笔记.md`，再沿 AnimBP 与选动画的数据资产核查，不能只找传统状态机里的 SequencePlayer。

本轮离线摘要读到 CMC 角色 1,415 节点、CMC AnimBP 4,139 节点。这是解析器包含生成图的统计口径，不等于编辑器里手工维护的节点数，也不作为进度指标。

### 3.2 战斗系统

具体资产与执行链以 [战斗系统交接文档](../战斗系统交接/战斗系统交接文档.md) §2–§5、§6.3 为准。

定位问题时使用以下入口：

| 主题 | 主要资产 / 函数 |
|---|---|
| 输入、轻击、蓄力、重击 | `AC_Combat`：`CombatGraph`、`LightAttack`、`StartCharge`、`ReleaseCharge`、`HeavyAttack` |
| 装备与卸下 | `AC_Combat` + `BP_MasterWeapon` + `DT_WeaponDetails` + `AMS_Equipment` |
| 输入门控、挥击判定窗口 | `ANS_InputDisabled`、`ANS_WeaponTrace` → Tag 为 `Combat` 的组件 |
| 武器轨迹、命中去重、伤害 | `AC_Combat.PlayWeaponTrace`、`GE_Damage`、GAS 桥接 |
| NPC 伤害与死亡事件转发 | `BP_MasterNPC` 上 `AC_GASCombat` 的委托 → `AC_NPC` |
| 受击方向、大小硬直、死亡 | `AC_NPC.ApplyHitReaction` / `SelectHitMontage` / `HandleDeath` |
| 数值消费 | `BPFL_GameParams.GetCombatParam` / `GetEnemyParam` |

本项目的受击 / 死亡委托在 `BP_MasterNPC` 事件图绑定，再分别调用 `AC_NPC.ApplyHitReaction` / `HandleDeath`；`AC_NPC` 的父类为 `ActorComponent`。后续教学沿用这个绑定点。

**当前进度的文档入口**：[Docs/README](../README.md) §0、§4.4，以及交接文档 §6.3。其最新记录是轻 3 + 重 2、装备/卸下和 NPC 受击/硬直/死亡已完成。下一阶段仍按现有排期推进招架、闪避、处决等；本次浏览没有另行调整任务优先级。

### 3.3 引擎外置依赖

战斗还依赖 **GASCombatBridge 1.1.0**。本轮在以下位置确认插件描述和二进制目录存在：

`E:/UE_5.7/Engine/Plugins/Marketplace/GASCombatBridge/`

该插件含 Runtime 与 Editor 模块，默认启用，并依赖 `GameplayAbilities`、`GameplayStateTree`；当前安装目录仅见 `Binaries`、`Config` 和 `.uplugin`，未见源码。

这解释了为什么项目的 `Plugins/` 只有两个 Python 插件，却能使用 GAS 中文节点。搬机器或复现工程时需要单独核对这个依赖；只复制主仓库并不能证明依赖完整。

### 3.4 数值管线

上游 Excel → `export_datatables.ps1` → 9 份 CSV / JSON 与行号映射 → `import_datatables.py` → 9 张参数 DataTable → 蓝图函数库取数。加上独立的 `DT_WeaponDetails`，项目共 10 张业务数据表。

运行时数值事实源与文档同步规则遵循 [Docs/README](../README.md) §3–§4。导出脚本默认优先查桌面的上游 Excel，再查项目内候选路径；当前策划原稿与数值表未纳入正式 Docs 的问题仍见文档待办。

`run_pipeline.cmd` 默认会导出并导入，不能当成单纯浏览命令。编辑器持有旧表时，导入后的磁盘内容可能被后续保存覆盖；执行前需确认编辑器与表的状态。只做静态核对可使用 `verify_mapping.py`，但它的结果也要核实覆盖范围，见 §5。

## 4. 与 DeepSeek Harness 共用工具

DSH 接入说明位于 `Plugins/ComboMCP/docs/dsh-setup.md`：通过标准 MCP stdio 启动 `mcpserver/server.py`，DSH 侧名称为 `mcp__combo__*`。本轮确认工具注册表有 **24 个工具**。

本次 Codex 会话没有直接挂载这些 MCP 工具，但已成功使用现有 CLI 调用同一工具层，无需改动 DSH 配置。以下命令在项目根目录执行：

```powershell
$uePython = 'E:/UE_5.7/Engine/Binaries/ThirdParty/Python3/Win64/python.exe'
$comboCLI = './Plugins/ComboMCP/tools/call_tool.py'
$env:PYTHONIOENCODING = 'utf-8'

# 本轮已成功执行的离线读取入口
& $uePython $comboCLI class_summary asset_path=/Game/Combo_Demo/BP/Components/AC_NPC
& $uePython $comboCLI flow asset_path=/Game/Combo_Demo/BP/Components/AC_NPC graph_name=HandleDeath

# 只读数值检查；失败与警告需要结合当前蓝图核对
& $uePython './Scripts/DataPipeline/verify_mapping.py' --quiet
```

常用顺序：`class_summary` → `graph_overview` → `flow` → `node_detail`。动画另用 `montage` / `anim_asset`；引擎语义用 `engine_source` / `engine_facts` / `interface_check` / `ue_docs`。工具提示与参数以当前 `mcpserver/tools.py` 的定义为准，README 中工具数量等旧文字可能滞后。

离线缓存位于 `Plugins/ComboMCP/cache/t3d/`。读取已有缓存不要求在线编辑器；缺缓存或需刷新时再用 `sync` 采集已保存资产。远程反射和 PIE 状态则是另一个通道。本轮没有验证在线通道连通性。

## 6. 协作执行方式

以下分工已由用户转达并经双方确认：**DSH 负责蓝图教学、引擎证据与验收交付；Codex 负责规划、正式文档收口、入库与发布同步**。信息由用户在会话间转达，具体任务范围仍以用户当次请求为准。DSH 交付必须列出「需更新章节」；Codex 检查资产提交说明中的「文档同步：交接文档 §x / 手册 Step y」。

1. 开始任务先读 Docs 索引与最新交接段落，记录主仓库和插件仓库的提交号、未提交文件、涉及资产及缓存时点。
2. 一项修改指定一方负责写入，另一方负责读取、查证和验收；尤其避免同时保存同一个 `.uasset` / `.umap`。
3. 可以同时读取已落盘内容；缓存采集应安排顺序，避免一方写缓存时另一方据半成品下结论。
4. `Scripts/ue_exec.py` 明确注明 Remote Execution 是单客户端命令通道。DSH 与 Codex 使用实时编辑器操作时轮流占用，完成后释放。
5. 接手时交接“问题、基准、修改资产、证据、实际验收、未验收内容”，不能只交接一句结论。
6. 游戏改动在主仓库处理；ComboMCP 改动在独立子仓库处理。不要运行全量保存脚本把另一方尚未完成的工作一起提交。
7. 资产修改后按 Docs 索引 §4 更新指定事实源；排期、实施步骤与数值各回自己的来源。本文只维护入口与协作边界。
8. 手册文件名 `(已完成)` 在主仓库与公开仓库继续保留；正文分别记录核心行为验收、Step 14 清理与新增数据契约待办，不能据文件名宣称全部完成。

主仓库本轮统计为 3,890 个跟踪文件、11 次提交、3,809 个 LFS 文件。公开展示仓库是独立目录 `E:/Unreal Projects/Animation_Sample_Showcase`；本轮仅阅读发布脚本，没有同步或推送。发布脚本是有实际写入和推送行为的工具，不是只读检查入口。
